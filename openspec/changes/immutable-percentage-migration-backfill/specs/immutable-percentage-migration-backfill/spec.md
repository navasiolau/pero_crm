# Spec Delta

## Purpose

Сохранять неизменяемое содержание уже применённых процентных миграций и добавлять отсутствующие настройки отдельной миграцией, не меняя существующие ставки, настройки организации и финансовую историю.

## ADDED Requirements

### Requirement: Неизменяемая применённая миграция
Система SHALL хранить исходное содержание уже применённой миграции без добавления новых операций; новые операции MUST иметь отдельную миграцию. Смысловое различие SQL MUST NOT считаться вариантом окончаний строк или исправляться переписыванием ledger.

#### Scenario: Найден применённый исходный SQL
- **WHEN** фактический checksum старой миграции совпадает с восстановленным исходным SQL, а текущий Git содержит дополнительную операцию
- **THEN** исходный файл восстанавливается byte-exact, новая операция получает отдельную миграцию, старый ledger не меняется

#### Scenario: Штатный инструмент отверг существующую историю
- **WHEN** migration tool сообщает конфликт уже применённой истории
- **THEN** выполнение останавливается с сохранённым evidence; resolve/reset/переписывание ledger не выполняются

### Requirement: Заполнение всех отсутствующих процентных пар
Система SHALL добавлять конфигурации ENGINEERING, ASSEMBLY и INSTALLATION для каждой отсутствующей пары изделие/вид процента, включая изделия с частичными конфигурациями и soft-deleted изделия. Новая конфигурация SHALL иметь ставку0, revision1 и пустой список reviewed legacy work IDs.

#### Scenario: Полностью отсутствующие настройки
- **WHEN** изделие не имеет процентных конфигураций
- **THEN** появляются ровно три конфигурации с нулевой ставкой

#### Scenario: Частичные и удалённые изделия
- **WHEN** изделие имеет одну конфигурацию или отмечено soft-deleted
- **THEN** добавляются только отсутствующие пары без изменения существующей конфигурации и статуса удаления

### Requirement: Сохранение существующих фактов
Новая миграция SHALL сохранять полные существующие конфигурации, включая NULL/positive/zero ставки, revisions/participants/work review, настройки организации, completions/shares/adjustments/payroll/FX и прочие исторические строки. Исторические UPDATE SHALL NOT выполняться повторно как часть нового заполнения.

#### Scenario: Существующая ставка и финансовая история
- **WHEN** конфигурация имеет NULL, ноль или положительную ставку и существуют связанные финансовые снимки
- **THEN** её ID и все поля, связанные строки и настройки организации остаются идентичными

### Requirement: Идемпотентное заполнение
Система SHALL сохранять уникальность пары изделие/вид процента и не изменять уже существующую пару при повторе или конкурирующем добавлении. Иные нарушения, включая случайное столкновение PK, MUST оставаться ошибками.

#### Scenario: Повтор заполнения
- **WHEN** заполнение выполняется после успешного добавления всех отсутствующих пар
- **THEN** добавлено0 строк и ни одна существующая строка не изменена

#### Scenario: Конкурирующая конфигурация
- **WHEN** другая разрешённая операция успела создать ту же пару
- **THEN** новая миграция сохраняет созданную конфигурацию и не создаёт дубликат

### Requirement: Проверяемая сохранность на разрешённой цели
Проверка SHALL выполняться на существующей разрешённой local/staging БД с подтверждёнными source/target/history guards, native proof и protected fingerprints. Неизвестный результат или несовпадение guards MUST останавливать работу без автоматического retry/cleanup. Создание новой БД/схемы/стенда, reset/seed/dump и изменения main/production MUST NOT входить в эту задачу.

#### Scenario: Rollback-only локальная проверка
- **WHEN** временные native проверки завершились откатом на существующей local5433
- **THEN** исходные protected fingerprints равны, все exact temporary rows отсутствуют, ledger неизменен; результат честно обозначен local SQL proof

#### Scenario: Реальная staging приёмка
- **WHEN** root выполнил согласованную новую миграцию на точно принятом staging SHA/образе
- **THEN** ledger содержит ровно одну новую finished запись, старые записи сохранены, missing pairs0 и существующие configs/financial history неизменны
