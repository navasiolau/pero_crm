# Spec Delta
## Purpose
Пакетная загрузка файлов проекта: пользователь выбирает до 100 файлов одним действием, каждый файл обрабатывается независимо с собственным подтверждением, а итог пачки показывает число успехов и ошибки без потери загруженного.
## ADDED Requirements
### Requirement: Batch file selection up to 100
The system MUST принимать до 100 файлов за одну пачку из выбора в диалоге, перетаскивания и вставки из буфера, используя те же кнопку и зону без изменения интерфейса.
#### Scenario: Shift-select batch of photos
- **WHEN** пользователь выбирает сдвигом 5–20 фотографий и подтверждает диалог
- **THEN** все выбранные файлы встают в одну пачку и загружаются без повторного открытия диалога
#### Scenario: Over-limit selection is capped
- **WHEN** выбрано больше 100 файлов
- **THEN** загружаются первые 100, а итог сообщает об усечении
### Requirement: Independent per-file processing
The system MUST отправлять каждый файл пачки отдельным запросом с собственным идентификатором загрузки; ошибка одного файла MUST NOT отменять или валить остальные.
#### Scenario: One oversized image in batch
- **WHEN** в пачке есть изображение больше 25 МБ среди корректных файлов
- **THEN** этот файл отклоняется с ошибкой лимита, остальные загружаются, итог показывает «Загружено X из Y» и ошибку по имени файла
### Requirement: Differentiated size limits
The system MUST отклонять изображения и обложки больше 25 МБ и принимать не-изображения (документы, чертежи, PDF) до 1 ГБ, возвращая раздельные тексты ошибок для каждого случая.
#### Scenario: Large PDF document upload
- **WHEN** загружается PDF-документ размером 600 МБ
- **THEN** сервер принимает его, а изображение такого же размера отклоняет с ошибкой про 25 МБ
#### Scenario: Both size guards enforced
- **WHEN** размер файла превышает лимит
- **THEN** отказ происходит и на ранней проверке размера, и на проверке прочитанных байтов до записи в хранилище
### Requirement: Size-dependent client timeout
The system MUST ждать ответ 60 с для файлов до 25 МБ и до 10 мин для файлов около 1 ГБ, не обрывая крупные загрузки преждевременно.
#### Scenario: Large document near 1 GB
- **WHEN** загружается документ около 1 ГБ
- **THEN** клиент не прерывает запрос раньше 10 мин
### Requirement: Single-file covers unchanged
The system MUST оставить назначение обложки проекта и эскиза изделия строго одиночным: выбор нескольких файлов там невозможен, поведение и подтверждения прежние.
#### Scenario: Cover upload as before
- **WHEN** пользователь назначает обложку проекта или эскиз изделия
- **THEN** загружается ровно один файл с прежними проверками формата и лимита 25 МБ
### Requirement: Image optimization per file
The system MUST применять к каждому изображению пачки ту же обработку, что и раньше: sharp-превью (thumb) и WebP-превью; превью-сервис MUST отклонить источник больше 25 МБ.
#### Scenario: Batch photos thumbnails
- **WHEN** пачка фотографий успешно загружена
- **THEN** у каждого изображения есть thumb, превью и удаление работают как для одиночной загрузки
