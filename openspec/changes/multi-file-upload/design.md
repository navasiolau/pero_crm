# Design
## Context
См. proposal.md (Why). Сейчас `Uploader` (files-tab.tsx) и `PhotoUploadButton` берут только `files[0]`, сервер режет всё лимитом 25 МБ (`MAX_SIZE` в route.ts, проверки `file.size` и `buffer.length`), клиентский таймаут фиксирован 60 с. Обложки (`assignCover`/`assignProjectCover`) идут через тот же роут, но с отдельными контрактами и проверками формата.
## Goals / Non-Goals
Goals: пачка до 100 файлов без смены UI; независимость файлов (частичный успех); лимит 1 ГБ для не-изображений; таймаут по размеру; обложки строго одиночные.
Non-Goals: потоковая загрузка (chunked/resumable), смена хранилища, изменение превью-сервиса и sharp-блока, новые кнопки и зоны.
## Decisions
- Общий батч-планировщик в `lib/file-upload-client.ts` (`sendUploadBatch`): первые 100 файлов, файлы до 25 МБ — пул 4, больше 25 МБ — строго последовательно; результаты возвращаются в порядке выбора. Альтернатива — общий пул без выделения крупных — отвергнута: параллельные гигабайтные потоки грозят памятью и каналом.
- Лимит на сервере определяется типом содержимого, а не категорией: `image/*` и обложки — 25 МБ, остальное — 1 ГБ. Чистый модуль `server/files/upload-limits.ts` без зависимостей — обе проверки роута (`file.size`, `buffer.length`) и юнит-тесты используют его. Альтернатива — лимит по категории — отвергнута: PDF замера и фото замера лежат в одной категории MEASUREMENT.
- Каждый файл пачки — отдельный `FormData` + `createUploadAttempt` (свой `clientMutationId`): идемпотентность и диагностика повторных запросов сохраняются без изменения серверной логики.
- Таймаут по умолчанию выводится из размера файла в форме: 60 с до 25 МБ, далее линейно до 600 с к 1 ГБ; явный `timeoutMs` приоритетнее. Sharp-блок и `SOURCE_MAX_BYTES` превью не трогаем.
- Проверка расширения `validateFileForCategory` — для каждого файла до отправки; ошибка файла попадает в список ошибок пачки, остальные едут дальше.
## Risks / Trade-offs
- [Риск] `Buffer.from(await file.arrayBuffer())` + одиночный `s3Put` держат весь файл в памяти; гигабайтный PDF может упереться в память Node → Митигация: крупные файлы строго последовательно; обязательный local/staging тест PDF 600 МБ–1 ГБ до приёмки; потоковая запись — вне scope, зафиксирована как follow-up при OOM.
- [Риск] Долгая загрузка и уход со страницы → Митигация: существующие guards (`active`, `onBusyChange`, сверка `currentTarget`) удерживают состояние пачки; итог показывает подтверждённые сервером записи.
- [Риск] Пустой MIME-тип у экзотических файлов → Митигация: не-`image/*` считается документом (лимит 1 ГБ); проверка расширения категории остаётся первым барьером.
## Migration Plan
Миграции БД нет, API обратно совместимо (тот же multipart, те же поля). Откат — revert коммитов ветки. Приёмка: lint, `@pero/web` тесты, браузерные кейсы из evidence (пачка фото, thumb/preview/удаление, 25МБ-отказ в пачке, одиночная обложка).
