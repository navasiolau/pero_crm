# Design

## Context

№214–215 добавили JSONB и конструктор произвольных разделов. Владелец отверг UI: нужны непосредственный ввод в нумерованный список и перенос только соответствующих характеристик из КП. Существующий CAS/receipt/sourceGeneration уже защищает сохранения.

## Goals / Non-Goals

**Goals:** заменить Product-конструктор простым полем, ограничить его JSON предметными характеристиками, сохранять ввод автоматически.

**Non-Goals:** новый редактор КП/PDF, новые DB columns/migrations, массовая обработка записей, production.

## Decisions

- В карточке и ручном создании один простой ol/li со всеми девятью существующими заголовками CATALOG: Корпус, Фасад, Столешница, Обивка, Вставки и ручки, Фурнитура, Подсветка, Внутреннее наполнение, Мягкое наполнение. Пустые строки видны сразу и нумеруются; поле доступно без предварительного нажатия. Нет выбора типов/групп, add/remove, повторов заголовка, подсказок, статусов «Сохранено», дополнительных текстовых полей/accordion.
- Текст сохраняется после 400ms паузы ввода, blur/Ctrl+Enter ускоряют сохранение. Enter — перевод строки, IME не отправляет незавершённую композицию. Существующий controller сохраняет очередь, исходный baseline, receipt UUID и черновик. Ошибка — только исключительный toast/aria-invalid, без панели действий.
- Единая существующая JSONB-колонка остаётся. Совместимый envelope хранит sections и внутренний sourceGeneration; description/size/note в новом Product-снимке null. Raw Product.description не удаляется, но не показывается и не интерпретируется в списке. Просмотр не пишет БД.
- Новый technicalSpecificationEntry задаёт стандартный type, expectedSectionId (null для ещё не заполненной строки), expectedValue, expectedSourceGeneration и value. Под Product row lock выполняются прежние ACL/receipt и CAS; отсутствующий раздел создаётся только при фактическом вводе, с ID операции. Разные строки объединяются в свежем JSON, старые поколения/ID конфликтуют. Очистка значения оставляет пустую строку. Прежние свободные custom/source writes не возвращают мусор в Product JSON.
- Product-only projection отделяется от полного КП. Она берёт только стандартные types/точные соответствующие названия. Legacy: точные известные заголовки/неоднозначность без угадывания; outer/inner объединяются как конкретные материалы без общих подписей, hinges/lighting/drawers идут в свои разделы без повторяющегося заголовка исходного блока. Значения из нескольких блоков объединяются без дублей. Неизвестные разделы, description/size/note, цены/услуги/свободные коммерческие JSON-поля не переносятся. Полный источник сохраняется в КП/версии; общий KP renderer и его adapter не обрезают сведения.
- При сохранении/восстановлении КП весь ограниченный Product-снимок заменяется как прежде, sourceGeneration меняется только при реальной замене. Существующие Product JSON читаются через ограниченную проекцию для вида; никакого фонового backfill. Финансовая/производственная история и серверные права прежние.

## Risks / Trade-offs

- Сохранение без blur может пересечься с КП → очередь, receipt и generation CAS остаются обязательны.
- Старые неизвестные блоки не имеют однозначного места → остаются в исходном КП, не становятся произвольными строками поля изделия.
- Не допустить расширения области → не переделывать КП, печать, финансовые поля или инфраструктуру; только Product-поле и его перенос.

## Migration Plan

Нет DB migrations. Проверки на существующем guarded local 5433 и actual staging. Normal commit/merge/push, штатный CI/W07, приёмка точного SHA/образа. Production не включён.
