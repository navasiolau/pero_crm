# Design

## Context

Мотивация — в `proposal.md`. Канбан проектов использует `ProjectKanbanCard`; обе доски изделий и их DnD-overlay используют `ProductKanbanCard`. Области обложки сейчас имеют `aspect-[3/4]`, а изображение уже заполняет их через `object-cover object-center`. Общий `ProductHeroImage` также обслуживает детальный просмотр и по умолчанию сохраняет `object-contain`.

## Goals / Non-Goals

**Goals:** задать 4:3 на двух существующих областях карточек, сохранив все обработчики и общую реализацию загрузки.

**Non-Goals:** менять общий `ProductHeroImage`, детальные страницы, хранение/превью файлов, серверные данные и существующий поиск.

## Decisions

- Заменить только `aspect-[3/4]` на `aspect-[4/3]` в общих карточках. Вариант отдельной геометрии для каждой доски создаёт лишнее дублирование, а глобальная замена в Hero затронула бы детальные страницы.
- Обновить геометрию в существующем `product-card-navigation-browser.mjs`: он уже компилирует реальные карточки и обе доски изделий, проверяет три исходных пропорции, delayed/error/empty, resize/cache, навигацию, полноэкранный оригинал и DnD. Добавить скриншоты проверенных размеров в его уникальный каталог артефактов.
- Выполнить прежний `kanban-search-focus-browser.mjs` для проектов и изделий на 1440/390/360 с синтетической обложкой у найденной карточки: это проверяет центрирование с новой высотой. Разрешить отдельный путь артефактов через env, чтобы сохранить прежние доказательства других задач. Новые зеркальные CSS-тесты не нужны.

## Risks / Trade-offs

- Меньшая высота карточки изменяет позицию при поиске → повторить реальные сценарии фокусировки и DnD на desktop/mobile.
- Исходники разных пропорций обрезаются → сохранить прежний центрированный `cover` только в канбане и проверить прежний `contain`/оригинал отдельно.

## Migration Plan

Миграции БД нет. После локальных проверок — независимое ревью, обычный merge и приёмка фактически развёрнутого staging оркестратором; обратная правка двух классов возвращает прежнюю геометрию без изменения данных.
