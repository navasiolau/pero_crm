## Decisions

1. **Public streaming parser.** Предлагается direct pinned busboy1.6.0 и devDependency @types/busboy1.5.4; типы используют уже согласованный locked @types/node, без его обновления. В lockfile public parser сейчас отсутствует; существующие dependency versions не обновляются. Private Next vendored busboy не используется: это не публичный контракт. Самописный boundary parser отклонён из-за сложности/поверхности ошибок; полная formData сохраняет исходный дефект. Dependency/pinned-lock delta проходит отдельный reviewer/root GO перед install/source.
2. **Две lanes, один transport.** Новый `x-pero-upload-context` version1 содержит только target/mode/section/expected CAS/nonce из FormData; File bytes/SHA на клиенте не читаются. Header ASCII percent-encoded JSON <=4 КиБ, exact keys/types; malformed present header не fallback. Отсутствующий header допускает legacy lane. Auth/globalrole до body всегда. Declared target проходит существующие exact permission services до Request.body access; late fields сравниваются по normalized contract. Legacy проверяет доступный project/context как только он определим, а полный mode/target до publication; нельзя угадывать отсутствующие late optional fields. Referer не применяется как authority.
3. **Узкий target service.** Existing cover validators/authorizeProductCoverUpload/authorizeProjectCoverUpload/resolveUploadContext переиспользуются через один route-level target adapter, а не копируются для early/late/final stages. Synchronous parsing сохраняет status/kind/error, obsolete category/stage/caption refusal, section defaults, task inheritance и UUID validation. После spool заново session/roles/context перед storage; внутри существующей transaction финальная проверка текущего target перед writers. Смена назначения/этапа/CAS не вызывает новое намерение автоматически.
4. **Bounded owned spool.** Request.body→single public Web reader/byte counter→public Busboy.write ACK; один `file`, <=16 text fields, <=17 parts, fieldName<=100 UTF8 bytes, field<=4096 UTF8 bytes, суммарноmetadata<=64 КиБ, boundary<=200 bytes; binary body<=applicable decoded cap+128 КиБ; exact native base64 encoded wire cap2×decoded cap+128 КиБ, SHA/size послеdecode. Multipart Busboy1.6.0 имеет фиксированный header block<=16 КиБ и internal MAX_HEADER_PAIRS=2000 ограничивает накопление и может игнорировать дополнительные pairs; гарантированный отказ по pair count не обещается. limits.headerPairs/fieldNameSize в этой реализации не читаются. Field-name bytes проверяет собственный adapter в file/field callbacks. Parser/file/transform/write/read highWaterMark64 КиБ; doc никогда не читается целиком. Parser coarse limits: fileSize=2×documentCap+128KiB+1, fieldSize=4097, parts=18, fields=17, files=2; собственные counters проверяют допустимые inclusive пределы 4096/16/17/1 и immediate cap overflow. Truncated/limit flags обязательно проверяются до publication. Так точные 4096 bytes field и17 parts остаются допустимыми несмотря на parser limit-at-equality; cap+1 и18th part отвергаются. Не добавляется shadow multipart header parser ради64 pairs. defParamCharset UTF8; corrective preservePathtrue сохраняет native original File.name, а существующая sanitizeFileName/storage ownership обеспечивает path safety. MIME/name correction проходит дополнительный review до source. Input chunks проверяются/передаются с backpressure; HWM сам по себе не proof32 МиБ.
5. **Spool ownership и cleanup.** Только новый random app-owned temporary directory/file, directory0700/file0600/wx, no client path. Descriptor содержит measured size/hash и recorded realpath/dev/inode, его read factory/cleanup ограничены exact owned object. После limit/abort/error pipeline/reader/parser/file streams закрываются, затем exact cleanup в finally; unknown/reparse/inode mismatch STOP/HOLD, не broad rm. Startup orphan prune не вводится. Private spool не становится business object; доступ к нему не выдаётся через API. Scope IO/retention protocol и actual temp root согласуются перед runtime/RSS.
6. **Streaming storage.** Готовый spool имеет проверенный length/SHA; narrow S3 streaming helper передаёт fresh Readable, ContentLength и precomputed checksum при согласованной совместимости MinIO. Existing Buffer s3Put callers сохраняются. Один consumed stream не переиспользуется при retry; bounded reopen factory/явная политика maxattempts сохраняет память и unknown-ACK honesty. Local fallback публикует exact fresh destination через bounded copy/exclusive temp+rename, с path/reparse guards. Изображение можно читать как прежний25 МиБ bounded Buffer только для Sharp/thumbnail; original берётся из spool без перекодирования.
7. **Existing lifecycle.** Storage positive ACK обязателен до File+receipt; original fingerprint по той же нормализованной структуре/stream hash. Replays читают/hash stream, не доверяют client hash, подтверждают same bytes/target/actor. Existing transaction writers/notification/revalidation/CAS outcomes остаются. Concurrent same-nonce requests по существующему контракту могут выполнить Put для разных fresh keys до transactional dedup: остаётся один File/receipt/notification, а known loser compensation не оставляет дополнительный owned object. Единственный physical Put не обещается; архитектурная storage-before-nonce reservation вне139. Known failure компенсирует только fresh own keys; unknown DB ACK не удаляет possible committed original. Abort во время storage/commit не обещает отмены удалённого эффекта, uncertainty/reconciliation сохраняются.
8. **Независимый memory/HTTP proof.** Unit generated streams доказывают limits/hash/cleanup/ownership на реальном parser, handler на injected stores доказывает ACL/status/receipt paths. Отдельный isolated process с реальным HTTP sender вне measured worker проверяет25/100/1024 МиБ и два параллельных docs. Жёсткий предел32 МиБ/upload и64 МиБ для двух относится ко всем живым транспортным буферам, включая очереди и фиксированные резервные слоты. RSS/external/arrayBuffers измеряются отдельно с неизменным warmed baseline без forced GC: предел32 МиБ к общей памяти Node не применяется. Middleware/NextRequest test и actual Node/Next error path обязаны доказать413/422 JSON при cancel/limit, а не довольствоваться pipeline rejection. HTTP/native/visual/staging не заменяются DI.

## Risks / Trade-offs

- [Legacy target неизвестен до поздних полей] → root compatibility qualification, early global guard, private bounded spool, exact prepublication/final ACL; evidence lanes отдельно.
- [HWM не hardcap / upstream giant chunk / SDK скрытый buffer] → byte counters/backpressure, chunk bounds, native HTTP/RSS proof, source library inspection, не claim cap по setting alone.
- [Limit/abort уничтожает HTTP socket прежде JSON] → real Next/HTTP error tests доacceptance; безопасное прекращение чтения и прежние structured errors проверяются совместно.
- [Unicode/MIME/пустой файл отличаются при новом parser] → UTF8/filename/MIME/empty/boundary-split parity tests и original downloadSHA.
- [S3 stream повторно consumed/checksum/version compatibility] → known length/hash, fresh stream everyattempt, bounded retries и actual staged MinIO tiny/large checks, no speculative global config change.
- [Смена доступа во время IO / unknown ACK] → fresh auth/context+transactional check, exact own compensation и retained possible committed objects; no blind rollback.
- [Большой временный disk / failed cleanup] → per-upload cap/no world-readable temp/no broad pruning; actual owned lifecycle protocol и NO cleanup success при mismatch.

Proposed public framing API внутри multipart-upload.ts:
- Один Request.body reader, один последовательный public Busboy write(segment, callback). Следующий segment не отправляется до write callback; никакие private parser fields не читаются.
- До первого file event input split только на CRLFCRLF с retained delimiter-tail<=3 bytes. Rolling raw window<=16KiB+UTF8 boundary length+8. Это generic delimiter tap, не multipart boundary/body parser.
- После каждого CRLFCRLF cut сохраняется копия bounded candidate header/window/endOffset; snapshot не заменяется произвольным payload write. Public StreamSearch задерживает часть separator до следующего write, поэтому применяется bounded lookahead: следующие <=UTF8boundaryBytes+4 bytes отправляются по одному с public write ACK. На каждом таком write сохраняется предыдущий candidate; новое завершение separator создаёт новый candidate только в отсутствие file event. Если событие не пришло в этот finite probe, обычный delimiter tap возобновляется; retained candidate остаётся bounded до следующего cut. Первый file event связывается с наблюдаемым retained candidate, а не с концом текущего write.
- Text fields/preamble с CRLFCRLF создают cuts, но metadata не извлекается без public file event. Candidate должен содержать последний exact CRLF--boundary-CRLF либо исходный --boundary-CRLF целиком; suffix до separator <=16KiB и не содержит внутреннего CRLFCRLF.
