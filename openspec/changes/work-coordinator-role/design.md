# Design

**Execution agreement:** Номер задачи 121, ветка feature/121 согласованы владельцем 10.10.2026; OpenSpec и реализация одобрены. Одна целевая локальная проверка, затем существующий полный CI без изменений и развёртывание на staging только через него; одна целевая staging-приёмка. Повторные полные ручные проверки не выполнять без конкретного сбоя. Production/main этим запуском не разрешены.

## Context

Мотивация — `proposal.md`, рабочие действия и матрица — соседние changes `field-work-editing` и `field-product-status-visibility`. Исследована база `origin/staging` `ab1c77f3b82cab788f206914d5b2a063e6aafe68`. Прайсы сейчас управляются MANAGER_ROLES; роли — массив с union, ADMIN/DIRECTOR исключительны. Actor/session используют текущие DB-роли.

Владелец подтвердил, что новая роль дополнительная и не расширяет видимость изделий. Она не заменяет существующую WORKER/MOUNTER возможность работы с обычными Work/собственными задачами.

## Goals / Non-Goals

**Goals:** узкая дополнительная способность управлять прайсами и создавать обычные работы уже доступных изделий.

**Non-Goals:** новая базовая должность, собственный office/field/finance grant, редактирование проекта/техблока, изменение payScheme или автоматическое назначение роли.

## Decisions

1. **Добавочное значение роли.** `WORK_COORDINATOR` получает русскую подпись и место после базовых ролей в нормализации; display/primaryRole сохраняет базовую роль. Комбинация требует хотя бы одну другую разрешённую базовую роль. ADMIN/DIRECTOR по прежнему не комбинируются. UI и сервер применяют одинаковую валидацию; снятие последней базовой роли при оставшемся дополнении отклоняется.

2. **Отдельные operation grants.** PRICE_MANAGE объединяет прежний менеджмент и новую роль; WORK_CREATE — прежние разрешения и новое дополнение при обязательной проверке доступности продукта. Новое дополнение само не даёт Work update/remove или назначения другим людям. WORKER/MOUNTER редактируют обычные работы и берут задачи по своей независимой роли.

3. **Read и write не смешиваются.** WORK_COORDINATOR не включается в OFFICE_ROLES/MANAGER_ROLES/FINANCE_ROLES/FIELD_ROLES и не становится full project visibility. Прайсовый route/query имеет собственное чтение для новой роли; создание работы проверяет исходную productVisibilityWhere по базовой роли. FIELD-only redirect/классификация игнорирует добавочный признак: WORKER+WORK_COORDINATOR остаётся производственным аккаунтом с новым пунктом «Прайсы».

4. **История цены не переоценивается.** Редактирование каталога меняет расценку только для последующих Work snapshots; существующие Work/Task/PayrollEntry сохраняются. Контракты создания работ запрещают клиенту ручные значения тарифа, даже когда у него есть каталоговая способность.

5. **Административное назначение штатное.** Добавляются chip/label/validation, навигация и route/action guards; существующий процесс управления пользователями и аудит ролей сохраняется. Session callbacks читают актуальные роли; удаление дополнения закрывает операции на следующем запросе, не полагаясь на старую клиентскую кнопку.

## Risks / Trade-offs

- Добавление в общий менеджерский набор случайно даёт финансы/проекты → отдельные operation grants и отрицательные native/HTTP проверки всех побочных разделов.
- Сотрудник с дополнением перестаёт быть FIELD-only → базовая классификация/домашний redirect и собственные задачи проверяются на обеих комбинациях.
- Пустая базовая роль либо stale JWT сохраняет способность → одна серверная валидация сочетаний и свежий actor в write.

## Migration Plan

Аддитивно добавить enum Role; существующие User.roles, payScheme, начисления и assignments не изменяются. После regenerate pinned Prisma проверить все exhaustive maps и штатное назначение/снятие роли на собственном QA-пользователе. Local/staging без dump/seed/reset; production-миграция требует отдельного выпуска, одного временного дампа и изолированного восстановления по AGENTS.md. Откат приложения должен продолжать понимать уже назначенное значение; enum/роли не удаляются слепым down. Номер отдельной задачи согласуется до feature-ветки.
