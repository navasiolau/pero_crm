# Design

## Context

См. proposal.md. База задачи — staging `419ccbf23b611b0bcc9f318818fc49add43bfcbe`; основная копия остаётся на своей ветке с локальными изменениями. Владелец согласовал удаление исходных планов вместе со старыми идеями и сохранение B3D на диске.

## Goals / Non-Goals

**Goals:** AGENTS.md не более 8 192 байт UTF-8; действующие правила сохраняют смысл. README отражает код базовой ревизии. Изменения и удаления имеют проверяемые границы.

**Non-Goals:** изменения приложения, БД, зависимостей, секретов и инфраструктуры; коммиты, push и выпуск без отдельного указания; переписывание чужих changes и архивов приёмки.

## Decisions

- Работа с tracked-файлами выполняется в отдельном worktree `bugfix/2`. Основная копия получает только согласованную очистку локального мусора; её tracked-файлы, index и untracked OpenSpec сохраняются.
- AGENTS.md хранит правила, краткую модель и ссылки на источники. Исторический checkpoint удаляется, а не переносится в другой большой документ. Подробные доменные правила проверяются по коду и действующим specs.
- Четыре старых плана, meeting_summary.md и шаблонный apps/web/README.md удаляются; ссылки правятся только в корневом README, ARCHITECTURE.md и deploy/telegram-bot/README.md.
- B3D снимаются с учёта командой `git rm --cached`; хэши и наличие проверяются в основной копии и worktree. Каталог исключается из Git и Docker-контекста.
- Для локальной очистки составляется точный manifest из файлов основной `.playwright-mcp` и четырёх известных generated/log-файлов. Проверяются канонические пути, отсутствие reparse points, ссылки на приёмку и неизменность кандидатов между инвентаризацией и удалением. Используется `Remove-Item -LiteralPath`, без `git clean`, ACL-правок и рекурсивного удаления непроверенного каталога.
- `.pytest_cache` основной копии уже недоступен: он исключён из удаления. Данные приёмки в других worktrees, substantive research, env, загрузки и защищённые owner-документы сохраняются.
- Это docs/tooling change: `skip_specs: true`; новые продуктовые требования и delta specs не создаются.

## Risks / Trade-offs

- Потеря локального оригинала или чужой правки → ограниченный manifest, проверка reparse points, SHA-256 защищённых файлов и сравнение исходного Git status/index.
- Слишком короткие инструкции ослабят требования → смысловая сверка GitFlow, разрешений, БД/restic, безопасности и разработки; лимит проверяется по байтам.
- Старые ссылки останутся после удаления → поиск названий и локальная проверка Markdown-ссылок изменённых документов.
- Основная копия остаётся на прежней ветке → итоговые tracked-изменения доступны в прикреплённом worktree; интеграция идёт по GitFlow после разрешения на коммиты.

## Migration Plan

Миграции отсутствуют. Результат — проверенный незакоммиченный diff и отчёт. Дальнейшая интеграция: обычный merge рабочей ветки в staging, CI и фактическая staging-приёмка; затем выпуск по прямому указанию владельца и fast-forward main. Возврат tracked-документов возможен из базовой ревизии Git; удаляемые ignored-артефакты владельцем признаны устаревшими.
