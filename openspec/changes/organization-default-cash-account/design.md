# Design

## Context

См. proposal.md. OrgSetting уже хранит строковое значение без миграции. Денежные и task writers используют общий withTaskTransaction с advisory lock (18435, 55001). PaymentDialog сейчас сбрасывает draft эффектом; остальные формы выбирают пустую или первую кассу.

## Goals / Non-Goals

**Goals:** единый источник настройки, согласованность с деактивацией, устойчивое начало новой операции во всех web-формах.

**Non-Goals:** менять право проведения операций, бухгалтерскую историю, валютную переоценку, бота или создавать БД.

## Decisions

- Один OrgSetting с ключом defaultCashAccountId хранит JSON {revision, accountId}; ревизия предотвращает потерю изменений, в том числе смену A → B → A. Раздельные строки настройки и ревизии не нужны.
- Чтение добавляет isDefault в опции касс через общий helper. Это исключает дополнительные параллельные props и позволяет всем существующим контейнерам передать признак вместе с кассой.
- Назначение, аудит и деактивация выполняются под существующей общей денежной блокировкой. Отдельный lock настроек оставил бы гонку с проверкой активности кассы.
- PaymentDialog инициализирует состояние один раз на новую сессию открытия/автора/контекста после проверки actor. Обновление опций не повторяет инициализацию. Восстановленный запрос загружается раньше default. Ручная смена валюты сохраняет прежний выбор первой кассы этой валюты.
- CashPayoutForm и логистика используют ленивое начальное состояние, массовый расчёт выбирает default при открытии диалога. «Новая операция» повторно читает актуальные props.

## Risks / Trade-offs

- [Настройка изменилась при открытом draft] → применить её только при следующей новой операции.
- [Касса деактивировалась после выбора] → сохранить ввод, сервер отклонит неактивную кассу; не подменять реквизиты молча.
- [DB-проверки выполняются последовательно оркестратором] → агент проверяет unit/DI и реальный компонентный браузерный harness; native helper передан оркестратору, CI-fixture локально не подменяется.

## Migration Plan

Миграции нет. Отсутствующая строка означает отсутствие назначения. При откате кода строка не влияет на старые формы; платежи не переписываются.
