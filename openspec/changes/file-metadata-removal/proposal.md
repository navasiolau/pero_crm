# Proposal

## Why

Категории и комментарии заставляют сотрудников заполнять лишние поля при загрузке и дублируют место размещения файла. Владелец согласовал задачу 113: сохранить документы и разделы, убрать эти метаданные из действующей модели и интерфейса.

## What Changes

- **BREAKING**: заменить `File.category`, `File.stage`, `File.caption` и старые enum на `File.section`: GENERAL, MEASUREMENT, PRODUCTION, INSTALLATION.
- Раздел определяется местом загрузки, без выбора категории и подписи. Существующая «Сборка» объединяется с производством.
- Миграция сохраняет все File IDs, ключи хранилища, оригиналы, связи с проектами/изделиями/задачами и текущими эскизами/обложками.
- Снять runtime-плагин категорий file-stages, его настройки расширений и категориальную проверку. Сохранить ограничения MIME обложек, размера, доступа, идемпотентности и безопасной записи.
- Старые запросы с category/stage/caption отклоняются до чтения файла с 422 и просьбой обновить форму.

## Capabilities

### New Capabilities

- `contextual-file-sections`: контекст загрузки, сохранная миграция разделов и отсутствие категорий/комментариев.

### Modified Capabilities

Нет: политика engineer-product-access сохраняется.

## Impact

Prisma File/миграция, web upload и upload client, cover core, запросы и компоненты разделов, registry/settings file-stages, регрессионные тесты. Упрощённые строки списка и печать относятся к отдельным задачам 115/116. Change и реализация заранее разрешены владельцем; коммит, merge и production не разрешены. Local/staging без дампов; restic запрещён.
