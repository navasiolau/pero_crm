# Proposal

**Execution agreement:** Номер задачи 118, ветка bugfix/118 согласованы владельцем 10.10.2026; OpenSpec и реализация одобрены. Одна целевая локальная проверка, затем существующий полный CI без изменений и развёртывание на staging только через него; одна целевая staging-приёмка. Повторные полные ручные проверки не выполнять без конкретного сбоя. Production/main этим запуском не разрешены.

## Why

Владелец воспроизводит отказ выхода сразу после входа: пока сотрудник не перешёл в другой раздел, «Выйти» не завершает сеанс и не открывает логин. Выход должен работать с первого экрана независимо от предварительной навигации.

## What Changes

- Надёжно завершать текущий браузерный сеанс по первой команде «Выйти» после входа и перенаправлять на `/login`.
- Сделать ожидание результата и ошибку выхода явными; не допускать повторного параллельного запуска.
- Сохранить обычный выход после навигации, CSRF/cookie-политику и актуальную проверку роли/сеанса.
- Не завершать другие устройства пользователя и не менять его пароль или роли.

## Capabilities

### New Capabilities

- `initial-login-logout`: выход сразу после аутентификации и проверяемое завершение текущего веб-сеанса.

### Modified Capabilities

Нет. Контракт отдельного исправления сохраняет текущую аутентификацию.

## Impact

`NavUser`, logout Server Action, точечные auth/browser проверки. На исследованном свежем `origin/staging` `ab1c77f3b82cab788f206914d5b2a063e6aafe68` клиент вызывает logout из dropdown, сервер ожидает `signOut({redirectTo:'/login'})`. Причина отказа пока не доказана; точная последовательность первого входа является обязательной регрессией. Миграция БД не нужна. Номер отдельного bugfix согласуется перед рабочей веткой; код и выпуск в рамках предложения не выполняются.
