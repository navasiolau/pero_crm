# Design

**Execution agreement:** Номер задачи 118, ветка bugfix/118 согласованы владельцем 10.10.2026; OpenSpec и реализация одобрены. Одна целевая локальная проверка, затем существующий полный CI без изменений и развёртывание на staging только через него; одна целевая staging-приёмка. Повторные полные ручные проверки не выполнять без конкретного сбоя. Production/main этим запуском не разрешены.

## Context

Мотивация — `proposal.md`. База: свежий `origin/staging` `ab1c77f3b82cab788f206914d5b2a063e6aafe68`. `NavUser` вызывает logout Server Action из `DropdownMenuItem.onClick`; action ожидает `signOut` с redirect на `/login`. Вход использует серверную форму и redirect на первый экран. JWT/session callbacks каждый запрос проверяют актуального пользователя и sessionVersion.

Симптом подтверждён владельцем, но сетевое/браузерное воспроизведение этого первого перехода в рамках планирования не выполнялось. Нельзя объявлять причиной hydration, cache или Auth.js только по чтению этих файлов.

## Goals / Non-Goals

**Goals:** завершение текущей браузерной сессии и предсказуемый redirect без предварительного перехода по CRM.

**Non-Goals:** отзыв всех устройств, изменение sessionVersion/пароля, замена Auth.js, собственное удаление auth cookies или новая аутентификация.

## Decisions

1. **Регрессия проверяет точную последовательность.** Новый браузерный контекст: login → первый авторизованный экран → меню → «Выйти», без промежуточной навигации. Сравнение с logout после перехода включает факт вызова action, ответ/redirect и последующую проверку сессии. Это узкая диагностика уже известного сценария, а не общий поиск проблемы.

2. **Сохраняется штатный серверный signOut.** Предпочтён явный form-action submit со стабильным жизненным циклом вне размонтируемого dropdown и состоянием pending, вместо fire-and-forget вызова. Если воспроизведение покажет иной локальный дефект вызова/redirect, исправляется этот участок с той же регрессией. Собственный cookie endpoint отвергнут: он мог бы потерять CSRF и часть cookie-политики.

3. **Ожидание и ошибка видимы.** Повторный submit блокируется до результата; штатный redirect не перехватывается как обычная ошибка. Реальная ошибка показывается пользователю с возможностью повторить, без ложного сообщения об успешном выходе.

## Risks / Trade-offs

- Закрытие dropdown прерывает клиентское состояние → форма/ожидание не зависят от его размонтирования.
- Redirect ошибочно перехвачен → сохранить его штатное прохождение и отдельно обработать настоящую ошибку.
- Кэш показывает прежний экран после выхода → проверять защищённый запрос и возврат назад/обновление, не считать изменение URL доказательством окончания сессии.

## Migration Plan

Без БД-миграции. Отдельный согласованный bugfix от свежего staging, local regression в реальном браузере и проверка фактического staging после разрешённых merge/push/CI. Не менять текущие сеансы других пользователей; QA использует собственный тестовый контекст. Дампы и restic не нужны. Код/выпуск ещё не выполнены.
