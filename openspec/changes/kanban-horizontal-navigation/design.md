# Design

## Context

Все три доски имеют data-slot=kanban-scroll и overflow-x-auto, общий app shell уже min-w-0. Карточки используют отдельные draggable-компоненты; их слушатели не менять.

## Goals / Non-Goals

**Goals:** доступная горизонтальная навигация на длинной доске.
**Non-Goals:** новые статусы, персистентное положение прокрутки, изменение drag/drop.

## Decisions

KanbanScrollArea оборачивает текущие колонки. После области доски расположен обычный overflow-x-auto контейнер с пустым содержимым шириной всей доски: браузер сам рисует track/thumb как у вертикальной полосы. Sticky bottom-0 удерживает эту полосу у нижнего края рабочей области длинной доски; короткая доска имеет полосу сразу под колонками. Прокрутка контейнера и доски синхронизируется через scrollLeft без range и отдельных кнопок. Штатная полоса внутри длинного содержимого скрыта, видима только одна нижняя полоса. ResizeObserver следит за шириной доски/содержимого. Горизонтальные wheel/touch, Shift+wheel и фокусируемая область с ArrowLeft/Right/Home/End сохраняются. Клавиатурные перемещения синхронные, без smooth feedback. При отсутствии overflow нижняя полоса скрыта. Вертикально продолжает прокручиваться страница; высота доски не ограничивается и второй вертикальный скролл не добавляется. DragOverlay остаётся вне скролл-контейнера.

## Risks / Trade-offs

Sticky при внешнем overflow → нижняя полоса и область доски являются соседними элементами, их родитель не ограничивает overflow. Длинная доска → проверить доступность полосы в начале/середине/конце страницы, в том числе вкладку изделий проекта. Native полоса получает оформление браузера/ОС, как текущая вертикальная. Resize/фильтры → clamp native и обновление размеров.
