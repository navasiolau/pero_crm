# Proposal

## Why

Сейчас менеджмент вручную распределяет количество работы между задачами, а исполнитель не может передать часть своей незавершённой задачи коллеге. Требуется единое деление в процентах для задач любых ролей с точным сохранением исходного объёма и бюджета, без повторного применения процента при оплате.

## What Changes

- По умолчанию задача имеет одного исполнителя и 100% доли. Все активные роли доступны для назначения с сохранением текущих ограничений доступа инженера.
- Исполнитель делит свою незавершённую задачу, менеджмент — любую разрешённую; получатель должен быть другим активным сотрудником с доступом к контексту.
- Группа долей сохраняет исходное количество и бюджет; повторное деление распределяет только оставшуюся долю. Копейки распределяются без увеличения или потери бюджета.
- Выполненные и уже начисленные доли не делятся. Факт времени, таймер и фотографии остаются у исходной задачи; зависимости ждут обе части.
- Карточка задачи и «Мои задачи» получают действие «Разделить», выбор сотрудника и процента, понятное подтверждение количества и суммы.

## Capabilities

### New Capabilities

- `universal-work-shares`: права, точное распределение, неизменность истории и зависимостей при делении задач между сотрудниками.

### Modified Capabilities

Доступ инженера из принятой основной спецификации `engineer-product-access` сохраняется; участие нескольких инженеров в одном изделии добавит отдельная фича.

## Impact

Additive schema/migration для групп и снимков долей, доменные операции Task/Work, расчёт сдельной суммы, списки исполнителей и UI задач. Product percentage pools, авансы и 3D не входят в изменение. Миграция только готовится; применение к любой БД запрещено до отдельного решения root/владельца. Проверки текущего этапа — unit/DI, генерация клиента, typecheck/lint/build без подключения к БД.
