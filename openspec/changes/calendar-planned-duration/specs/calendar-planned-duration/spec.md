# Spec Delta

## Purpose

Позволить владельцу личного плана указывать необязательную плановую длительность записи для последующих итогов часов без подмены фактического времени.

## ADDED Requirements

### Requirement: Optional planned duration
Запись SHALL хранить неотрицательную целую плановую длительность в минутах либо отсутствие значения, отдельно от фактических трудозатрат.

#### Scenario: Fractional hours
- **WHEN** пользователь вводит1,5 часа
- **THEN** сохраняются90 минут, повторное открытие показывает1,5 часа

#### Scenario: Empty and zero
- **WHEN** поле оставлено пустым либо явно введён0
- **THEN** сохраняются соответственно отсутствие значения и0, старые записи остаются без значения

#### Scenario: Minute precision
- **WHEN** дробные часы дают долю минуты
- **THEN** форма округляет до ближайшей минуты с пояснением, сервер отклоняет дробные/отрицательные минуты

### Requirement: Personal durable mutation
Изменение длительности SHALL соблюдать личный доступ, версию записи и правила повторного создания.

#### Scenario: Retry and stale update
- **WHEN** повторён тот же create либо пришло изменение со старой версией
- **THEN** create не создаёт дубль; изменённая длительность в повторном create и stale update вызывают конфликт

#### Scenario: Existing client
- **WHEN** старая форма обновляет запись без поля длительности либо меняется только статус
- **THEN** сохранённая длительность не теряется

#### Scenario: Another owner
- **WHEN** другой пользователь, включая администратора, запрашивает/меняет запись
- **THEN** личные данные и длительность недоступны
