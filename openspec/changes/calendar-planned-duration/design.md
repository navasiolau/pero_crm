# Design

## Context

Личный CalendarEntry имеет ownerId, startsAt, state и revision. Единственное ядро mutateCalendarCore обслуживает создание/редактирование/статус; оно повторно читает доступ и ограничивает данные владельцем. См. proposal.md.

## Goals / Non-Goals

**Goals:** добавить один источник плановой длительности, сохранив retry, приватность и старые записи.
**Non-Goals:** фактические таймеры производственных Task/TimeEntry, денежные расчёты, итоги107 и аналитика108.

## Decisions

1. Nullable Int plannedMinutes плюс CHECK >=0; верхний предел технического Int 2147483647, без придуманного ограничения на рабочий день. NULL отличается от0. Decimal часов в БД потребовал бы лишнего округления при суммировании.
2. Контракт принадлежит server/calendar. На create отсутствие означает NULL; на update отсутствие поля сохраняет прежнюю длительность для совместимости уже открытых старых форм, явный NULL очищает. State-операция длительность не меняет. Retry создания сравнивает и минуты.
3. В lib/calendar-duration один браузерный parser часов (запятая/точка, неотрицательные, округление до ближайшей минуты) и обратный formatter для редактирования/подписей. Округление явно объясняется в UI; канонический сервер принимает только integer minutes/null. Две цифры часов при открытии сохраняют каждую минуту после roundtrip.
4. Existing actor/session/CAS остаются единым доступом. Новое поле не влияет на задания напоминаний или фактическое время; изменение записи сохраняет прежний revision-процесс.

## Risks / Trade-offs

- Дробные часы не всегда равны целой минуте → округление показано рядом с полем и проверено roundtrip.
- Старая вкладка без нового поля → update сохраняет значение, create имеет совместимый NULL.
- Миграция → только nullable колонка/CHECK, прежние данные и напоминания сохраняются.

## Migration Plan

Local существующий5433 и staging без дампов; проверить прежние поля хешами и старые NULL. Обычный merge/CI/фактическая staging-приёмка. При откате приложения колонку оставить. Main/production только по отдельному разрешению владельца.
