# Design

## Context

См. proposal.md. Visibility отделяет полное чтение от назначенных технических writes; OFFICE_ROLES сейчас ошибочно разрешает стоимость инженеру.

## Goals / Non-Goals

**Goals:** закрытая денежная проекция на сервере, согласованные UI-флаги и глобальный readonly для обеих полевых ролей после DESIGN.
**Non-Goals:** расширение технических/финансовых writes, изменение начислений90, скрытие собственных исторических выплат.

## Decisions

- canViewProductMoney — чистое объединение MANAGER_ROLES/FINANCE_ROLES. Его используют денежные DTO и страницы. Техническая hasFullProjectVisibility остаётся самостоятельной.
- Полевая ветка product/project visibility даёт все не-DESIGN; assignedProductVisibilityWhere и write-предикаты сохраняются.
- Проекции скрывают expectedPrice/initialPrice у всех ограниченных исполнителей, включая назначенных; описание неназначенного изделия продолжает маскироваться. В родительском списке prices/totalPrice не выдаются.
- ownMember требует совпадения текущего выбранного assignee с actor; старое начисление не становится чужой строкой при смене получателя. Текущий выбранный без своей исторической доли получает только текущий прогноз.
- Чужая task-оплата скрывается при сериализации TaskDetails; собственная сдельная оплата сохраняется.
- Регрессии проверяют реальные query/route-проекции и матрицу стадий/ролей, native PostgreSQL — через временную транзакцию на существующей5433 с откатом.

## Risks / Trade-offs

Скрытый столбец не защищает RSC → проверять DTO/null и сериализованное содержимое.
Объединение ролей может расширить writes → отдельные negative-тесты productEdit/taskExecution/upload.
