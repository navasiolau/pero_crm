# Spec Delta

## Purpose

Позволяет проверить каждую составляющую расходов проекта, увидеть её исходную операцию и получить согласованные итоги по статьям без повторного учёта материалов.

## ADDED Requirements

### Requirement: Единый журнал и экономика
Система SHALL показывать денежные расходы, складские выдачи и возвраты отдельными строками и учитывать каждую сумму ровно один раз в расходах проекта и разбивке по статьям. Общие расходы организации SHALL оставаться вне проекта.

#### Scenario: Выдача и возвраты
- **WHEN** выданы 3 единицы по 20 BYN, затем возвращена 1 единица
- **THEN** видны строки +60 и −20 BYN, расход проекта составляет 40 BYN, дополнительных кассовых расходов нет

#### Scenario: Изменение закупочной цены
- **WHEN** после выдачи зарегистрирована закупка по другой цене
- **THEN** цена и сумма прежней выдачи не меняются

#### Scenario: Статьи и неполная история
- **WHEN** две статьи имеют одинаковое название или отсутствует сохранённая сумма движения
- **THEN** статьи различаются по идентификатору, неизвестная сумма явно обозначена и не заменена нулём

### Requirement: Финансовый просмотр исходной операции
Финансовые роли SHALL видеть дату, изделие, материал, единицу, количество, снимковую цену, сумму, автора и исходный идентификатор складской строки. Менеджер без финансовой роли SHALL не получать эти данные. Складская строка SHALL быть доступна только для просмотра в журнале расходов.

#### Scenario: Бухгалтер открывает строку
- **WHEN** бухгалтер открывает складской расход из финансов проекта
- **THEN** доступны детали исходного движения без технических данных изделия и без требования операционного доступа

#### Scenario: Объединение ролей
- **WHEN** пользователь имеет роли менеджера и бухгалтера
- **THEN** финансовый просмотр доступен по объединению прав
