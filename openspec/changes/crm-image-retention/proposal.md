# Proposal

## Why

Watcher скачивает и запускает новые версии CRM, но не ограничивает хранение прежних образов и не проверяет свободное место перед скачиванием. На staging накопилось 269 образов при четырёх используемых; 10.11.2026 заполнение квоты 32 GiB заблокировало обновление и остановило PostgreSQL.

## What Changes

- После успешного обновления автоматически удалять только подтверждённые старые образы CRM, сохраняя текущую и две предыдущие успешные версии.
- Рассматривать web и renderer одной версией; сохранять любые образы, на которые ссылаются существующие контейнеры, включая остановленные.
- До pull проверять свободное место. Предлагаемый минимальный запас — 3 GiB; при нехватке сначала выполнять разрешённую очистку, а если запаса всё ещё нет — завершать обновление до скачивания и сохранять работающую версию.
- Выполнять очистку через точный список image IDs без force/prune, с повторной проверкой ссылок непосредственно перед удалением и с ограничением времени.
- Сохранять безопасный отчёт: защищённые версии, удалённые image IDs, свободное место до/после и причины пропуска. При повторном штатном запуске продолжать незавершённую уборку.

## Capabilities

### New Capabilities

Новых capabilities нет.

### Modified Capabilities

- `crm-autodeploy`: добавить политику хранения образов и проверку дискового запаса до скачивания.

## Impact

`deploy/watch-crm.py`, его fake-adapter тесты и документация установки. Обновление самого host watcher требует отдельной проверки устанавливаемого файла; новый образ приложения его автоматически не заменяет. Сначала локальная проверка и staging, production — только по отдельному прямому поручению.

## Non-goals

Очистка БД, volumes, файлов клиентов, S3, restic, журналов, сетей, пакетов ОС и чужих Docker-образов не входит в задачу. Задача не создаёт новые стенды и не заполняет диск ради тестирования.
