# Proposal

## Why

Задача 128 устраняет расхождение глобального канбана с принятой политикой назначения инженера. Сейчас он подставляет прежнее участие в оплате вместо текущего engineerId: назначенный инженер без участия не получает разрешённый возврат, а бывший участник видит действие, которое отклонит сервер.

## What Changes

- Передавать идентификатор текущего пользователя от страницы изделий к глобальному канбану.
- Использовать один адаптер текущего назначения для карточки, глобального и проектного канбанов.
- Проверять независимость назначения от исторического участия и сохранять role union, DRAFT-lock, серверный ACL и финансовый снимок.
- Снять сопоставимый UI baseline и подготовить ограниченный QA preference-checkpoint для обоих списков и вкладки изделий проекта.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `engineer-product-access`: одинаковая доступность принятого возврата текущего инженера в карточке и обеих досках.

## Impact

UI: products page/view/kanban, project products-tab, product-header и общий product-percentage-ui adapter; targeted tests и OpenSpec. Поддерживающий QA adapter остаётся private ignored, использует существующий транспорт, HMAC и exact CAS. Нового серверного права, миграции, зависимости или пересчёта исторической оплаты нет. Отдельная ошибка autofocus остаётся задачей 145.
