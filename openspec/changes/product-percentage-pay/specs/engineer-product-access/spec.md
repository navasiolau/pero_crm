# Spec Delta

## MODIFIED Requirements

### Requirement: Видимость назначенного изделия
Система SHALL предоставлять инженеру доступ только к изделию, где сотрудник назначен инженером/участником ENGINEERING и текущий статус равен DESIGN. Пользовательские фильтры SHALL только сужать разрешённую выборку. Инженерное право исчезает после выхода изделия из DESIGN; независимые права других ролей объединяются по обычным правилам. ADMIN, DIRECTOR, MANAGER и ACCOUNTANT сохраняют полный просмотр. WORKER и MOUNTER SHALL видеть конкретные назначенные им/доступные по их задачам изделия только после DESIGN; изделия и данные DESIGN остаются скрытыми для производственной роли. Общая задача проекта с `productId=null` сохраняет прежний project-wide доступ только к части проекта с изделиями не в DESIGN. Проект, содержащий только DESIGN-изделия, для такой производственной роли скрыт; проект без изделий остаётся доступным, если пользователю назначена собственная общая задача.

#### Scenario: Свои и чужие изделия разных этапов
- **WHEN** инженер запрашивает список, карточку, поиск или опции изделий
- **THEN** возвращается только его изделие DESIGN; чужое DESIGN и своё PRODUCTION отсутствуют, прямые ссылки не раскрывают данные изделия

#### Scenario: Подмена фильтра
- **WHEN** инженер явно фильтрует по чужому инженеру или PRODUCTION
- **THEN** результат пуст и фильтр не заменяет ограничение доступа

#### Scenario: Инженер после выхода из DESIGN
- **WHEN** чистый ENGINEER открывает изделие после перехода в PRODUCTION
- **THEN** инженерный доступ к изделию и его данным отсутствует

#### Scenario: Независимое право комбинированной роли
- **WHEN** ENGINEER имеет иную роль, которая отдельно разрешает доступ к изделию
- **THEN** доступ предоставляется только в пределах прав этой роли и общего приоритета

#### Scenario: Производственный доступ скрывает DESIGN
- **WHEN** WORKER или MOUNTER имеет задачу/назначение в проекте, где есть изделие DESIGN
- **THEN** список, поиск, вложенные данные и прямая ссылка не раскрывают это DESIGN-изделие

#### Scenario: Общая задача проекта и смешанные изделия
- **WHEN** WORKER или MOUNTER имеет общую задачу проекта (`productId=null`) в проекте с DESIGN- и PRODUCTION-изделиями
- **THEN** общий project-wide доступ раскрывает только недизайнерскую часть; проект только с DESIGN-изделиями скрыт

#### Scenario: Проект без изделий с собственной задачей
- **WHEN** у WORKER или MOUNTER есть назначенная общая задача проекта, в котором пока нет изделий
- **THEN** проект остаётся доступен для выполнения этой задачи

### Requirement: Объединение прав ролей
Система SHALL объединять доступ по всем ролям. ADMIN, DIRECTOR, MANAGER и ACCOUNTANT сохраняют полный просмотр; ADMIN, DIRECTOR и MANAGER управляют процентными ставками и долями. WORKER и MOUNTER сохраняют прежний доступ к части проектов с собственными задачами, кроме изделий DESIGN. ENGINEER получает инженерный доступ только к своему назначенному изделию DESIGN. Пустые роли SHALL не давать доступ.

#### Scenario: Совмещённые роли
- **WHEN** MANAGER+ENGINEER или ACCOUNTANT+ENGINEER открывает чужое изделие
- **THEN** оно доступно для просмотра по офисной роли; настройки процентов доступны ADMIN, DIRECTOR и MANAGER по объединённым ролям с приоритетом MANAGER

#### Scenario: Инженер и производственная роль
- **WHEN** ENGINEER+WORKER имеет задачу на проекте с изделием PRODUCTION
- **THEN** проект и разрешённое PRODUCTION-изделие доступны по производственной роли, своё DESIGN доступно только пока статус DESIGN, после чего исчезает инженерное право

#### Scenario: Просмотр не расширяет редактирование
- **WHEN** ENGINEER+ACCOUNTANT видит чужое изделие по роли бухгалтера
- **THEN** инженерная правка технического блока и изменение процентных настроек запрещены, если нет отдельного права менеджмента

#### Scenario: Прежние производственные права
- **WHEN** WORKER/MOUNTER загружает общий файл в проект со своей задачей
- **THEN** прежний доступ сохраняется кроме файлов изделий DESIGN; переданный taskId проверяется на исполнителя и принадлежность тому же проекту/изделию

### Requirement: Разрешённые данные родительского проекта
Система SHALL открывать проект пользователю с ограниченной видимостью, если в нём есть доступное изделие. Реквизиты, общие файлы и переписка проекта доступны; вложенные изделия, задачи, работы, файлы, материалы, история и агрегаты SHALL не раскрывать недоступные изделия. Клиенты и подсказки SHALL выводиться только через доступные проекты. Project status transitions SHALL NOT create product percentage accruals.

#### Scenario: Смешанный проект
- **WHEN** проект содержит доступное по роли изделие и чужое DESIGN-изделие
- **THEN** доступны только разрешённые изделия, а скрытые изделия отсутствуют во вложенных данных и агрегатах

#### Scenario: Общие суммы смешанного проекта
- **WHEN** чистый инженер или производственный пользователь открывает родительский проект
- **THEN** финансовые агрегаты, позволяющие вывести данные скрытого DESIGN-изделия, не передаются; офисные роли A/D/M/ACCOUNTANT сохраняют полный просмотр

#### Scenario: Скрытые связи
- **WHEN** у доступной задачи есть зависимость или файл недоступного изделия
- **THEN** название, идентификатор и содержимое скрытой связи не выдаются; незавершённая скрытая зависимость блокирует выполнение без раскрытия названия

#### Scenario: Проект меняет этап
- **WHEN** менеджер меняет статус родительского проекта
- **THEN** процентное начисление по изделиям не создаётся
