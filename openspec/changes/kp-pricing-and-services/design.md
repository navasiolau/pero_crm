# Design

## Context

См. proposal.md. Текущие суммы проекта вычисляются через общий `product-quantity`, экономика имеет отдельный select, а inline-редактирование публикует снимки с PostgreSQL txid и CAS. Расчёт исходного генератора изучен в `pero_kp/public/js/sheet-render.js`; его шаблоны не изменяются.

## Goals / Non-Goals

**Goals:** единая точная проекция сохранённых коммерческих данных и совместимое добавление общего режима услуг.

**Non-Goals:** новые публичные API КП, загрузки, генерация документов и начисление зарплаты. Подключение к сохранению №181 требует обычного merge зависимостей и отдельной сквозной проверки; чистые тесты не объявляются такой приёмкой.

## Decisions

- `printed-source-pricing` читает эффективные печатные копейки идентичными операциями normalizeState/totalsOf исходного генератора, включая Math.round/Number.EPSILON. Это явная граница совместимости: 10.075 печатается как 10.07, а 100.75 минус 10% — как 90.68. Исходный JSON не нормализуется на месте и не меняется.
- `projectProposalPricing` получает целые печатные копейки и использует отдельный Decimal-контекст высокой точности для всех последующих действий: распределения скидки, FX, BYN-цен и поправки. Коэффициент един для изделий и услуг; в CRM сохраняются цены единицы и отдельное количество. Значения за пределами безопасных целых копеек исходного генератора отклоняются до записи.
- Курс содержит валюту, положительное значение, календарную дату и NBRB/MANUAL. Обычное сохранение использует прежний снимок; смена валюты требует нового курса. Получение НБРБ выполняется до транзакции, через существующий провайдер CRM; сетевой вызов не находится внутри расчёта или общего сохранения.
- `servicesTotal` nullable и `proposalRoundingAdjustment` default 0 дополняют Project. CHECK запрещает одновременно общую сумму и разбивку. Новые строки разбивки содержат `crmKind`; свободная подпись не определяет финансовую категорию.
- Остаток округления равен итоговому BYN КП минус сумма округлённых цен единицы с количеством и услуг. Его учитывают все итоговые функции; в inline UI это поле доступно только для чтения.
- CAS изменения услуги включает исходный режим и все суммы услуг. Переключение режима очищает альтернативные поля одной записью; сервер возвращает полный подтверждённый денежный снимок для согласования контроллеров.
- Транзакционный адаптер принимает уже вычисленную проекцию, проверяет связь состава и LEAD, обновляет коммерческие поля изделий/проекта и аудит, не изменяет исторические начисления. После merge №181 вызывает его своим обязательным pricing hook в общей транзакции.

## Risks / Trade-offs

- Потеря копейки при количестве больше одного → отдельная поправка и сценарии положительного/отрицательного остатка.
- Двойной учёт услуг/расхождение UI → общий helper, эксклюзивный CHECK, полная CAS-проекция и тесты перехода режимов.
- Старый курс при смене валюты → валюта обязательна в снимке курса; несовпадение отклоняется.
- Зависимости №180/181 пока не интегрированы → фиксируется конкретный handoff; сквозная работа сохранения не заявляется до merge и DB/runtime-проверки.

## Migration Plan

Аддитивный ALTER TABLE Project без изменения существующих бизнес-сумм. Старые проекты получают NULL общей суммы и нулевую поправку. На этом этапе миграция не применяется: подготовленная проверка использует существующую разрешённую local БД 5433 только после разрешения оркестратора, guards, BEGIN/ROLLBACK и сверки данных. Production и staging следуют AGENTS.md без самостоятельных дампов или новых стендов.
