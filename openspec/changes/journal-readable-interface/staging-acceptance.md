# Приёмка интерфейса №223 на фактическом staging

Прогон выполняет root после подтверждения staging SHA/image/health. Используется уже проверенный административный контекст; этот документ не разрешает создание пользователей, смену паролей или обход guards. Read-only server actions: `listJournal`, `listJournalFilterOptions`, `getJournalEntry` в `src/server/changelog/actions.ts`. Их build-specific IDs брать из server-reference manifest проверяемого образа, не переносить от предыдущей сборки.

1. Открыть `/changelog` в 1440×900. Дождаться `[data-journal]` и таблицы. Заголовки `thead th` строго: Время, Пользователь, Сущность, Действие, Было → стало. В таблице нет источника, raw entity:id, badge типа автора или фрагмента old/new.
2. Поиск по label «Поиск по журналу» и кнопка «Применить»: проверить выбранную root существующую запись по её ID и слову из конца полного значения. Проверить пользователя, русскую сущность, диапазон и «Сбросить». Для поиска по source выбрать значение из карточки события. Общее число и пагинация должны соответствовать server result, не объёму первой страницы.
3. Открыть строку `tr[aria-label^="Открыть событие:"]`. Окно `[role=dialog]` одно, источник находится внутри. Раскрыть «Технические сведения»: ID равен выбранному событию. Ссылки на сущности используют постоянные IDs. Прокрутить `[data-journal-scroll]` до конца; никакой текст не обрезан.
4. Закрыть кнопкой «Закрыть»: фокус вернулся строке. Повторить Enter и Space. Кнопка «Показать изменения» той же строки открывает одно окно, а `[data-journal-diff]` оказывается в области просмотра. Закрытие возвращает фокус кнопке. Проверить что кнопка не вызвала второй detail action.
5. Повторить на 390×844: `[data-slot=mobile-list-card]` представляет те же события. Окно занимает доступный экран, content scroll не переполняет окно по ширине, закрытие доступно. Снять list/event screenshots и визуально просмотреть их.
6. Для DIRECTOR и остальных выбранных ролей `/changelog` не выдаёт журнал. Server actions должны отвергаться до чтения данных; дополнительно проверяется в native/query сценариях №222. Не считать скрытое меню достаточным подтверждением.

Обязательная запись результата: фактический SHA и image, проверенные роли, выбранные event IDs, ожидаемый и найденный total, server action IDs из manifest, сценарии, пути к приватным screenshots, статус. Cookies, tokens, пароли и сырые заголовки авторизации в receipt не включать.

Коды ошибок/retry и запоздавшие ответы детерминированно покрываются `tests/journal-interface.test.mjs` на реальных компонентах; staging дополнительно подтверждает работу настоящего transport и авторизации.
