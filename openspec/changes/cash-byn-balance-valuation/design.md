# Design

## Context

`cash-statement.ts` объединяет расчёт, чтение Payment/Payout и read-only RepeatableRead entrypoint. `activePaymentWhere` исключает отменённые закупки и неактивные ревизии логистики. Payout содержит отдельные nullable cashAmount/cashCurrency; `historicalByn` достоверно восстанавливает BYN только из сохранённой валюты BYN. Существующий `nbrb.ts` предназначен для денежных форм и отдаёт Number; изменять его контракт этой задачей не требуется.

## Goals / Non-Goals

**Goals:** точный расчёт физического остатка отдельно от исторических BYN-движений, контролируемая оценка и объяснение неизвестности.

**Non-Goals:** восстановление недостающих фактов, ремонт production-записей, изменение платёжных форм, бухгалтерского баланса или начислений.

## Decisions

- Сохранить чистый `buildCashStatement` с необязательным параметром датированных курсов. Суммировать native-остатки и BYN-движения независимо; использовать Decimal во всех денежных вычислениях. Оценку округлять после умножения всего остатка, курсовую разницу считать из уже округлённых отображаемых показателей.
- Выделить чтение snapshot-фактов. `getCashStatement` завершает read-only RepeatableRead до загрузки уникальных курсов только для ненулевых подтверждённых остатков. Предварительный чистый расчёт определяет необходимые пары валюта/дата, после получения курсов расчёт повторяется. `loadCashStatement` остаётся DB-helper без скрытого сетевого обращения, с передаваемыми курсами для DB-проверок.
- Клиент датированных курсов принимает строковую дату и injectable fetch. Проверяет HTTP-статус, валюту, календарную дату, положительные конечные официальный курс и scale; использует Decimal при делении. Ошибка не прерывает отчёт, а даёт недоступную оценку с причиной. Подменять отсутствующий курс единицей нельзя.
- Для BYN применяется курс 1; для подтверждённого нулевого остатка поддерживаемой валюты курс не нужен. Неполнота native-истории распространяется на зависимый остаток. BYN-движения с сохранёнными суммами остаются доступными. Группа без кассы имеет неизвестную оценку BYN; native-поведение этой группы сохраняется.
- Добавить `revaluation` к итогам, метаданные начальной/конечной оценки к строке и число недоступных оценок. В native-интерфейсе курсовую разницу скрыть. В BYN показать её отдельным столбцом и пояснить даты, исходные остатки и курс в детализации.

## Risks / Trade-offs

- [НБ РБ недоступен или не знает дату] → сохранить движения и нулевые остатки, отметить только зависимую оценку неизвестной.
- [Старая выплата без cash-снимка] → не выводить физическую сумму из BYN по сегодняшнему курсу.
- [Точная причина production 0,67 не подтверждена] → регрессионный пример явно демонстрационный; сверку записей выполняет оркестратор отдельно только чтением.
- [Local PostgreSQL 5433 недоступен] → не запускать инфраструктуру, seed/reset или новый стенд; подготовить DB-проверку и зафиксировать отсутствие native DB-приёмки.

## Migration Plan

Схема и данные не меняются. После локальных проверок требуется приёмка реально развёрнутого staging с точной ревизией и сценариями. Возврат предыдущего приложения возвращает прежнее отображение без обратной миграции.
