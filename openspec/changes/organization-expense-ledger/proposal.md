# Proposal

## Why

Общие расходы компании сейчас нельзя внести без фиктивного проекта: запрет есть в Zod и PostgreSQL. Задача №100 разрешает такие расходы с кассой, статьёй и отчётным документом в CRM и Telegram.

## What Changes

- Разрешить EXPENSE с projectId/projectAmount NULL, сохранив согласованность nullable пары, денежные ограничения и обязательный документ.
- Добавить «Расходы организации» и переиспользовать одну выборку/таблицу для приходов и расходов.
- Общая PaymentDialog поддерживает необязательный проект для обоих направлений; длинный список использует существующий SearchableSelect.
- Telegram получает явный выбор «Без проекта» для прихода и расхода; сохранение идёт через прежнее ядро.
- Общие расходы уменьшают кассу и баланс организации, не распределяются по проектам.

## Capabilities

### New Capabilities
- `organization-expense-ledger`: общие расходы и общий финансовый журнал по направлениям.

### Modified Capabilities
Нет.
