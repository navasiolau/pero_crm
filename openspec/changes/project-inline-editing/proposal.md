# Proposal

## Why

Проект сохраняется полной формой, а его статус и контактные изменения имеют лишь часть защиты №17. Задача №18 переносит общую механику частичного сохранения на проект, защищает все редактируемые поля и делает обязательные данные отказа/рекламации единым серверным правилом.

## What Changes

- Название первым, следом селект «Статус»; прямые правки клиента, менеджера, адреса, телефона, доставки/выгрузки/монтажа. Нынешние служебные поля/вычисляемые суммы сохраняют смысл, BYN без выбора валюты, первоначальная цена скрыта.
- ProjectPatch с закрытым allowlist, decimal strings, CAS/receipt, queue и компактным ответом; reuse №17 controllers/shared contact core без полной RSC-перезагрузки на поле. Полноценный genuine baseline для прежней формы и бота, transactional audit/outbox.
- **BREAKING**: переход статуса принимает expectedStage и общий профильный core. REFUSED требует непустую причину, комментарий optional; RECLAMATION — причину, описание и виновную сторону. Это явно новое подтверждённое правило текущего плана, фактический старый core обязательность не проверяет.
- Серое readonly поле «Инженеры назначенные в Изделиях», уникальные назначения по видимым изделиям. Вкладки Общее → Изделия → Файлы → Задачи → Материалы → Финансы; скрыть коммуникации/историю карточки, сохранить данные и административный журнал.
- Flat files без категорий/этапных групп, прежний ACL/просмотр/скачивание/подтверждаемое удаление; PDF-КП обычное вложение без extraction/конвертации.

## Capabilities

### New Capabilities

- `project-inline-editing`: частичные конкурентно безопасные правки проекта, единый status contract и согласованный интерфейс карточки.

### Modified Capabilities

Нет. Ролевые ограничения, денежная BYN политика и файловый доступ сохраняются.

## Impact

`server/projects/core.ts`, `stage-core.ts`, typed patch contract/actions, shared contacts, legacy overview/bot/API/kanban callers, project page/tabs/files. Общие inline primitives и Client/Project контактные операции №17 переиспользуются, не создаются повторно. Новых dependencies/миграций не предполагается.

Вне объёма: production/main, большой product textarea №19, product files/cover №20–21, оплата/доли №22–24, финальная product page №25, автоматические initialPrice снимки и окончательные writer ограничения №26, PDF extraction и новые FX/conversion writers.
