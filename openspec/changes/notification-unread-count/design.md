# Design

## Context

`getBellData()` выполняет отдельный `notification.count` без ограничения количества и возвращает последние десять элементов отдельно. Ограничение «9+» находится исключительно в `NotificationsBell`. На десктопе badge имеет фиксированную ширину 16 px; это недостаточно надёжно для трёх символов «99+».

## Goals / Non-Goals

**Goals:** изменить порог отображения и дать badge ширину по содержимому при прежнем положении относительно колокольчика.

**Non-Goals:** менять выборку уведомлений, авторизацию, polling, события чтения, шапку и соседние элементы навигации.

## Decisions

1. Использовать уже полученное полное число, заменив клиентский порог 9 на 99. Ограничивать серверный count или увеличивать список последних уведомлений не требуется.
2. Сохранить круглую минимальную форму badge для одной цифры, но вместо фиксированной десктопной ширины использовать минимальную ширину и горизонтальный padding. Текст не переносится; символы получают место за счёт ширины самого badge.
3. Проверить настоящий компонент с подменённым только transport: числа 0/9/10/99/100, обновление и геометрию на 1440×900 и 390×844. Серверную выборку проверить имеющимися тестами прав уведомлений. Окончательную проверку на развёрнутом staging выполняет root.

## Risks / Trade-offs

- [Три символа наложатся на соседний элемент шапки] → проверить bounding boxes badge, кнопки и соседних элементов в браузере.
- [Визуальный тест с синтетическим count принят за реальную БД] → в evidence отдельно записать компонентный transport и фактическую staging-проверку; данные для проверки в БД не создавать.

## Migration Plan

Миграция не требуется. Изменение доставляется штатным CI и watcher; root фиксирует работающий SHA, образ, здоровье и сценарий шапки.
