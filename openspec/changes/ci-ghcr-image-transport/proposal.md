# Proposal

## Why

Квота хранения GitHub Actions аккаунта достигла 93%. CI сохраняет полные OCI-архивы web, бота и renderer на сутки только для передачи между jobs; это создаёт повторные сетевые передачи и накопленный расход хранения.

## What Changes

- По согласованному владельцем 15.11.2026 решению передавать исходные проверенные OCI через приватный GHCR под уникальными служебными тегами `ci-<run>-<attempt>-<sha>`.
- В Actions передавать только ограниченный по размеру пакет метаданных с SHA-256, привязкой к успешному producer и исходному OCI digest; исключить файловые слои и архивы образов.
- Сохранять сборку один раз, provenance, существующий параллелизм, проверки и все gates. Назначать `sha-*`, `main` и `staging` только после общего успеха; PR не публикуют кандидатов.
- Автоматически удалять только устаревшие завершённые служебные кандидаты и доказанно принадлежащие им незащищённые manifests. Защищать все выпускные/неизвестные теги и разделяемые manifests.
- Подтвердить объём handoff и отсутствие замедления обычным CI/staging, без отдельных benchmark-прогонов.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `crm-autodeploy`: служебное хранение проверенных OCI отдельно от выпуска, продвижение исходного digest, ограниченные метаданные Actions и безопасная автоматическая очистка кандидатов.

## Impact

Задача №219, ветка `bugfix/219` от свежего `origin/staging` `6b5742d85ee3fe135cbe6260ab6ff44f035aa324`. Изменяются workflows, CI helpers, их тесты и инструкция деплоя. Новых зависимостей и миграций нет. Существующие БД, S3, серверы, restic и watchers не изменяются. Исторические Actions artifacts сейчас не удаляются: для них сохраняется ранее согласованный отдельный список. Коммит/публикация и перенос в main требуют прямого указания согласно AGENTS.md.
