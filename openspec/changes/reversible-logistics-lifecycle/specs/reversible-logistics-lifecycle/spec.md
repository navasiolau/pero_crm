## ADDED Requirements

### Requirement: Сохраняемый состав рейса

Система SHALL сохранять записи снятых долей и строк с прежними идентификаторами и учитывать только активные строки и доли в текущем рейсе.

#### Scenario: Удаление проекта из черновика

- **WHEN** оператор убирает проект со строками из состава и сохраняет рейс
- **THEN** список, поиск и чтение рейса используют только новый состав
- **AND** отмена возвращает прежний состав и прежние идентификаторы

### Requirement: Штатный откат рейса

Система SHALL связывать пользовательские действия по созданию, редактированию, удалению и проведению рейса с общим откатом журнала для ADMIN/DIRECTOR.

#### Scenario: Отмена исправления оплаты между кассами

- **WHEN** уполномоченный пользователь отменяет исправление актуальной ревизии
- **THEN** система сохраняет исходный журнал проводок и создаёт новую проводку из исходного валютного снимка и комплекта ТТН
- **AND** сохраняет полное соответствие итоговых сумм долям по проектам

#### Scenario: Текущих остатков не хватает

- **WHEN** после восстановления исторической проводки остаток кассы или баланс организации стал бы отрицательным
- **THEN** состояние оплаты, состав рейса и журнал остаются без изменений

### Requirement: Сохранение оригинала ТТН

Система SHALL сохранять файл, исходные метаданные и историю накладной при откате загрузки.

#### Scenario: Отмена свободной ТТН

- **WHEN** журнал отменяет загрузку READY ТТН, свободной от ссылок проводок
- **THEN** документ скрывается из обычного чтения, списка и поиска
- **AND** обратная операция возвращает прежний ID и оригинал без повторной записи файла

#### Scenario: ТТН используется в исторической проводке

- **WHEN** пользователь пытается скрыть ТТН, привязанную к любой проводке рейса
- **THEN** операция отклоняется, сохраняя исторический документ
