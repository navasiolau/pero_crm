# Proposal

## Why

Владелец уточнил задачу112: после успешной загрузки нового эскиза прежний эскиз должен исчезнуть из вложений и быть физически удалён вместе с миниатюрой. Baseline `3f4c0d9ccd4c90c6002e8168c50d5bff01d648a8` сохраняет старый File и его bytes; приёмка09.10.2026 подтверждала именно прежнюю политику и не подтверждает это уточнение.

## What Changes

- Атомарно сменить текущий эскиз, удалить ровно исходный File и сохранить точное задание очистки в существующем DomainEvent; удалять его original и thumbnail только после COMMIT.
- Удалять все версии и delete markers ровно двух ключей S3, проверяя физическое отсутствие; для local fallback удалять только точные файлы.
- Подтверждать успех после очистки; при её сбое возвращать503 с `commitState=committed`, сохраняя durable intent и возможность завершить очистку повтором той же mutation.
- Сохранить DESIGN-only техническое разрешение назначенного ENGINEER и ENGINEERING-участника, включая замену чужого и legacy-эскиза без автора; обычное право удаления вложений не расширять.
- Сохранить CAS/replay/compensation: конфликт и повтор устаревшей операции не меняют текущий указатель и не удаляют победивший файл. Активная общая ссылка обложки запрещает замену до записи.
- Выполнить focused RED→GREEN и новую root-only staging-приёмку exact old File/original/thumbnail versions; исторический backend3 harness и его receipts не изменять.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `engineer-product-access`: точечное физическое удаление вытесненного текущего эскиза и восстановимое завершение очистки. Новая политика владельца заменяет требование сохранения прежнего вложения из исторического change `engineer-sketch-replacement`; инженерные ACL и статусные переходы не расширяются.

## Impact

Ветка `bugfix/112`, один прежний OpenSpec change. Изменяются product sketch transaction/upload acknowledgment, точная storage cleanup, существующий outbox dispatcher и focused тесты. Миграций, нового сервиса или массового удаления исторических эскизов нет. Коммиты и staging-интеграция уже разрешены владельцем; main/production требуют отдельного прямого указания.
