# Доказательства UI покрытий состава

Компонент состава группирует слои по поверхности и сохраняет серверный порядок слоёв. Название, код, необязательный HEX и файл-образец показаны раздельно. HEX используется только как цветовой образец и не подставляется вместо текстуры или кода. Надпись `Образец не задан` показывается только при отсутствии и HEX, и изображения.

Миниатюра использует существующий защищённый маршрут `/api/files/{id}?thumb=1` через `next/image` с `unoptimized`. Оригинал открывается тем же защищённым маршрутом в новой вкладке. Список вариантов файла запрашивается на странице изделия только при `canEditTech`. Добавление, правка и удаление покрытий доступны только для выбранного черновика, если разрешено редактирование состава.

При открытии формы или подтверждения удаления UI фиксирует `productId`, `revisionId` и `draftVersion`. Все запросы используют этот снимок, даже если параллельный `router.refresh()` принёс новые props. Устаревшая версия закрывает старую форму/диалог, показывает серверное сообщение и обновляет карточку без автоматического повтора. При неизвестном результате старый редактор закрывается, карточка обновляется, а пользователь видит сообщение проверить результат до новой правки.

Локальные проверки: сначала regression-тест привязки завершился RED с `MODULE_NOT_FOUND`, затем `pnpm exec tsx --test tests/composition-finish-binding.test.ts` прошёл 3 проверки привязки и неизвестного результата. `pnpm exec tsx --test tests/surface-finishes-ui.test.tsx tests/product-composition-view.test.tsx` прошёл 10 сценариев SSR и валидации. Scoped ESLint прошёл для компонентов состава и покрытия, страницы изделия и UI-тестов. Общий TypeScript/build выполняет root после завершения параллельной серверной работы.

Ограничения: не выполнялись живая CRM, просмотр на ширинах 360/390/1440 px, авторизованная загрузка защищённой миниатюры и ручная проверка клавиатурой в браузере. Ролевые серверные проверки и БД принадлежат параллельной backend-работе. Поэтому задача OpenSpec 3.1 остаётся незакрытой до runtime, role и responsive приёмки.
