# Design

**Execution agreement:** Номер задачи 122, ветка feature/122 согласованы владельцем 10.10.2026; OpenSpec и реализация одобрены. Одна целевая локальная проверка, затем существующий полный CI без изменений и развёртывание на staging только через него; одна целевая staging-приёмка. Повторные полные ручные проверки не выполнять без конкретного сбоя. Production/main этим запуском не разрешены.

## Context

Мотивация — `proposal.md`. База `origin/staging` `ab1c77f3b82cab788f206914d5b2a063e6aafe68`. `/payroll` получает только текущего пользователя сессии. `getMyPayroll` возвращает текущий долг/оценку и отдельно начисления/выплаты выбранного месяца; сейчас они стоят в четырёх равнозначных карточках под одним MonthSwitcher. Две таблицы имеют 4 и 6 колонок, включая тип, кассу и автора.

## Goals / Non-Goals

**Goals:** объяснить доступную к выплате сумму, предварительный текущий месяц и историю выбранного периода с меньшим количеством постоянно видимых деталей.

**Non-Goals:** новая формула долга/оценки, закрытие текущего месяца, финансовая сводка сотрудников, запрос выплат, изменение валютной истории или публичный просмотр другого расчётника.

## Decisions

1. **Разные временные области видны в компоновке.** Верхний блок «Сейчас» содержит две суммы: «К выплате сейчас» и «За <текущий месяц>, приблизительно». Ниже отдельный блок «История за месяц» с MonthSwitcher и двумя компактными итогами — «Начислено»/«Выплачено». Переключатель относится только к этому нижнему блоку; текущая сводка не выдаётся за историческую.

```text
Моя зарплата

Сейчас
[К выплате сейчас]   [За текущий месяц, приблизительно]

История за [месяц]
Начислено: … BYN     Выплачено: … BYN
Начисления: дата · основание · сумма · детали
Полученные выплаты: дата · зарплата/аванс · сумма · детали
```

2. **Начисления и полученные деньги не объединяются.** Сохраняются две понятные секции. Основные строки — дата, основание/вид выплаты, сумма; тип начисления, комментарий, автор, касса и валютные исходники раскрываются по «Детали». Используются существующие DataTable/семантические раскрытия, а не новый график или библиотека. Период и единица BYN подписаны у итогов.

3. **Сохранённые денежные факты не меняются.** Представление использует уже рассчитанные server values и сохранённые BYN-эквиваленты, без пересчёта по сегодняшнему курсу. Исходная валюта/физически выданная сумма остаётся в деталях. NULL показывается как невозможность точного расчёта, не 0. Для отрицательного долга отображается «К выплате сейчас: 0» и отдельное пояснение «Выплачено вперёд: …»; исходный серверный debt и его влияние на будущие выплаты не меняются. Это не переименование любой выплаты в ADVANCE: тип строки сохраняется.

4. **Текущий месяц явно предварительный.** История текущего месяца имеет отметку «Месяц ещё идёт»; её начисления не представляются доступным к выплате долгом. Название текущего месяца используется из того же серверного периода, что и сводка, а не независимо выводится клиентским часовым поясом. Правила месячного закрытия не меняются.

5. **Личные данные остаются личными.** Actor берётся из сессии; month разрешено выбирать, userId — нет. Новый layout не подтягивает общий payroll workspace или суммы коллег. Директор по прежнему не получает личную зарплатную страницу.

## Risks / Trade-offs

- Раскрытие скрывает нужные сведения → основные суммы/вид выплаты всегда видны; детали доступны клавиатурой и на мобильном экране.
- При смене месяца текущий долг принят за итог периода → отделённая область «Сейчас» и подпись периода сохраняются.
- Историческая валюта не даёт BYN → показать неизвестность и исходные данные в деталях, не изобретать пересчёт.

## Migration Plan

Без миграции или финансовых writes. Отдельная согласованная feature; сравнить до/после все исходные суммы и число личных записей, проверить два периода, текущую предварительную оценку, аванс/отрицательный debt, NULL и 1440/390. После разрешённых merge/push/CI принять фактическую личную страницу staging. Дампы/restic не нужны; расчётные функции не переписываются ради оформления.
