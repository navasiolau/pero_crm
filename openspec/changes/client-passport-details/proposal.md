# Proposal

## Why

В карточке клиента уже есть ФИО, телефон, адрес и e-mail, но нет паспортных реквизитов для оформления заказа. Согласованная задача №171 добавляет эти сведения с доступом только для управления клиентами.

## What Changes

- Добавить необязательные «Номер паспорта» и «Кем выдан» в создание, редактирование и просмотр клиента.
- Разрешить чтение и изменение паспортных реквизитов ADMIN, DIRECTOR и MANAGER; остальные роли не получают значения в серверных DTO.
- Сохранить контактные поля, аудит и сравнение исходных значений каждого изменяемого поля, включая паспортные реквизиты.
- Добавить только nullable-колонки; существующие клиенты и финансовая история сохраняются.

## Capabilities

### New Capabilities

- `client-passport-details`: необязательные паспортные реквизиты, ограничение чтения и безопасное конкурентное редактирование клиента.

### Modified Capabilities

Нет. Действующие правила видимости клиентов через доступные проекты сохраняются.

## Impact

Prisma Client/миграция, серверный CRUD клиента и проекции чтения, общий ClientDialog и справочник клиентов. Перекрывающие чтения клиента в проекте и поиске получают явные безопасные проекции. Новых зависимостей, REST-полей для бота и переноса legacy-данных нет. Применение миграции к существующей БД и staging-приёмка требуют доступного разрешённого окружения.
