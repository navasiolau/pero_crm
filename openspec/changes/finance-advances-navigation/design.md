# Design

## Context

Существующая форма уже использует финансовые server actions с ограничениями кассы. Задача 58 исключила чистого менеджера из ADVANCE_ROLES, но lib/nav.ts всё ещё содержит `/advances`. На странице финансов уже есть входы в зарплату, кассы и проекты. Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:** каноническая финансовая страница, сохранение существующей формы и совместимости старой ссылки.

**Non-Goals:** пересчёт авансов, смена схем оплаты, разрешение произвольных выплат менеджеру, миграции и правка данных.

## Decisions

- Новая server page `/finance/advances` повторно использует существующий AdvancesView и listAdvanceOptions. Не перемещаем общие компоненты, чтобы не менять импорты зарплаты и денежные операции.
- Новая страница проверяет auth и ADVANCE_ROLES; middleware дополнительно защищает весь `/finance`. Совмещённые роли сохраняют объединение прав.
- Старый `/advances` выполняет авторизованный redirect на новую страницу. Удаление маршрута дало бы ошибку по сохранённым ссылкам.
- Удаляем nav entry и не заменяем его другим отдельным пунктом. Вход находится на странице финансов.

## Risks / Trade-offs

- Старые ожидания тестов меню содержат `/advances` → обновить существующие проверки финансовых ролей и календаря; проверить прямой доступ обеих групп ролей.
- Параллельная задача общего прихода меняет страницу финансов → координатор объединяет обе рабочие ветки обычным merge и сохраняет оба входа.

## Migration Plan

Миграции БД не нужны. Координатор выполняет локальные проверки, обычный merge в staging и проверяет фактическую новую страницу и совместимый переход на развёрнутой ревизии. Исторические выплаты не изменяются.
