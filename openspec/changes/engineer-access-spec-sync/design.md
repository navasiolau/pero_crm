# Design

## Context

Исходная ревизия задачи: `3819f175dca3f69f40da92760cf746bad430f4bc`, ветка `bugfix/127`. Основная спецификация не синхронизирована с уже принятыми `engineer-production-return` и `procurement-finance-access`. Сервер разделяет текущий инженерный read DESIGN/PRODUCTION, технический DESIGN-grant участника и самостоятельные grants ролей. Ошибка подстановки участника вместо назначения в глобальном канбане исправляется отдельной задачей 128.

## Goals / Non-Goals

**Goals:** непротиворечивая основная спецификация и проверяемая матрица действующих разрешений.

**Non-Goals:** новое право доступа, изменение приложения или внешнего вида, SQL-миграция, переписывание исторических уведомлений/оплаты, исправление UI задачи 128, закрытие инцидента iMac.

## Decisions

1. Синхронизировать полный блок каждого затронутого requirement, включая Purpose, смешанный проект и уведомления. Частичная замена DESIGN на DESIGN/PRODUCTION могла бы случайно расширить техническое редактирование.
2. Явно разделить текущее `Product.engineerId` и историческое участие. Самостоятельный технический DESIGN-grant не удалять; он не заменяет назначение в PRODUCTION.
3. Описать действующее объединение ролей: ACCOUNTANT не даёт общего операционного просмотра; PROCUREMENT даёт просмотр и самостоятельные складские/финансовые права. Производственную матрицу и DRAFT-ограничения сохранить по актуальной политике.
4. Добавить в основную capability требование возврата со ссылкой на принятую спецификацию `engineer-production-return`; runtime-код не менять. Существующие поведенческие tests достаточны для документного change, новый тест буквального текста не нужен.
5. Локально запустить `engineer-access`, `engineer-access-actions`, `engineer-production-return`, `engineer-filter-visibility`, `single-product-percentage-core` и `procurement-access`. Native/browser доказательство на принятом staging собирает оркестратор; модульные fixtures не выдаются за него.

## Risks / Trade-offs

- [Устаревшие границы ACCOUNTANT или FIELD] → сверка с принятыми changes и текущими query/action tests; никаких runtime-правок.
- [Ложное закрытие глобального канбана] → отдельная задача 128 и явная запись границы приёмки.
- [Модульная проверка принята за staging] → отдельно фиксировать статус runtime и принятый SHA.

## Migration Plan

Миграций и новых зависимостей нет. Изменение проходит независимое ревью, локальную OpenSpec strict validation и regression suites, обычный merge в staging и проверку фактической staging-ревизии. Main остаётся вне разрешённого выпуска.

Обязательная безопасность: `D:/Projects/pero_infra/infra-recovery/SAFETY-RULES.md`; при несовпадении guard СТОП. Нет дампов, reset, seed, restic, production или инфраструктурных операций.
