# Proposal

## Why

Ответственному за работы нужно перераспределять обычные незавершённые задания в уже доступных изделиях, сохраняя объём, оплату и историю. Отдельная команда исполнителя закрывает обход через общую форму задачи и подтверждает повторы без второго назначения.

## What Changes

- WORK_COORDINATOR получает узкое назначение/переназначение/распределение обычных LEGACY задач доступных изделий; чтение чужой задачи не даёт её выполнение или глобальные финансовые права.
- Отдельное переназначение меняет assigneeId и возвращает задачу в NEW с CAS splitRevision, UUID receipt, аудитом, событием и уведомлением. Количество, группа, денежный снимок, вложения и история сохраняются; DONE/PayrollEntry/settlements запрещают операцию.
- Получатель — активный подходящий сотрудник с PIECE и правом обычной сдельной оплаты. Свежие роли и доступ проверяются внутри транзакции. Для частичной передачи используется разделение №191.
- MANAGER использует ту же команду для обычной задачи. Списки расценок/работ получают opt-in ширину560px либо ширину trigger, если больше, с ограничением viewport и переносом названий.

## Capabilities

### New Capabilities

- `work-coordinator-reassignment`: узкое управление исполнителем обычной работы с сохранением снимков и совместным UI.

### Modified Capabilities

Нет.

## Impact

Новые policy/core/actions/query/dialog переназначения; narrow visibility grant чтения LEGACY задач и DTO affordance; после обычного merge191 — общие task-dialog/actions/my/tasks-tab. Опциональные параметры SearchableSelect применяются только к work/rate selectors. Схема БД и роли менеджмента не меняются.
