# Proposal

## Why

КП должно быть источником коммерческих данных заказа. Сейчас отдельный генератор не связывает позиции с изделиями CRM, а создание проектов не использует общую блокировку мутаций.

## What Changes

- Единая транзакционная выдача номера для обычного проекта и проекта КП; аудит и outbox входят в ту же транзакцию.
- Внутренние операции создания и сохранения КП с проверкой ревизии, повторяемым идентификатором операции и полной синхронизацией активного состава.
- Стабильные ID позиций и изделий, мягкое скрытие исключённых изделий, безопасная перенумерация активных изделий и проверка принадлежности одному проекту.
- Выбор существующего клиента, проверенный ID служебного клиента и структурированное обновление реквизитов с защитой карточки «Временный».
- MANAGER получает доступ только к действующим связанным черновикам КП; ссылки используют ID изделия.
- Публичный раздел остаётся выключенным; денежная синхронизация подключается следующим change внутри той же транзакции.

## Capabilities

### New Capabilities

- `kp-project-synchronization`: создание КП с проектом и транзакционная синхронизация коммерческого состава.

### Modified Capabilities

Нет.

## Impact

Серверные домены projects/products/kp, политика доступа и ссылки изделий, индекс номера Product и защитные ограничения ProposalItem. Зависит от аддитивного хранения задачи №180. Публичные API, генерация, денежные формулы, S3 и архивный импорт в №181 не добавляются.
