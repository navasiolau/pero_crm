# Design

## Context

См. proposal.md. Денежное ядро считает Payment и Payout, используя сохранённые эквиваленты. Исторические выплаты могут не иметь кассы, физической суммы или BYN. Валюта кассы после создания не редактируется.

## Goals / Non-Goals

**Goals:** сверяемые начальный/конечный остатки и движение за период, единые знаки/Decimal и честная неполнота.

**Non-Goals:** изменение денег, начислений, курсов, старых записей или настройка складского учёта.

## Decisions

- Read-only loader с FINANCE guard выбирает все Payment по paidAt и Payout по createdAt до исключающей верхней границы. Зарплатные начисления и StockMovement в cash report не входят.
- Общий cashMovementDelta используется денежным ядром, списком касс и новым отчётом. historicalByn сохраняет действующее правило: сохранённый BYN либо явно сохранённая валютаBYN; сегодняшний курс не вызывается.
- Обе даты включены, верхняя граница — следующий день00:00 Europe/Moscow через существующий календарный parser. Общий helper пригоден и для аналитики108.
- Расходы отображаются отрицательными, как в референсе; closing=opening+income+expense. DTO денег — decimal strings|null, чтобы не терять копейки больших итогов; точный форматтер не приводит их к Number.
- РежимBYN объединяет сохранённые эквиваленты. Native использует физические amount/cashAmount только в подтверждённой валюте кассы. Отсутствие физической суммы/валюты или несовпадение валют делает зависимый итогNULL, не приводит чужую валюту к текущей.
- Неактивные кассы сохраняются. Операции без кассы выводятся отдельно, с известной валютой или меткой неизвестности; это не автоматическое распределение по кассам. Footer totals разделяются по валютам; строки неполной истории отмечаются.
- Один набор фактов формирует остатки, группы и детализацию. Пустая касса имеет подтверждённые нули; неизвестная сумма не ноль. Историческая неизвестность до начала влияет на opening/closing, но не скрывает известное движение периода.
- Экран использует общие UI/table/FileViewer. Раскрытие кассы показывает даты, тип, назначение/сотрудника, проект и отчётный документ. Из отчёта ничего не удаляется.

## Risks / Trade-offs

- Неполные старые выплаты → предупреждение по фактическим отсутствующим данным иNULL зависимых сумм.
- Большой срок → сумма считается по всей истории до конца периода, детали показываются только внутри периода с пагинацией.
- Ошибка границ → тесты MSK-midnight, конца месяца, обеих выбранных дат и периода без операций.

## Migration Plan

Без миграции. Local unit/native/UI, обычный merge, CI, actual staging. Складской gate не нужен для этого read-only отчёта; main ожидает владельца.
