# Spec Delta

## Purpose

Предоставить редактору и автоматизированным агентам единый доступ к КП и договорам с транзакционной согласованностью, ограниченными полномочиями и приватной выдачей файлов.

## ADDED Requirements

### Requirement: Панель КП в CRM
Меню SHALL показывать «КП и договоры» сразу после «Изделия». Редактор CRM MUST исключать полосу с логотипом, «Перо Лайв» и подзаголовком генератора. Обе кнопки «Сгенерировать PDF» и «Сгенерировать договор» SHALL находиться в панели CRM над редактором и выполнять существующие операции с сохранённой ревизией. Печатное оформление MUST сохраняться.

#### Scenario: Выбор клиента без дополнительных кнопок
- **WHEN** пользователь выбирает другого клиента CRM в редактируемом КП
- **THEN** КП сохраняет связь и сразу получает его данные, а форма договора подставляет реквизиты выбранного клиента; кнопки создания и редактирования клиента отсутствуют

#### Scenario: Выпуск из панели CRM
- **WHEN** пользователь запускает PDF либо договор из панели над редактором
- **THEN** вызывается существующий workflow; просмотр прошлой версии сохраняет ограничения выпуска, а договор текущей заблокированной редакции остаётся доступен

### Requirement: Имя скачиваемого PDF
PDF коммерческого предложения SHALL скачиваться с именем `КП_<номер>.pdf`, например `КП_222.pdf`. Номер MUST браться из снимка выпуска, а не из внутреннего ID. Это правило SHALL действовать для новых PDF, сохранённых версий и PDF, подготовленных вместе с договором. Содержимое документа и ключи хранилища MUST сохраняться.

#### Scenario: Скачивание ранее выпущенного КП
- **WHEN** пользователь повторно скачивает PDF сохранённой версии с номером 222
- **THEN** получает `КП_222.pdf`, даже если исходное имя артефакта было сохранено без номера

### Requirement: Раздельная проверенная авторизация
Session API SHALL требовать актуальную web-сессию и роль ADMIN/DIRECTOR/MANAGER; изменения MUST проверять тот же Origin. Публичный v1 MUST принимать только Bearer и явные scopes КП действующего ключа активного владельца с одной из этих ролей. Общие read/write/admin MUST NOT заменять scopes КП.

#### Scenario: Непривязанный либо отозванный ключ
- **WHEN** запрос содержит legacy admin-ключ без владельца, неподходящую роль, недостаточный scope или отозванный ключ
- **THEN** операция отклоняется до чтения тела и бизнес-данных; cookie не заменяет Bearer

### Requirement: Авторизация долгих операций
Система MUST повторно проверять владельца, роли, отзыв, scopes и версию сессии до/после долгого I/O и в финальной транзакции. Аудит команды SHALL содержать ID ключа без секрета.

#### Scenario: Отзыв во время рендера
- **WHEN** ключ или сессия отозваны после запроса выпуска
- **THEN** финальная публикация и автоматические переходы проектов не выполняются

### Requirement: Единое сохранение и восстановление ответа
Оба API SHALL использовать один сервис с `operationId` и ожидаемой ревизией. Повтор SHALL возвращать прежний результат; смена содержимого с тем же UUID MUST отклоняться. `GET operations/:uuid` SHALL разрешать потерянный ответ создания без повторного проекта. Неожиданный номер MUST откатывать создание и не расходовать номер.

#### Scenario: Потерян ответ создания
- **WHEN** создание подтверждено БД, но HTTP-ответ потерян
- **THEN** агент получает исходный результат по UUID, а повтор не создаёт второго проекта

### Requirement: Сохранённые снимки и приватные результаты
PDF, версии и договоры MUST выпускаться только из сохранённых серверных ревизий. API SHALL отдавать приватные авторизуемые URL; state SHALL сохранять `kp-media:` ссылки и не раскрывать ключи S3, credentials или публичные URL.

#### Scenario: Попытка рендера произвольного состояния
- **WHEN** запрос PDF/договора передаёт raw state либо чужие media/version/artifact ID
- **THEN** запрос отклоняется; сохранённый документ и этапы не меняются

### Requirement: Фиксированный курс и границы транзакции
Система SHALL получать НБРБ вне транзакции на дату КП только при создании или явном запросе нового курса. Обычное сохранение SHALL применять сохранённый курс; восстановление версии SHALL применять исторический курс в общей транзакции.

#### Scenario: Повтор обычного сохранения
- **WHEN** КП сохранено без изменения валюты и явного курса
- **THEN** новый сетевой курс не запрашивается, все цены и связи обновляются одной транзакцией

### Requirement: Ограничения HTTP и выключенный раздел
API MUST ограничивать фактический поток JSON/файла, проверять закрытые входные схемы и не доверять Content-Length. При выключенном модуле все его маршруты SHALL возвращать 404; ограничения этапов действуют независимо от feature flag.

#### Scenario: Большое либо неподдерживаемое тело
- **WHEN** размер потока превышает лимит или запрос содержит неподдерживаемые поля
- **THEN** чтение прекращается и операция не создаёт записей или объектов
