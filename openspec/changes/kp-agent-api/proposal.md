# Proposal

## Why

Редактор и ИИ-агенты должны использовать единые операции сохранения и выпуска КП. Отдельный доступ по ключу требует ограниченных scopes, действующего владельца и повторяемых команд без дублирования проектов или документов.

## What Changes

- Общий сервис собирает синхронизацию, фиксированные курсы, приватные изображения, версии и договоры задач №180–186.
- Session API `/api/kp` и Bearer-only `/api/v1/kp` используют одинаковые команды и DTO, проверки ревизии и `operationId`.
- Отдельные явные scopes КП, свежая проверка пользователя/ключа на границах долгого I/O и аудит ключа в транзакции команды.
- Приватная выдача изображений и документов; передача состояния напрямую рендеру запрещена.
- Настройки ключей получают отдельный пресет ИИ-агента КП; остальные API сохраняют действующее поведение.

## Capabilities

### New Capabilities

- `kp-agent-api`: общий session/Bearer API КП и договоров с повторяемыми командами и ограниченным доступом.

### Modified Capabilities

Нет.

## Impact

Серверный сервис КП, маршруты session/v1, настройки API-ключей, OpenAPI и документация интеграции. Зависимости №180–186 объединяются обычным merge; облачные данные и выпуск не меняются при реализации.
