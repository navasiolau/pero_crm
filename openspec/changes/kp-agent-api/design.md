# Design

## Context

См. proposal.md. Модули №181–186 предоставляют транзакционные операции, подготовку media вне транзакции, неизменяемые версии и договоры. Существующий verifier хранит SHA256 ключа, допускает сервисные ключи без владельца и wildcard admin для старых API; их поведение сохраняется.

## Goals / Non-Goals

**Goals:** общий production service и тонкие session/Bearer handlers, свежая авторизация и повторяемые операции, реальное подключение производителей.

**Non-Goals:** изменение шаблонов, новые права остальных API, импорт облака, включение feature flag либо deployment. MCP/skill/Python принадлежат основному агенту.

## Decisions

- Два catch-all route используют общий router с явной таблицей HTTP-методов и scopes. Session route самостоятельно проверяет auth/Origin и исключается из middleware, чтобы не клонировать multipart body.
- Новый authorizer повторно читает реальный ApiToken и User, требует явный scope и прежнего владельца. Общий VerifiedToken не расширяется. JWT sessionVersion передаётся через существующий session callback и проверяется повторно; в финальной tx строки User/ApiToken блокируются SHARE.
- Командный receipt и аудит ключа сохраняются в ChangeLog той же транзакцией, что бизнес-изменение. Replay проверяется до НБРБ/media prep и повторно под общей блокировкой. ID новых позиций назначаются детерминированно для operationId; ожидаемый номер проверяется до commit.
- Внешний НБРБ, Sharp/S3 и Chromium выполняются вне SQL-транзакции. Финальная запись использует №181 hooks денег/медиа; rate snapshot сохраняется вместе с коммерческими данными. Restore передаёт исторические реквизиты, курс и состояние тому же in-tx save.
- PDF/договор возвращают долговечный job. Worker повторно авторизует сохранённый ActorBinding при claim, I/O и finalize; private artifact download дополнительно проверяет владельца документа и hash/size.
- Canonical state возвращается без переписывания media-токенов. HTTP download URL формируется относительно выбранного API; metadata не содержит storage binding/key. Отдельный multipart alias поддерживает перенесённый редактор.
- JSON ограничен 2 МиБ, каждое изображение 15 МиБ; multipart ограничен суммой двух изображений и 256 КиБ overhead. Реально прочитанные байты считаются независимо от заголовка.

## Risks / Trade-offs

Уточнение приёмки 22.10.2026: оболочка CRM содержит выбор клиента, версии и обе кнопки генерации; прежняя полоса с брендом удаляется только из HTML редактора CRM. Команды панели вызывают существующие функции сохранения/выпуска и открытия договора через проверенный same-origin bridge. Выбор клиента сразу сохраняет его ID и полный снимок; управление справочником остаётся на странице клиентов. Печатные HTML/CSS, шаблон DOCX и шрифты не меняются.

- Изменение данных во время НБРБ/media подготовки → повторная проверка ревизии и полномочий в final tx, orphan ledger сохраняет неподтверждённые копии для дальнейшей очистки.
- Потерян ACK → receipt/GET operations; новое создание без проверки старого UUID не требуется.
- Dependencies ещё не merged → импорты производителей сохраняются реальными, полная типизация/HTTP/native приёмка выполняются после обычных merge; заглушки не считаются реализацией.

## Migration Plan

Новых миграций №187 не планируется. После обычного объединения №180–186 выполнить Prisma generate, проверки сервиса/auth/HTTP и guarded native сценарии. Раздел остаётся выключенным до сквозной приёмки. Production, облачные данные и хранилища этим change не изменяются.
