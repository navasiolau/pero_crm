# Spec Delta

## Purpose

Финансовые пользователи сохраняют и просматривают отчётные документы независимо от наличия проекта, сохраняя изоляцию технических файлов и надёжность повторной загрузки.

## ADDED Requirements

### Requirement: Финансовый доступ
Система SHALL разрешать загрузку только активным ADMIN, DIRECTOR, ACCOUNTANT, PROCUREMENT с объединением ролей. Непривязанный документ SHALL быть виден только загрузившему его пользователю; документ платежа SHALL быть доступен финансовым ролям. Каждое чтение и изменение MUST проверять текущие права.

#### Scenario: Бухгалтер без технического доступа
- **WHEN** чистый ACCOUNTANT загружает общий финансовый документ
- **THEN** загрузка и просмотр доступны, технические файлы и права проекта не расширяются

#### Scenario: Чужой неподвязанный файл и отзыв роли
- **WHEN** другой пользователь запрашивает неподвязанный файл либо финансовая роль отозвана
- **THEN** содержимое не выдаётся; для запроса без финансовых прав хранилище не читается

### Requirement: Подтверждённая однократная загрузка
Система SHALL подтверждать файл только после записи содержимого в настроенное хранилище. Повтор с прежним идентификатором и теми же данными MUST возвращать прежний документ, а изменённые данные или другой actor MUST отклоняться. Ошибка хранилища SHALL не подтверждать готовность файла и не создавать денежную операцию.

#### Scenario: Обрыв и повтор
- **WHEN** загрузка повторена после потери ответа
- **THEN** возвращается единственный исходный документ без второй записи аудита

#### Scenario: Ошибка записи
- **WHEN** сохранение содержимого завершилось ошибкой
- **THEN** документ недоступен для использования в платеже, повтор загрузки остаётся возможен

### Requirement: Просмотр и совместимость
Система SHALL предоставлять загрузку из формы операции и кнопку «Отчетный документ» в строках расходов организации и складских движений, имеющих доступный готовый документ. Кнопка SHALL открывать общий полноэкранный просмотр изображения/PDF, для неподдерживаемого формата — полноэкранное представление с возможностью скачать оригинал. При отсутствии файла кнопки SHALL не быть. Самостоятельный экран загрузки/списка документов в Финансах SHALL отсутствовать. Исторические File и Payment SHALL сохраняться.

#### Scenario: Старый платёж и обычное вложение
- **WHEN** применяется аддитивная миграция документов
- **THEN** существующие платежи без документа и прежние ссылки технических вложений остаются действительными

#### Scenario: Документ в двух журналах
- **WHEN** у денежного расхода, связанного с приходом на склад, есть готовый документ
- **THEN** финансовый пользователь открывает один исходный файл кнопкой в обеих строках, включая мобильное представление

#### Scenario: Нет документа или финансового доступа
- **WHEN** у строки нет файла, например при инвентарном движении, либо у пользователя нет финансовой роли
- **THEN** кнопки нет, закрытые финансовые метаданные не передаются

#### Scenario: Прежняя ссылка и полноэкранный просмотр
- **WHEN** открыта прежняя страница документов либо кнопка файла в строке
- **THEN** прежняя страница перенаправляет к расходам; кнопка открывает полноэкранный просмотр, не открывая одновременно карточку операции
