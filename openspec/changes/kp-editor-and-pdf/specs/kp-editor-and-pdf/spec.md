# Spec Delta

## Purpose

Сохранить привычный редактор коммерческих предложений и внешний вид документов при работе внутри CRM, с приватными изображениями, проверкой ревизий и изолированным рендером.

## ADDED Requirements

### Requirement: Закрытый редактор CRM
Система SHALL открывать редактор и его ресурсы только активным ADMIN, DIRECTOR и MANAGER при включённом разделе. Редактор SHALL сохранять исходную компоновку, предпросмотр и мобильный интерфейс без влияния CSS CRM.

#### Scenario: Раздел выключен или роль отозвана
- **WHEN** пользователь напрямую запрашивает страницу, iframe или ресурс редактора без действующего доступа
- **THEN** сервер возвращает 404 и приватный ответ не попадает в offline-кеш.

### Requirement: Сохранение и экспорт по серверной ревизии
Редактор MUST сохранять стабильные ID позиций, `crmKind` услуг и канонические ссылки изображений. Экспорт SHALL ожидать успешного сохранения и отправлять идентификатор КП, ревизию и UUID операции. Локальный черновик SHALL быть изолирован по пользователю, КП и серверной ревизии.

#### Scenario: Изменение формы перед PDF
- **WHEN** пользователь изменяет КП и нажимает «Сгенерировать PDF»
- **THEN** сначала завершается сохранение, затем запускается задание сохранённой ревизии; при конфликте PDF не запускается.

#### Scenario: Заблокированный проект
- **WHEN** сервер сообщает, что КП нельзя редактировать
- **THEN** редактор показывает причину и закрывает изменения/сохранение, оставляя просмотр и разрешённые операции договора.

### Requirement: Совместимый ограниченный рендер
Renderer SHALL сохранять исходные расчёты SheetRender, A4 без полей, фон, порядок и оформление страниц. Он MUST использовать закреплённые шрифты, дождаться их и всех изображений, отклонять отсутствующие ресурсы и любые внешние URL. Задание SHALL иметь ограничения ресурсов и времени; ошибка не создаёт готового выпуска.

#### Scenario: Неизвестное изображение или сетевой URL
- **WHEN** сохранённый снимок содержит ресурс без предоставленных принадлежащих ему байтов
- **THEN** рендер завершается ошибкой до публикации и не загружает URL из сети.

#### Scenario: Договор из сохранённого PDF
- **WHEN** для приложения договора предоставлен прежний PDF без доступных исходных изображений
- **THEN** изолированный worker возвращает страницы PNG с ограничением времени и объёма байтов, сохраняя порядок PDF без произвольного предела числа страниц.

### Requirement: Нет произвольного предела числа страниц

Редактор, валидаторы рендера и клиент ответа SHALL NOT ограничивать PDF, растеризацию или DOCX фиксированным числом страниц. Ограничение64 SHALL удаляться, а не заменяться другим числом. Положительный целый pageCount и соответствие фактическим страницам MUST проверяться. Проверка большого документа SHALL выполняться только на staging, без200-страничного теста production.

#### Scenario: КП на200 страницах
- **WHEN** на существующем staging редактируют синтетическое КП на200 страницах и запускают генерацию
- **THEN** правки сохраняются в проверяемом снимке, настоящий PDF содержит200 страниц и исходное оформление сохраняется

### Requirement: Документ не меняет оформление
Перенос MUST сохранять печатные CSS, шаблон договора и структуру отображаемых расчётов. Данные клиента, курса и версий SHALL передаваться через интерфейсы CRM, не меняя подписи строк печатного КП.

#### Scenario: Сравнение эталонов
- **WHEN** одинаковый снимок с длинным описанием, несколькими изображениями и услугами отображается исходным и перенесённым шаблоном
- **THEN** состав страниц и результат визуальной сверки совпадают для всех страниц.

### Requirement: Проверенный парный выпуск renderer
CI MUST испытать исходный Linux141 renderer OCI и сохранить тот же digest без пересборки при публикации. Web OCI SHALL ссылаться на испытанный renderer через immutable label с общей revision/protocol/source/font/template идентичностью. Opt-in watcher SHALL сохранять штатный автоматический GitFlow, использовать branch tag только как discovery и обновлять пару по immutable refs под прежними W07/lock.

#### Scenario: Частичная публикация
- **WHEN** новый web уже обнаружен, но связанный renderer digest недоступен или несовместим
- **THEN** watcher не изменяет работающие сервисы и не запускает новую половину пары.

#### Scenario: Ошибка здоровья пары
- **WHEN** после обновления web или renderer не проходит проверку здоровья
- **THEN** watcher возвращает оба прежних локальных image ID и проверяет их здоровье без DB restore или изменения её mount; при первой активации удаляется только собственный новый private renderer без постоянных mounts.

#### Scenario: КП выключено
- **WHEN** feature flag КП выключен
- **THEN** watcher исполняет прежний web-only путь и не активирует профиль renderer.

#### Scenario: Checkout на другой ОС
- **WHEN** Git извлекает закреплённые ресурсы, manifests и исходные fixtures на Linux после Windows
- **THEN** EOL filters не меняют их raw bytes и контрольные суммы остаются прежними.
