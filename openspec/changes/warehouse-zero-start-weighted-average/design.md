# Design

## Context

Остатки сейчас — сумма INCOME+RETURN−EXPENSE, цена — Material.purchasePrice. В production 2119 импортных материалов, 1568 импортных движений, 1091 строка с issuedQty. История связана с расходами проектов, поэтому её нельзя переписать ради нулевого старта.

## Goals / Non-Goals

**Goals:** новый текущий баланс, точная средняя, безопасные транзакции и подтверждённое точечное восстановление.

**Non-Goals:** переоценка старых движений/проектов, изменение норм, issuedQty, валют, прав, restic и производство фикстур на production.

## Decisions

- WarehouseAccountingState — единственная операторская запись: runId, фаза FROZEN/VERIFYING/ACTIVE/RESTORED, SHA архивов и proof, исходные цены. Отсутствие записи не активирует новый учёт. VERIFYING уже показывает новые позиции, но пишет только оператор; ACTIVE открывает записи.
- WarehouseBalance — текущие quantity Decimal(12,3), valueByn Decimal(30,9), revision по материалу. WarehouseMovementValuation — точный cost/value, связанное движение и источник возврата, уникальная квитанция запроса с fingerprint/actor. Только новые таблицы; старые денежные колонки не меняют тип.
- Арифметика BigInt в атомах: количество ×1000, стоимость ×10^9. Деление HALF_UP. Полная выдача снимает весь остаток стоимости; последний возврат возвращает оставшуюся точную и денежную стоимость исходной выдачи. Material.purchasePrice — кеш средней до 2 знаков, обновляется SQL только по этому столбцу, без updatedAt.
- Общая shared advisory-блокировка склада (18436,94001), затем идемпотентный запрос (18437,hashtext(UUID)), материал FOR UPDATE и изделие. Оператор — exclusive lock. При заморозке блокируются настройки, движения, потребности и пересчёт потребностей через количество изделия; прочие поля карточек работают. До инициализации метаданные/нормы доступны, движения закрыты.
- Серверные поля: clientMutationId обязателен, income unitPrice >0 (до 2 знаков), quantity >0 (до 3). Выдача не принимает ручную unitPrice. Возврат выбирает sourceMovementId нового учёта; при старом учёте явная unitPrice >0, в пределах выданного старого количества. Финансовые поля источников скрыты по действующим ролям.
- Запросы текущего количества используют WarehouseBalance, а до запуска — старую историю только для чтения. Цена/количество одного баланса читаются вместе; проектная экономика продолжает использовать неизменённые totalByn всех движений.
- Операторские команды freeze → backup → isolated restore/rehearsal → attach proof → zero → verify → activate. Команда проверяет архивные warehouse-строки и исходные снимки в той же транзакции/exclusive-блокировке, что zero. zero сравнивает защищённые данные в одном MVCC-снимке; Material сравнивается без purchasePrice. Ошибка — rollback. restore запрещён при новых valuation; никаких DELETE старых строк/полного restore рабочей БД.
- Аудит и outbox события создаются в транзакции движения/баланса/цены/квитанции. Доставка и уведомление — после commit. Ошибка outbox откатывает всю операцию; ошибка доставки сохраняет событие в очереди и не сообщает об ошибке уже сохранённого движения. Округлённые частичные возвраты ограничены остатком денежного снимка, чтобы копейки не превысили исходную выдачу.
- Два защищённых production-архива остаются до приёмки владельцем. Копия содержит полный контекст FK. Репетиция в PG17 без сети: настоящее восстановление, сброс, точечное восстановление, сравнение строк/схемы/связей. На local/staging только существующая БД и контролируемый rollback, без дампов.

## Risks / Trade-offs

Округление цен → точная стоимость сохраняется в новом снимке, сумма финансового движения округляется отдельно до копеек. Старые поля и расходы неизменны.

Новые операции между backup и reset → складской gate и проверка архивного состояния. После новых записей слепое восстановление запрещено; диагностическая команда выдаёт объём нужной выборочной коррекции.

## Migration Plan

Добавочная миграция, локальная проверка, разрешённый коммит, обычный merge и фактическая staging-приёмка. Main 93+94 — по отдельному прямому указанию. Затем guarded production-процедура, без фикстур; архивация/удаление точных временных копий после приёмки.
