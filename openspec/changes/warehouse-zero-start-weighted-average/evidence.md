## Реализованный результат

- Добавочная миграция `20261007170000_warehouse_weighted_average` создаёт только служебную схему и операторские функции; сама не обнуляет данные.
- Текущий склад после подтверждённого запуска использует отдельные количество и точную стоимость. Средняя цена читается из одного баланса, отображается с двумя знаками. Номенклатура, выдача, варианты материалов и нехватка используют общий учёт.
- Приход требует положительные количество/цену; цена материала и выдачи недоступны для ручной правки. Новый возврат выбирает исходную выдачу; старый требует положительную фактическую оценку. Денежные поля серверных DTO сохраняют действующие права.
- Движение, точный снимок/квитанция, баланс, кеш цены, issuedQty, аудит и outbox сохраняются в одной транзакции. Доставка события и уведомление выполняются после commit. Повтор не удваивает движение или аудит. Частичные возвраты сохраняют точный остаток стоимости и не возвращают лишние копейки.
- Заморозка блокирует складские движения, категории, номенклатуру, потребности и пересчёт материалов через количество изделия. Обычные правки карточек продолжают работать.
- Операторский сброс изменяет из существующих строк только `Material.purchasePrice`, без `updatedAt`. Старый журнал, расходы, нормы и выдачи сохраняются. Повторный запуск не стирает последующую инвентаризацию; восстановление после новых движений отклоняется.

## Готовность восстановления и оставшиеся обязательные этапы

Оператор: `deploy/warehouse94-operator.py`, SHA256 `41bb430d9149d1993ae19fab104be6640be639180f6adc94842313ea2389e802`. Процедура — `deploy/warehouse94-operator.README.md`.

Проверены отказы на чужом host, staging dump, SQL с неверным снимком, чтение symlink receipt; команды используют REPEATABLE READ и guards фактической ревизии/контейнеров/volume/bucket. Backup держит экспортированный согласованный снимок. Инструмент проверяет восстановленные строки, колонки, определения ограничений/FK, функций, триггеров и индексов, затем настоящее zero/targeted restore и совпадение исходных остатков/цен. Архивы остаются до приёмки владельцем.

**Production-бэкапы и восстановление из их архивов ещё не выполнялись.** Native SQL QA не считается доказательством пригодности production-архива. Перед production-миграцией обязателен первый архив с настоящим изолированным restore; после миграции/заморозки — отдельный свежий архив с восстановлением, пробным обнулением и настоящим точечным возвратом. Без успешного proof команда zero отказывает. Проверка восстановления проводится в изолированном PG17 без сети/портов/production volume.
