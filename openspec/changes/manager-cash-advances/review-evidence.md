## RED → GREEN

- Исходный тест нового денежного ядра дал `MODULE_NOT_FOUND` до реализации. Последующие assertion-level RED: 0,50 RUB ошибочно превращались в 0,65 RUB из-за промежуточного округления; невозможная/будущая дата курса принималась; событие содержало строку вместо числовой суммы; устаревшая ожидаемая валюта кассы принималась. Эти случаи исправлены и проверены.
- Root добавил проверку отрицательного остатка после валютного пересчёта: `(119,99−120)/4 = −0,0025 USD`. До исправления — `Missing expected rejection`, 11/12 PASS. Проверки денежных writers теперь используют Decimal без округления, представление округляется отдельно; после исправления 12/12 PASS. Отклонённая операция не создаёт выплату, receipt или событие.
- UI review: неопределённый результат обычной выплаты сохраняет весь исходный запрос, включая месяц и UUID; повтор не блокируется изменившимся клиентским пределом долга. Тесты 2/2 PASS. Массовая выплата явно показывает верхнюю границу в валюте зарплаты и остаток выбранной кассы; пустая касса блокируется, результат без выплат не показывается как успешная выдача. Тесты 3/3 PASS.

## Границы доказательств

Права, повтор после удаления, совместимость legacy, долг прошлых месяцев и сериализованные параллельные выдачи проверены DI-тестами. Новый focused DI-тест запускает реальные `createPaymentCore` EXPENSE, `issuePayoutCore` ADVANCE и `settleAll` через общий `createTaskTransaction` с `ReadCommitted` и advisory `(18435,55001)`; гонки 600+500 при доступных 1000 не дают отрицательного остатка. Вместе с настоящим ожиданием другого backend PID в PostgreSQL `pg_locks` это подтверждает защитный путь, но **не является native смешанной гонкой разных writers**. Защита смены валюты проверена отдельно. Staging positive USD/FINAL доказан; исторических Payout в локальном начальном наборе было ноль, поэтому legacy-строка остаётся DI/миграционной совместимостью, не живой старой выплатой.

Последний полный офлайн-прогон после QA cookie/fingerprint правок: web **448/448 PASS**, bot **9/9 PASS**; Python **64** (62 PASS, 2 POSIX-only skip на Windows), оба TypeScript checks PASS, ESLint 0 ошибок с одной прежней unused-import warning в `scripts/cleanup-uploads.ts`, OpenSpec strict PASS. Логи `Temp/pero-cash-frozen-offline-b5f66b0c6a1046908f0ebe5e42f9ed8a`. **Build runtime commit `3f6da0da082cc707370346c9c3a458ba24d1c189` прошёл ранее** (включая CI #57); после последующих QA-only helper/evidence изменений build повторно не запускали. Дополнительная полная ролевая матрица добавлена после реализации и прошла GREEN; prior RED для неё не заявляется.

Подготовлены отдельные local/staging QA runner, SQL adapter и native entrypoint с opt-in и аттестацией существующих целей. Native lock proof требует реально ожидающий PID в `pg_locks`, а не просто паузу таймера. Local и staging миграции, ограниченные native/UI-проверки и exact-ID cleanup выполнены на существующих целях. Main/production не затрагивались; откат stage на старый код после новых cash-linked Payout во время QA был запрещён, дальнейший выпуск — только совместимым исправлением вперёд.
