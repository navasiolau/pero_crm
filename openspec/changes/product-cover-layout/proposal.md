# Proposal

## Why

В карточке изделия важные сведения и техническое описание сейчас занимают отдельные полноширинные блоки, а изображение показывается ниже небольшим preview с видимыми подписью и именем файла. Для быстрого обзора нужна обложка, связанная с карточкой: фото должно читаться рядом с заголовком на широком экране и сразу после него на телефоне.

## What Changes

- Перестроить верх карточки изделия: когда cover назначен, на экранах от 1024 px он занимает около 40% справа от самой верхней строки заголовка, а заголовок, статус, общее редактирование, сведения и описание остаются в колонке около 60% слева; на меньших экранах заголовок идёт первым, затем cover и остальные поля/описание. Без cover информационный блок снова занимает всю ширину, без пустой колонки.
- Убрать видимую подпись «Эскиз», имя файла, «Открыть оригинал» и прочие cover-captions; поверх имеющегося изображения оставить только две небольшие icon-кнопки: полноэкранный просмотр и замена. Без cover авторизованное действие замены остаётся одной небольшой иконкой возле заголовка. Доступные aria-имена сохранить для assistive technology.
- Добавить полноэкранный режим FileViewer только для cover: original image целиком через `object-contain`, viewport-sized, без панели с именем файла; Esc и close возвращают в карточку. Существующий обычный режим FileViewer для других вложений не менять.
- Разрешить ENGINEER и management roles заменить cover только на видимом по существующей ACL изделии. Диалог предлагает уже прикреплённые изображения либо загрузку нового PHOTO через существующий upload endpoint; изменение только Product cover pointer, старые File остаются прикреплёнными.
- Канбан-карточки сохраняют текущее отношение image/info 2:1 и размеры; быстрые cover-preview используют защищённый оптимизированный image route, original открывается только в fullscreen.

## Capabilities

### New Capabilities
- `product-cover-layout`: адаптивное размещение cover в карточке изделия, полноэкранный просмотр и безопасная замена обложки.

### Modified Capabilities
Нет. Действующие права на просмотр изделия и файла сохраняются; новая возможность добавляется только в границах того же видимого изделия.

## Impact

Карточка изделия `/products/[id]`, общая image component и `FileViewer` с opt-in fullscreen-вариантом; минимальный sketch/cover DTO; picker для прикреплённых изображений и upload action contract `setProductCover(productId, fileId)`. Серверный контракт использует текущий File storage и `/api/files/upload`; миграция схемы и изменение ролевой модели не предполагаются. Kanban-карточки сохраняют поведение предыдущей feature.
