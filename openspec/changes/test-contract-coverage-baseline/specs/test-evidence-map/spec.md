# Spec Delta

## Purpose

Карта доказательств связывает действующие требования CRM с конкретными проверками и честно показывает выполненные проверки, отсутствующие сценарии и границы измеренного покрытия production-кода.

## ADDED Requirements

### Requirement: Проверяемая карта действующих контрактов

Карта SHALL для каждого критического денежного, ACL, файлового, timer и queue контракта указывать требование, production-модуль, точный тест или блок, уровень доказательства и дальнейший native/runtime/browser сценарий. Отсутствующая защита MUST быть явно связана с задачей исправления.

#### Scenario: Изолированная проверка с fake transaction
- **WHEN** контракт проверен реальным модулем с подставной сериализующей транзакцией
- **THEN** карта указывает DI, сохраняет полезные проверки и помечает PostgreSQL-конкурентность NOT_RUN, а не PASS

#### Scenario: Отсутствующая regression
- **WHEN** требуется ветвь отказа, повтора или конкуренции, которой текущий тест не выполняет
- **THEN** карта содержит явный gap и номер соответствующей согласованной задачи

### Requirement: Решения по тестам на уровне защищаемого блока

Карта SHALL хранить KEEP/REWRITE/CONSOLIDATE/RETIRE с причиной и сохраняемой защитой. Смешанный suite MUST классифицироваться по блокам; guard, legacy-история и настоящий Chromium компонент не теряют защиту из-за имени файла или регулярного выражения.

#### Scenario: Смешанный suite
- **WHEN** один файл проверяет действующий fallback и устаревший UI helper
- **THEN** карта сохраняет fallback и отдельно указывает кандидата удаления или замены устаревшего блока

### Requirement: Воспроизводимый baseline покрытия

Coverage инструмент SHALL запускать существующий автоматический тестовый набор и публиковать реально измеренные метрики целевых production-модулей вместе с ревизией, хешами входов, командой, версией runtime и результатом запуска. Helpers, tests и vendor MUST быть исключены из знаменателя. Ненагруженный целевой модуль MUST явно присутствовать как NOT_RUN; произвольный глобальный порог не задаётся.

#### Scenario: Завершённый локальный прогон
- **WHEN** тестовый прогон и измерение успешно завершены
- **THEN** отчёт содержит измеренные данные, точный SHA/исходные хеши и статус PASS только для выполненного Node набора; browser/native/staging не получают этот статус автоматически

#### Scenario: Прогон прерван или не содержит корректного coverage
- **WHEN** тесты падают, reporter не закончил работу или покрытие недоступно
- **THEN** отчёт сохраняет FAIL/BLOCKED с причиной и не подставляет выдуманный процент

### Requirement: Явные границы evidence

Каждая заявленная выполненная проверка SHALL быть связана с SHA, target и сценарием. NOT_RUN/BLOCKED MUST сохраняться для отсутствующих, устаревших и неподходящих доказательств; Node coverage не доказывает работу SQL, canvas, Chromium bundle или проблемного iMac.

#### Scenario: Проверка устройства недоступна
- **WHEN** baseline собран на локальном ПК, а iMac недоступен
- **THEN** измерение iMac остаётся BLOCKED независимо от зелёных локальных тестов
