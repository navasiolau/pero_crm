# Design

## Context

Сессии бота и Mini App сопоставляют Telegram с записью `TelegramLink`. Финансовые формы Mini App уже обслуживает CRM, а команды чата через REST обращаются к существующим операциям. Внешний staging Caddy требует Basic Auth на текущем адресе CRM.

## Decisions

- В CRM использовать общий запрос действующей привязки для сессий обоих каналов. Возвращать боту права проектов, финансов и склада из действующих наборов ролей CRM и единый текст отказа.
- Гейт сообщений и callback бота проходит до ответа. Одноразовый код из профиля CRM проверяется существующей операцией привязки. Ошибки до проверки доступа остаются в журнале сервиса.
- Mini App отправляет подписанные данные запуска в существующий API обмена. Он выдаёт текущую cookie сессии либо возвращает понятный отказ. Удалить обработку логина и пароля и сохранить существующие записи привязки и схему БД.
- На `telegram-staging.peromebel.by` Caddy направляет маршруты Mini App к staging CRM и помечает приватные запросы. CRM допускает на этом входе только Telegram-сессию. Основной адрес staging использует Basic Auth. Маршруты загрузки и скачивания файлов проходят тот же гейт.

## Risks / Trade-offs

Ответ о правах добавляется к протоколу сервисного клиента. Обновлённый бот с прежним API закрывает доступ до получения прав из CRM. При выпуске сначала обновляется CRM, затем бот. DNS, TLS и настройки адреса применяются на staging при выпуске.
