# Spec Delta

## Purpose

Переносить существующие КП, изображения и договоры в CRM, сохраняя исходные факты и байты без изменения действующих заказов и исходного R2. По уточнению 26.10.2026 все КП используют общие правила; отдельного архивного режима нет.

## ADDED Requirements

### Requirement: Источник читается и фиксируется без изменения

Importer SHALL выполнять только чтение источника и сохранять hash каждого исходного JSON/объекта и общего manifest. Неизвестные поля SHALL сохраняться; source createdAt MUST не заменяться временем импорта.

#### Scenario: В источнике нет отдельной даты создания
- **WHEN** исходный документ содержит только ID с timestamp и updatedAt
- **THEN** дата создания берётся из исходного ID с confidence IDderived, а другие неизвестные даты явно отмечаются unknown

### Requirement: Перенос и нормализация не изменяют бизнес-сущности

Importer SHALL сохранять КП и историю импорта без создания или изменения проектов, изделий и клиентов CRM. Все записи партии SHALL становиться видимыми в одной финальной транзакции после проверки байтов и связей. Нормализация SHALL связывать перенесённые КП с проверенными существующими проектами, не вызывая коммерческую синхронизацию, изменение этапов или генерацию файлов.

#### Scenario: Сбой посередине загрузки
- **WHEN** часть объектов загружена, но импорт не завершён
- **THEN** незавершённая партия остаётся скрытой, бизнес-данные сохраняются, а повтор продолжает по точному ledger без дублей

### Requirement: Нет отдельного архивного режима

Система SHALL NOT вводить архивный фильтр, метку или отдельную архивную блокировку КП. Открытие текущего КП SHALL не сохранять его и не синхронизировать CRM. Явное сохранение/восстановление SHALL использовать обычную серверную проверку этапа «Лид»; отсутствие проекта SHALL оставаться ошибкой привязки, а не архивным режимом.

#### Scenario: Перенесённое КП связано с вручную изменённым проектом
- **WHEN** оператор нормализует КП либо пользователь только открывает его
- **THEN** изменяются только разрешённые связи самого КП, а поля Project/Product/Client и финансовые факты не переписываются

#### Scenario: Связанный проект находится вне Лида
- **WHEN** пользователь пытается сохранить изменения нормализованного КП
- **THEN** интерфейс, API и MCP запрещают сохранение по обычным правилам этапа, сохраняя чтение изображений и истории договоров

#### Scenario: Обычное сохранение после нормализации
- **WHEN** пользователь явно сохраняет изменения в Лиде
- **THEN** срабатывает существующая общая синхронизация, стабильные связи позиций сохраняются, а отсутствующий первоначальный курс выбирается по обычным правилам без обновления ранее фиксированного курса

#### Scenario: Сохранение и выпуск КП с импортированными изображениями
- **WHEN** пользователь сохраняет либо выпускает КП с проверенным импортированным изображением, ключ которого содержит SHA-256
- **THEN** обычная подготовка независимой копии для изделия принимает точный ключ этого КП и изображения с совпадающим хэшем и MIME, сохраняя исходные байты, ссылки и оформление документа
- **AND** ключ другого КП, изображения либо несовпадающего хэша отклоняется

### Requirement: Повтор подтверждает тот же источник

Importer MUST проверять source/target hashes и связи при повторе и SHALL отклонять изменённый источник или чужие байты. Неопределённый ACK SHALL разрешаться фактическим readback.

#### Scenario: КП и настройки отредактированы после переноса
- **WHEN** ранее опубликованный manifest повторяется после разрешённого сохранения, перенумерации позиций или привязки к проекту
- **THEN** импорт подтверждает неизменяемую историю исходного переноса и не перезаписывает текущий КП, настройки, связи и разрешённо очищенные данные

#### Scenario: Источник изменён после review
- **WHEN** hash записи или объекта отличается от frozen manifest
- **THEN** импорт останавливается без перезаписи ранее опубликованного архива

#### Scenario: Изображение меняется после копирования
- **WHEN** target readback уже подтвердил копию, а исходные binary bytes изменились перед финальной публикацией
- **THEN** повторная проверка SHA/размера всех уникальных source objects блокирует публикацию; сетевые чтения выполняются вне SQL с обновлением active lease

### Requirement: История договоров сохраняется без вымышленных связей

Importer SHALL сохранять все обнаруженные DOCX в dry report, включая неподтверждённые связи. Применение MUST требовать reviewed mapping к исходному основному КП и SHALL явно отмечать неизвестные исторические настройки.

#### Scenario: DOCX не связан в исходном JSON
- **WHEN** exports UUID отсутствует в settings record
- **THEN** dry report сохраняет объект и evidence, а apply ждёт reviewed binding без автоматического угадывания существующего CRM-проекта

### Requirement: Применение ограничено проверенной целью

CLI SHALL по умолчанию выполнять dry-run; apply MUST требовать reviewed manifest и точную привязку local5433/staging либо отдельно reviewed production release proof с явным разрешением конкретной операции и повторными runtime/DB/storage guards. Переключение UI/API SHALL оставаться отдельным действием после приёмки.

#### Scenario: Не совпадает endpoint или цель БД
- **WHEN** фактическая цель отличается от manifest
- **THEN** до upload и публикации возвращается guard mismatch; source и существующие данные не изменяются

### Requirement: Восстановление missing images требует явного reviewed provenance

Importer SHALL принимать локальные замены только через совместно заданные recovery-map/root с review каждой строки, точной source binding, всеми исходными item/slot ссылками, SHA/size/MIME и происхождением LOCAL_FILE/PDF_DCT. Manifest и сохранённый IMPORT snapshot MUST сохранять это происхождение, исходный URL и отсутствие знания оригинальных R2-байтов. Runtime root и абсолютные локальные пути SHALL не попадать в manifest.

#### Scenario: Подтверждённый отсутствующий объект восстановлен из PDF
- **WHEN** настоящий source GET возвращает NoSuchKey либо NotFound с HTTP404, а reviewed map указывает точную локальную копию DCT stream и исходные позиции
- **THEN** importer проверяет bounded local bytes, MIME, SHA/size, PDF source/evidence hashes и сохраняет копию с provenance; отдельный original и успешный выпуск PDF не выдумываются

#### Scenario: Ошибка прав либо восстановленный key появился в R2
- **WHEN** source GET возвращает AccessDenied, NoSuchBucket, другую ошибку либо найденный объект для recovery key
- **THEN** importer прекращает перенос без fallback; найденный объект не заменяется локальной копией даже при равном SHA

#### Scenario: Локальная копия изменилась после загрузки
- **WHEN** до финальной публикации изменились recovery bytes или обнаружен выход через path/symlink/junction
- **THEN** повторное чтение останавливает публикацию; архив остаётся скрытым и бизнес-данные сохраняются
