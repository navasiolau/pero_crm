# Design

## Context

№193, feature/193 от staging3def4f0c. ProjectStage и ProductStatus используются также типизированной историей и денежными снимками; удаление enum разрушило бы совместимость. Нативный запуск поручен Root отдельно. Safety: D:/Projects/pero_infra/infra-recovery/SAFETY-RULES.md; СТОП при guard mismatch.

## Goals / Non-Goals

**Goals:** отделить действующие наборы от исторических подписей, закрыть новые переходы во всех входах и подготовить повторяемый перенос.

**Non-Goals:** SQL schema migration, удаление enum/причин/истории, переписывание frozen заданий КП, финансовое начисление, инфраструктурные операции, самостоятельный запуск утилиты или production.

## Decisions

1. STAGES/PRODUCT_STATUSES содержат только действующие значения; подписи и стили отдельно сохраняют старые значения для исторических карточек. PostgreSQL enum и KP parser не меняются.
2. Контракт проекта по-прежнему принимает старые enum для чтения exact receipt. После проверки прав и exact receipt сервер проверяет действительность нового toStage. Изделие проверяет действующий target до writes.
3. Нормализатор URL удаляет только известные retired значения, сохраняя действующие значения смешанного набора. Неизвестные значения по-прежнему не превращаются в расширенный фильтр.
4. Telegram показывает только действующие этапы и отклоняет старую callback-кнопку до новых операций. Исторические подписи остаются.
5. Утилита отделяет plan от apply, фиксирует exact данные/план hash и операцию, проверяет target и SHA; обязательный Root callback доказывает отсутствие старых writers живыми image/SHA/process proof. Штатные idle pool connections нового web/бота допускаются. Одна транзакция, snapshot/CAS, advisory lock и SHARE ROW EXCLUSIVE NOWAIT защищают от конкурентных новых записей. Обновляются текущие строки и добавляется история/аудит без штатных действий смены этапов. Возврат КП в LEAD использует только сброс acceptance и отмену ожидающей очистки, без restore файлов и новых jobs.

## Risks / Trade-offs

- [Старые receipts] → проверка retired target после exact replay, исторические schema не сужаются.
- [Начисление при служебном переносе] → прямой CAS текущих значений без status-core и stage hooks.
- [Работающий старый writer] → инструмент требует quiescence и строгую identity/revision проверку; любое несовпадение rollback.
- [Уже удалённые файлы] → перенос не восстанавливает их и не изменяет версии КП.

## Migration Plan

Root принимает новый staging SHA/образ, останавливает writers разрешённым порядком, проверяет план и отдельно запускает apply. Инструмент не меняет runtime/инфраструктуру. Схема, enum и предыдущие migration-файлы сохраняются. Изменения истории не откатываются автоматически; при ошибке транзакции весь перенос отменяется.
