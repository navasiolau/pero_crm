# Spec Delta

## Purpose

Восстановить чтение и обычные операции категорий склада посредством совпадения модели ORM с фактической исторической схемой, без новых функций и изменения складских данных.

## ADDED Requirements

### Requirement: Модель категории соответствует существующей таблице

Prisma Client SHALL не запрашивать/возвращать MaterialCategory.revision, которого нет в исторической таблице и которое не используется приложением. Существующие category id/name/comment/active/createdAt/updatedAt SHALL сохраняться без добавления новой CAS механики или SQL-изменений.

#### Scenario: Чтение категорий
- **WHEN** приложение вызывает обычный materialCategory.findMany/listCategories на существующей local/staging схеме
- **THEN** запрос успешен и не вызывает P2022 по revision

#### Scenario: Обычные операции
- **WHEN** разрешённый пользователь создаёт/читает/переключает категорию
- **THEN** обычные default returning scalar поля корректны без revision, активность и данные категорий работают по прежним правилам

### Requirement: Номенклатура открывается без падения

Страница warehouse/items SHALL открываться разрешённому пользователю без server-side exception digest967541885 и показывать существующий справочник. Доступ/фильтры/количества/цены и исходные записи SHALL оставаться неизменными.

#### Scenario: Переход со склада
- **WHEN** пользователь открывает Склад→Номенклатура на фактически развёрнутой исправленной ревизии
- **THEN** страница отвечает успешно, справочник доступен, server-side P2022 отсутствует
