# Proposal

## Why

Изображения КП должны храниться приватно в CRM и сохранять внешний вид исходного документа. Копии изображений изделий должны переживать очистку КП; сбой загрузки не должен оставлять неучтённые объекты.

## What Changes

- Приватные неизменяемые оригиналы и оптимизированные изображения с проверкой фактических байтов, размера и SHA-256.
- Канонические ссылки `kp-media:<id>` вместо внешних URL; проверка владельца КП и актуальных прав.
- Устойчивый двухфазный журнал загрузки/копирования через существующие ProposalJob и независимые File для изделий.
- Транзакционный hook сохранения КП, который заменяет только управляемые ссылки, сохраняя историю и ручные производственные файлы.

## Capabilities

### New Capabilities

- `kp-private-media`: приватные изображения, журнал загрузки и независимые копии изделий.

### Modified Capabilities

Нет.

## Impact

Серверный модуль `server/kp/media*`, аддитивная миграция после №180, File и центральный фильтр файлов. Транспорт подключается в №187, редактор — №184, выполнение очистки — №188; облачные хранилища и существующие данные в рамках №183 не изменяются.
