# Design

## Context

См. proposal.md. Postgres-фаза выполняет domain и finance файлы последовательно на одном принадлежащем CI стенде. Real-COMMIT тест обязан сохранять свои записи для независимого peer и повторов; `getEmployeeDues` считает долгом начисления за месяцы строго раньше текущего московского месяца.

## Goals / Non-Goals

**Goals:** сохранить проверки настоящего COMMIT и отделить созданное ими начисление от соседних сценариев массовой выплаты при смене календарного месяца.

**Non-Goals:** изменение бизнес-правил зарплаты, состава workflow или ослабление assertions. Новые зависимости, локальный стенд и production-фикстуры не нужны.

## Decisions

До включения mock Date взять текущую дату, вызвать `setUTCMonth(getUTCMonth() + 1, 11)` и `setUTCHours(12, 0, 0, 0)`. Заморозить только этот тест полученным временем. Явный день 11 исключает переполнение короткого февраля при запуске 31-го числа; UTC исключает зависимость от timezone runner. Следующий UTC-месяц не раньше текущего московского месяца, поэтому в ограниченной по времени CI-фазе это начисление не является прошлым долгом.

Сохраняются `tick(60_000)`, реальные записи и COMMIT, доказательства независимых соединений, повторов и rollback. Финансовые проверки по-прежнему требуют ровно одного получателя и исходных сумм; изменение ожидаемого `paidCount` недопустимо.

## Risks / Trade-offs

- Часы влияют на тестовые receipt/audit timestamps → проверить весь native job, включая первоначально упавшие три проверки; отдельного unit достаточно только для граничных календарных вычислений.
- Финансовые сценарии используют общую CI БД → не менять порядок файлов и не удалять чужие fixture-записи ради результата.

## Migration Plan

После согласования — один коммит 207, обычный merge в staging, неизменённый полный CI и проверка фактического SHA/healthy. Изменение runtime-кода приложения отсутствует; для staging достаточно подтвердить неизменность его исходников и read-only HTTP/API. Затем fast-forward принятого staging в main, полный CI main и read-only production-проверка пары образов, БД metadata и доступности. Прямые production DB-команды не выполняются.
