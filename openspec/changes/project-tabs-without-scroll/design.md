# Design

## Context

См. `proposal.md`. Страница проекта задаёт панели вкладок `overflow-x-auto`, а кнопкам — `shrink-0`. Общий компонент задаёт фиксированную высоту и непереносимый текст. Явных кнопок со стрелками в композиции нет: видимые стрелки принадлежат горизонтальному scrollbar браузера.

## Goals / Non-Goals

**Goals:** панель проекта не прокручивается горизонтально; все кнопки доступны, в том числе после добавления модулей. Обычный набор на широком экране занимает одну линию, на узком переносится внутри страницы.

**Non-Goals:** остальные панели вкладок и канбан, порядок вкладок, содержимое страниц, lazy loading журнала и ролевые правила не меняются.

## Decisions

- Добавить проектную обёртку списка вкладок в существующий `project-tabs.tsx`, чтобы одно место задавало адаптивный layout и использовалось как настоящей страницей, так и браузерной проверкой.
- Применить к проектной панели перенос, автоматическую высоту и кнопки с собственной высотой; длинные подписи модулей могут переносить текст. Не использовать обрезание содержимого через `overflow-hidden`: оно скрыло бы кнопки при недостатке ширины.
- Не менять общий `ui/tabs.tsx`: другим страницам текущий scroll-контракт может быть нужен.
- Сохранить DOM-порядок и Base UI семантику, чтобы `Журнал` оставался последним, а клавиатура переключала те же панели.

## Risks / Trade-offs

- На узком экране и при большом числе модулей панель становится выше → проверка 360/390/1024/1440 px подтверждает видимость всех кнопок и отсутствие горизонтального scroll.
- CSS общей вкладки задаёт высоту через горизонтальную группу → проектная обёртка явно переопределяет её и задаёт высоту самих кнопок; браузер проверяет геометрию, а не текст классов.

## Migration Plan

Изменение интерфейса без миграций БД. После локальных проверок root выполняет обычный merge, штатный CI и приёмку staging. При дефекте возврат осуществляется обычным исправляющим коммитом в ветке задачи.
