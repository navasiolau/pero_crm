# Design

## Context

У перенесённых позиций может быть пустой productId, а у КП — ещё не выбранный курс. Общая синхронизация сейчас скрывает такое изделие, а при аудите скрытия занимает идентификатор основного события КП.

## Decisions

- Под существующими блокировками определить соответствия до скрытия и перенумерации. Сопоставлять только ранее сохранённые активные позиции перенесённого КП по их прежней позиции, с активным изделием этого же проекта, свободным от любой связи. Уже установленные связи имеют приоритет.
- Передавать в аудит именованные параметры родительского события и пересчёта количества.
- Готовить выпуск явной командой редактора. При пустом курсе использовать существующее сохранение, НБРБ на дату предложения и проверку ревизии. Договор использует подтверждённые источники и снимок клиента. Повтор неопределённой операции разрешается по исходной команде.
- Браузерные сценарии используют только синтетические проекты staging. Изменения схемы не требуются.
