# Proposal

## Why

Текущий журнал загружает только 200 записей и ищет по обрезанным значениям на клиенте. Полную историю невозможно найти, а существующие записи не содержат общего формата названий и связей с проектом или изделием.

## What Changes

- Серверные поиск по подстроке, сортировка, точный счётчик и пагинация всей истории с периодом по Москве.
- Отдельные ADMIN-only чтения списка, полной карточки события и русских вариантов фильтров, включая исторических авторов и «Систему».
- Общие контексты global/project/product; проектная лента исключает события изделий.
- Достоверное обогащение старых записей и возобновляемый backfill только presentation/searchText без изменения исходного аудита.
- Совместимость прежнего listGlobalChangeLog до переключения интерфейса в №223.

## Capabilities

### New Capabilities

- `journal-server-search`: поиск полной безопасной истории, контекстное чтение и совместимое заполнение представления.

### Modified Capabilities

Нет.

## Impact

Задача №222, feature/222. Зависит от модели и миграции №221. Затрагивает server/changelog, server actions, скрипт backfill и поведенческие тесты. Не меняет business writers, права других разделов, исходные receipts или значения денег. UI выполняется отдельно в №223–224. Миграция и фактическая local/staging-приёмка координируются root.
