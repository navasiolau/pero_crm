# Proposal

## Why

Пользователь подтвердил штатный автодеплой: зелёные проверки ветки `staging` разрешают обновление staging, зелёные проверки `main` — production. По чтению live-состояния основным агентом 28.09.2026 оба watcher приостановлены, а старый алгоритм сравнения локального тега пропускает обновление, если новый образ скачан раньше запуска watcher.

## What Changes

- Добавить общий проверяемый watcher для строго определённых серверов CRM, который сравнивает скачанный образ с образом работающего `web`.
- До изменения `web` проверять hostname, каталог, итоговую compose-конфигурацию и принадлежность контейнеров; после изменения проверять здоровье и неизменность контейнера/томов БД.
- Сохранить внешний staging lock и защиту W07 от пересечения с восстановлением/refresh.
- Включить тесты watcher в существующий CI gate и метку OCI с Git SHA в публикуемые образы.
- Описать управляемое восстановление cron отдельно от изменения исходников. Локальные fake-тесты не заменяют приёмку на сервере.

## Capabilities

### New Capabilities

- `crm-autodeploy`: публикация образов после тестов и безопасное автоматическое обновление `web` нужной среды.

### Modified Capabilities

Нет существующих спецификаций.

## Impact

`deploy/watch-crm.py`, тесты Python stdlib, `.github/workflows/ci-cd.yml`, `deploy/README.md`; публичные API CRM, схема БД и данные не меняются. Применение на серверах и live-проверка выполняются основным агентом после локального ревью, staging проверяется до production.
