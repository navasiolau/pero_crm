# Design

## Context

См. proposal.md. Сейчас app.js пишет снимки каждой редакции и дополнительные backup-ключи, transport сохраняет отдельные save-recovery копии. Сохранение и PDF проходят через этот механизм. Базовый staging: 5be2194d.

## Goals / Non-Goals

**Goals:** единое правило выбора целого снимка; один ограниченный локальный жизненный цикл; сохранность последующих правок и неизвестных операций.

**Non-Goals:** совместное редактирование полей, история локальных версий, изменения печатного шаблона, модели БД или CI.

## Decisions

- Нативный IndexedDB-адаптер хранит запись пользователя/КП, черновик и необходимые операции. Транзакции сравнивают маркер правки/операции перед заменой или удалением; память сохраняет работу при ошибке диска. Синхронный cache transport загружается до использования; записи ожидают commit перед завершением миграции.
- Метка editedAt создаётся только при изменении canonical содержимого, включая fx/client и загруженные фото. Session API отдаёт X-KP-Server-Time; transport калибрует монотонные часы по ответу. Сервер выигрывает равенство, локальный вариант без времени допустим только на своей базовой редакции.
- Открытие/возврат/сохранение/PDF используют один resolver. Он учитывает causal продолжение собственного сохранения, чтобы поздний ACK не заменял последующий ввод. Серверный выбор снимает старый черновик условно, без создания backup.
- При 409 сохраняется проверка operation receipt, затем выбор по актуальности и не более одного повторного save. Неизвестный исход не освобождает UUID/body. API v1 и схема документа не меняются.
- Миграция выполняется один раз для текущего actor/document: известные старые ключи импортируются транзакционно, исходные значения удаляются только при совпадении с прочитанными. Чужие данные и неизвестные форматы не очищаются.

## Risks / Trade-offs

- Выбор целого снимка может отбросить более старые независимые правки: это явно выбранная владельцем политика.
- Ошибка IndexedDB: статус в редакторе, память и серверный путь продолжают работать; успешное сохранение на сервере подтверждается штатным ACK.
- Старые вкладки могут ещё исполнять прежний JS: миграция имеет durable marker и не переимпортирует уже разрешённые копии.

## Migration Plan

Без БД-миграции и дампов. Локальные regression/browser проверки, штатный полный CI, фактическая staging-приёмка и небольшой PDF. Коммит и выпуск main требуют указания владельца согласно AGENTS.md. При rollback приложения не восстанавливать БД; новый локальный IndexedDB не удалять.
