# Proposal

## Why

Разрастающиеся локальные копии КП переполняют localStorage и блокируют загрузку сервера и PDF. Владелец согласовал автоматический показ целого актуального снимка без диалогов восстановления.

## What Changes

- Серверный снимок используется по умолчанию; действительно более свежий локальный черновик выбирается автоматически. Равенство разрешается в пользу сервера.
- Один черновик и необходимые незавершённые операции хранятся в IndexedDB; бесконечные резервные копии удаляются из жизненного цикла.
- Время правок привязано к серверу; технические сохранения его не обновляют.
- Старые локальные записи переносятся в пределах пользователя и КП с проверкой успешной транзакции.
- Требование ручного разрешения конфликтов из change `kp-editor-and-pdf` заменяется согласованным правилом выбора целого снимка. Неизвестный результат операции по-прежнему сохраняет UUID/body.

## Capabilities

### New Capabilities

- `kp-current-state-selection`: автоматический выбор актуального снимка, ограниченный жизненный цикл черновика и совместимость незавершённых операций.

### Modified Capabilities

Нет опубликованной основной спецификации редактора; изменяется поведение ранее реализованного change `kp-editor-and-pdf`.

## Impact

Редактор и transport пакета kp-template, session API header X-KP-Server-Time, браузерные и regression-проверки. Без новых зависимостей, миграций, дампов и изменений CI. Ветка bugfix/200 от staging 5be2194d.
