# Design

## Context

Штатные команды уже ведут журнал в транзакции. Часть каталогов включает и отключает записи, а клиент и контрагент сохраняют стабильный идентификатор.

## Decisions

- Общий закрытый обработчик синхронно проверяет и меняет только перечисленные в команде поля. У каждого поля есть токен происхождения. Обычное изменение присваивает новый токен, подтверждённая отмена возвращает предшествующий. Независимые поля сохраняются.
- Команда создания архивирует запись под тем же ID. Клиенты и контрагенты получают отметку архива, остальные справочники используют штатную активность. Существующие зависимости блокируют архивирование создания.
- Назначение кассы по умолчанию имеет отдельную ревизию и проверку активности. При отключении кассы снятие назначения входит в корень той же операции.
- Изменение признака контактного лица и автозаполнение связанных проектов отменяются вместе. Для каждого затронутого проекта проверяется исходный клиент и токен изменённого контактного поля.
- Существующие права, финансовые реквизиты и исходные ссылки документов остаются действующими.

## Migration Plan

Аддитивные поля архива и токенов. Существующие записи не переоцениваются. Журнал, записанный до добавления команд, остаётся доступным для чтения.
