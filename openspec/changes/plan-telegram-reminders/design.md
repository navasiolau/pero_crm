# Design
## Context
65 имеет confirmed CalendarReminderFact и безопасный test namespace. Bot token существует только в isolated bot; web не имеет его и не должен получать. Existing bot health loop30s подходит для отдельного bounded job.
## Goals / Non-Goals
Goals: exact personal recipient, once/dedup, durable unknown result и актуальный preflight.
Non-Goals: org/otherstaff рассылки, повтор UNKNOWN, новая service infrastructure, реальные credentials/env/Telegram при author проверках.
## Decisions
WEB65loop только queue eligible confirmedFact в уникальный outbox(namespace,factId), проверяя current entry/revision/PLANNED/offset/flag/link/preference. Изолированный bot имеет единичный job: authenticated claim с requestUUID → durable CLAIMED → authorize с повторным current/link guard переводит SENDING → plaintext send → exact ACK. Повтор authorize не даёт второй grant. SENDING expiry/network/malformed/lost ACK становится UNKNOWN без retry; CLAIМED expiry до grant можно вернуть READY. Явный Telegram429 ok:false даёт не более3 попыток с bounded retry_after;400/403 terminal failure. ACK idempotent; подтверждённый поздний positive ACK может разрешить UNKNOWN в SENT без новой отправки. Данные snapshot не переадресуются при unlink/relink; invalid claim отменяется. Test env требует matching65namespace +exact OWNER/CHAT mappings+actual approved bot getMe ID, production imports не выбираются. Конфигурация defaultOFF; до валидной activation нет queue query/claim/send. Telegram token остаётся только runtime существующего bot; безопасные closed codes не содержат raw Telegram exceptions.
## Risks / Trade-offs
Telegram не имеет идемпотентного send key → UNKNOWN сохраняется без автоматического retry, возможна недоставленная запись; нельзя обещать delivery по timeout. Cancellation после принятого preflight и начала send не может отозвать сообщение → до каждого send current grant проверяется заново, после фиксируется фактический outcome. Actual testbot/chat сейчас не принят → mock/native proof не заменяет positive delivery.
## Migration Plan
Аддитивная outbox таблица/индексы без backfill чужих/imported фактов. Root native outer rollback проверяет queue/claim/refusal/UNKNOWN без внешнего send. Реальные namespace/testrecipient/bot configure и доставка принимаются Root отдельно.

## Runtime activation (Root only)
Обе стороны defaultOFF. Web требует принятого65context и CALENDAR_TELEGRAM_ENABLED=true, CALENDAR_TELEGRAM_SERVICE_TOKEN_ID — точный ID авторизованного bot CRM ключа, а не его plaintext token. Production: CALENDAR_TELEGRAM_BOT_ID; test: CALENDAR_TELEGRAM_TEST_BOT_ID и CALENDAR_TELEGRAM_TEST_RECIPIENTS JSON [{ownerId,chatId}], subset approved65owners. Bot получает тот же environment/namespace/mapping и сверяет реальный getMe.id до claim. Bot CRM base соответствует окружению; token остаётся в его прежнем runtime config. Web token не добавляется. Admin calendar.reminders ключ с другим ID получает403 до calendar query. В этой задаче настоящие env/token/getMe/send не использовались. Недостающий accepted testchat и unhealthy existingstagebot остаются отдельной фактической приёмкой Root; native/Unit не выдают SENT за реальную Telegram доставку.
