# Design

## Context

CRM фиксирует выбранные КП и сводку в задании выпуска. Рендерер подставляет параметры в штатный DOCX и добавляет страницы КП, проект и акт приёмки. История отдаёт сохранённые байты договора.

## Goals / Non-Goals

**Goals:** один файл и штатное действие выпуска, источники пределов в приложении, воспроизводимый выпуск из сохранённых КП.

**Non-Goals:** расчёт прочности мебели, новые поля или формы, загрузка документов поставщиков при выпуске, изменения порядка подписания эскиза.

## Decisions

- Для физлица общий расчёт выдаёт номер приложения после акта. Серверный расчёт прикладывает набор строк инструкции из КП, уже замороженных постановкой задания. Файл и данные приложения сохраняются в существующей версии договора.
- Для актуальных КП берутся допустимые разделы структурированной спецификации. Для старых КП используется их сохранённая проекция. Материалы и модели сопоставляются по обозначениям из опубликованных источников. Неоднозначная замена и неполный артикул не дают числовой предел.
- Справочник входит в идентификатор шаблона. В строке параметра указываются изделие по номеру КП и позиции, модель, единица или объект нагрузки, условия и ссылка. Рендер использует стили и разметку исходного договора, переход на новую страницу начинается после акта.
- Сроки гарантии остаются из настроек договора. Основание отказа оценивается для конкретного недостатка по применимому закону. Страна продавца сама по себе не определяет, где оформлен заказ, поэтому требование к эскизу сформулировано для заказов на изготовление в РБ.

## Risks / Trade-offs

- Класс фурнитуры можно принять за нагрузку готовой полки → в справочнике выводится область применимости самого производителя.
- Изменение источников может затронуть ожидающие задания → используется имеющаяся проверка версии и отпечатка шаблона, уже выпущенные байты не пересобираются.

## Migration Plan

Изменение шаблона и рендерера выпускается вместе. Миграция БД не требуется.
