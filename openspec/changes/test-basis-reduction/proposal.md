# Proposal

## Why

Задача №168: сократить перекрывающиеся тесты, helpers и QA без потери уникальных контрактов. В принятом staging `da5bf32c` тестовый инструментарий вырос до 64 775 текстовых строк / 683 файлов / 365 автоматических suites; пользователь согласовал сокращение, коммит и staging-приёмку.

## What Changes

- Удалить доказанные дубликаты проверок и выведенные из текущей эксплуатации QA-копии; для каждого удаления указать сохраняемую проверку в `reduction-map.md`.
- Удалять осиротевшие helpers только после проверки всех ссылок и ручных операторских entrypoints; исправить затронутые ссылки в существующей контрактной карте.
- Показать чистое уменьшение строк, файлов и suites, пройти локальные проверки и приёмку реально развёрнутого staging.

## Capabilities

### New Capabilities

Нет. Только сокращение тестового инструментария; `skip_specs: true`.

### Modified Capabilities

Нет. Поведение приложения и уникальные требования сохраняются.

## Impact

Allowlist реализации — только согласованные файлы тестов, helpers, QA и их существующие ссылки; окончательный список записан в `reduction-map.md` до удаления. Новые артефакты — только этот change; прежний cash QA-plan получает лишь актуальную отметку retirement. Runtime `src`, Prisma, зависимости и lockfile неизменны. Деньги, ACL, CAS, idempotency, rollback, S3, native guards и Chromium остаются покрыты существующими проверками. БД, данные, инфраструктура, main и production в задачу не входят.
