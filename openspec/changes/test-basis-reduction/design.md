# Design

## Context

См. `proposal.md`. Web запускает `tsx --test tests/*.test.ts tests/*.test.mjs`; существующая `docs/testing/contract-matrix.json` привязывает критические контракты к файлам и test blocks. В QA есть ручные entrypoints, для которых отсутствие импортов не доказывает неиспользование.

## Goals / Non-Goals

**Goals:** не менее 50% чистого сокращения строк в прежнем tracked-text scope: web 64 722 → не более 32 361, совокупно 69 662 → не более 34 831; проверяемая замена каждой удалённой проверки и сохранение работающей команды тестов. Числа файлов/suites отражают итоговую структуру, но не служат заменой сохранности контрактов.

**Non-Goals:** новая система метрик, новые тесты ради удаления, minify, изменение runtime, зависимостей, бизнес-данных или исторических evidence.

## Decisions

1. В `reduction-map.md` фиксируется точный allowlist: удаляемый файл/блок → сохраняемый файл/блок и уровень доказательства либо завершённый исторический workflow. Уточнённая владельцем цель 50% обязательна; совпадение имени, одинаковый setup или сама квота не оправдывают потерю уникального контракта.
2. При пересечении source-string и исполняемой проверки сохраняется проверка поведения; уникальные route/ACL/денежные и native/browser условия остаются. QA-копия удаляется при действующем каноническом entrypoint либо явно закрытом одноразовом workflow завершённого выпуска. Retirement старого CLI не объявляется выполнением его прежних native/browser сценариев на новом SHA.
3. Удаления выполняются по буквальным путям после проверки абсолютной границы checkout и reparse points всех предков. Общие helpers удаляются только вместе с последним подтверждённым потребителем.
4. Обновляются только существующие живые ссылки и контрактная карта. Исторические OpenSpec receipts не переписываются. Новый checker/framework не добавляется.
5. Повторяемые native lifecycle/guards допускается объединять через существующие доменные helpers, сохраняя exact target binding, ownership/CAS, rollback и проверку baseline, drain/close clients и money/S3 условия. Исполняемые автоматические проверки сохраняют свой уровень доказательства: native `NOT_RUN` не заменяет выполненный test block.

## Risks / Trade-offs

[Потеря уникального условия] → сопоставление до удаления и независимое review; money/ACL/CAS/idempotency/rollback/S3/native guards сохраняются.

[Ручной QA нужен оператору] → явная действующая замена в карте; только отсутствие импортов не считается основанием.

[Метрики вводят в заблуждение] → одинаковый tracked-text scope до/после и отдельно число suites; уменьшение не достигается форматированием.

## Migration Plan

Миграций нет. Первая фаза завершена и принята на `e986e290`; её команды и receipts остаются в `verification.md` как отдельный факт. Продолжение после уточнения цели требует нового allowlist и консолидации, проверки live refs и уникальных контрактов. После завершения параллельных edits оркестратор один раз выполняет полный автоматический прогон, typecheck/lint, OpenSpec validation и `coverage-baseline.mjs --check`. Зафиксировать счётчики и отсутствие runtime diff; после review выполнить обычный merge в staging, CI, проверку нового SHA/образа/здоровья и GET-only smoke.

## Next Architecture Option — USER_APPROVED_FOR_169

Возможный следующий этап для цели 50%: один управляемый integration environment с ephemeral CI PostgreSQL, S3 и web, без реальных данных, с exact target guards, обязательным lifetime и автоматическим завершением собственных ресурсов. В нём общие domain cases могут заменить повторяемый DI/native/manual setup при сохранении уровня и условий каждого доказательства; существующие UI checks, migration/ownership guards и core edge inventory сохраняются.
До удаления действующих проверок обязательны полная case-map и фактическая coverage/acceptance всех сохранённых условий. Размер экономии пока не доказан; 50% этим вариантом не обещаны.
