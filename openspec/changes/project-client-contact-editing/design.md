# Design

## Context

ProjectInlineContacts выводит readonly строки. Действующий patch поддерживает client.phone, но provider его исключает; address сейчас относится к Project.address. Клиентский CRUD уже использует блокировку Client и сравнение baseline.

## Goals / Non-Goals

**Goals:** активировать существующие inline поля и добавить отдельный client.address; сохранить транзакционные writers и безопасную последовательность контакты → смена клиента.

**Non-Goals:** новые редакторы, синхронизация через websocket, запись контактов из изделия, миграция старых адресов.

## Decisions

- Добавить client.address с nullable value/expectedValue и обязательным expectedClientId. Старый address сохраняет смысл Project.address; альтернативная смена его назначения сломала бы прежних callers.
- Общая операция Client для phone/address нормализует только переданное поле, проверяет baseline под блокировкой, пишет аудит/outbox. Порядок блокировок Project → Client сохраняется.
- Выделить координатор существующих inline controllers: контакты привязаны к подтверждённому clientId; сохранение выбора ждёт их flush; при успехе создаётся группа нового клиента. Это позволяет проверить медленные ответы без копирования бизнес-логики в UI.
- При внешней смене связи контактный черновик сохраняется, автоматический перенос ввода другому клиенту запрещён. Для конфликта одного поля доступны существующие принять/повторить; конфликт связи требует открытия актуального контекста.
- Provider включает новые контакты в flush перед статусом и загрузками; актуальные server renders обновляют только чистые поля. Изменение контакта не запускает refresh всей карточки или чтение экономики.

## Risks / Trade-offs

- Поздний ответ контакта → controller закреплён за исходным клиентом; смена ждёт завершения запросов.
- Контакты в старом списке выбора → для полей используются подтверждённые controller baselines, новый клиент берётся из серверной проекции.
- Нет мгновенной межвкладочной рассылки → другие карточки получают общие значения при следующем обычном чтении; конкурентная запись защищена baseline.

## Migration Plan

Миграции БД нет. Локальные проверки и отдельный обычный merge в staging; приёмка actual SHA/образа и реальных полей. При необходимости возврат образа не требует отката данных клиента. Main не разрешён.
