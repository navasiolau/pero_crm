# Spec Delta

## Purpose

Файловые формы и рабочие списки используют имена файлов без отдельных подписей, сохраняя прежние данные и доступ к вложениям.

## ADDED Requirements

### Requirement: Подписи отсутствуют в файловых интерфейсах

Система SHALL исключить ввод, отображение и отправку File.caption во всех файловых формах/карточках проекта, изделия, задач и коммуникаций. Имя файла SHALL оставаться подписью ссылки, названием и alt-текстом изображения. Описания задач/изделий и HTML table captions MUST оставаться без изменений.

#### Scenario: Исторический файл с подписью
- **WHEN** файл с прежним File.caption открывается в рабочем списке или галерее
- **THEN** отображается fileName, caption не используется и исходная строка БД не изменяется

#### Scenario: Загрузка из любого интерфейса
- **WHEN** пользователь загружает файл через обычный uploader или фото/эскиз диалог
- **THEN** отсутствует поле подписи и caption не отправляется

### Requirement: Новые подписи закрыты сервером

Upload API SHALL отклонять любое присутствующее multipart caption, в том числе пустую строку, с validation error до чтения bytes и любых storage/DB writes. Обычные caption-free загрузки SHALL сохранять действующие ACL/MIME/stages/ID/key проверки. Историческое поле File.caption MUST сохраняться без миграции и переписывания истории.

#### Scenario: Устаревшая форма
- **WHEN** старый клиент присылает caption со строкой или пустым значением
- **THEN** операция отклонена без bytes/storage/DB writes

#### Scenario: Совместимость прежних данных
- **WHEN** caption-free загрузка проходит штатные проверки
- **THEN** новый файл сохраняется без caption, остальные прежние файловые строки и история неизменны
