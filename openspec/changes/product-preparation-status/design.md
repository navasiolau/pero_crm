# Design

## Context

Product.status и первая история используют DESIGN. Общий product-statuses обслуживает все UI и фильтры. Производственные grants используют status not DESIGN; процентные завершения уже выбирают явные последующие статусы.

## Goals / Non-Goals

**Goals:** PREPARATION как новый дефолт с безопасными grants и общей визуализацией.

**Non-Goals:** автоматическое исправление старых изделий, новая финансовая логика, расширение инженерной очереди, изменение production.

## Decisions

- Добавить PREPARATION перед DESIGN в Prisma и общем списке, нейтральный slate стиль. Создание явно записывает PREPARATION вместе с первой историей.
- Общий POST_DESIGN_PRODUCT_STATUSES = PRODUCTION/STORAGE/INSTALLATION/DONE/RECLAMATION используется во всех производственных grants; проверка not DESIGN недопустима для нового начального статуса.
- Существующий ролевой policy разрешает любые менеджерские переходы и ограничивает чистого инженера DESIGN/PRODUCTION; для PREPARATION это уже нужное поведение. Финансовые триггеры сохраняют явные последующие статусы.
- Две миграции: сначала добавить enum value, затем после фиксации отдельной миграции изменить default. Это исключает использование ещё не зафиксированного значения PostgreSQL enum. Ни UPDATE старых Product, ни правка истории не нужны.

## Risks / Trade-offs

- Отрицательный grant открывает подготовку → единый явный набор и регрессии продукта/проекта/задач/файлов для всех исполнителей.
- Старый образ не понимает PREPARATION → до rollback проверить наличие новых изделий и выбрать совместимый образ; не превращать их автоматически в DESIGN.
- Ночной staging refresh возвращает production schema/data → сохранить действующий refresh/W07; приёмку фиксировать по фактической миграции и SHA, не менять расписание.

## Migration Plan

Применить только на существующей local БД 5433 и staging по штатному entrypoint, без дампов/reset/seed. Проверить старые статусы/финансовые факты и новое создание. Production отдельно разрешается владельцем; перед его миграцией нужен временный дамп с изолированным восстановлением, точным последующим удалением. Restic не используется.
