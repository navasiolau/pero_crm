# Design

## Context

Запросы карточки, списка изделий и состава проекта уже отбирают изделия по серверной политике видимости. После этого `maskProductionRead` повторно проверяет назначения и скрывает у части исполнителей как структурированный JSON, так и прежнее описание. Карточка уже умеет выводить технические строки обычным текстом и определяет право редактирования отдельно.

## Goals / Non-Goals

Связать просмотр характеристик с правом открыть изделие. Проверки статуса, удаления и черновика относятся к выборке самого изделия. Финансовые данные, доступ к файлам и выполнение работ регулируют отдельные политики.

## Decisions

- Исправить общую серверную проекцию, от которой зависят карточка и вложенные изделия проекта. Локальная правка компонента не поможет, когда из ответа уже удалены значения.
- Использовать существующие правила отображения актуального JSON и прежнего текста, включая приоритет сохранённого пустого списка. Просмотр не требует сохранения преобразованных строк в БД.
- В карточке использовать существующий режим чтения. Серверное право изменить техническую строку проверять независимо от чтения по текущей роли, назначению и статусу изделия. Это сохраняет действующую модель совмещения ролей.

## Risks / Trade-offs

Проверка только на назначенном изделии пропустит исходную ошибку. Для приёмки нужны пользователи обеих производственных ролей без назначения и отдельная проверка отказа в записи на сервере. Маскирование цены и недоступность изделий чужого этапа проверяются как границы доступа.
