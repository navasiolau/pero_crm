# Решение

Убрать обработчики Auth.js и внутренний идентификатор, служившие записи событий сеанса. Существующий механизм проверки пользователя и выдачи сессии обслуживает вход как прежде.

На стороне чтения определить историческое событие по сочетанию сущности и кода действия. Применить определение при формировании запросов для списка, подробностей и вариантов фильтра. Использование исходных полей охватывает старые записи и записи с подготовленным представлением. Обычные изменения пользователя и операции над привязкой Telegram продолжают проходить через существующий аудит.

Проверку на staging выполнять с рабочим Журналом и контрольными запросами только для чтения. Миграция для этого изменения не требуется.
