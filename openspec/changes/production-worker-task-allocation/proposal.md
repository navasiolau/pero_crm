# Proposal

## Why

Работник уже видит производство и создаёт работу из прайса, но распределять её количество по задачам может только менеджер. Владелец разрешил работникам назначать и распределять работы и задачи, сохранив собственное исполнение и прежние ограничения оплаты.

## What Changes

- В живом изделии PRODUCTION работник распределяет свободное количество обычной работы себе или другому активному WORKER.
- Цена и объём работы не меняются; сумма выделений не превышает её объём, старые группы учитываются один раз.
- Повтор создания с тем же UUID не создаёт вторую задачу; task, audit, event и receipt записываются атомарно.
- Видна безопасная краткая информация о собственных назначениях другим работникам, без их зарплатного расчётника, времени или прав редактирования.
- Общие менеджерские действия, исполнение, зависимости и автоматический таймер сохраняются.
- Уточнение владельца03.10: Task — конкретное количество работы изделия с одним исполнителем и server-projected вознаграждением. Убрать generic/unassigned Task creation, видимые доли/проценты/split и «Без денежного начисления»; нулевая сохранённая цена даёт допустимые 0 BYN. Исторические payroll/snapshots не пересчитывать.

## Capabilities

### New Capabilities

- `production-worker-task-allocation`: узкое назначение количества обычной производственной работы активным работникам.

### Modified Capabilities

Нет.

## Impact

Отдельные worker core/action/query и небольшой диалог в разделе работ изделия. БД и денежные snapshots не мигрируются. Рабочая ветка `feature/69` от свежего staging; текущее уточнение выполняется на согласованной базе `175103a42ff8a6c85acd1dbbda0013c93145df40`; Git и интеграция — у координатора.
