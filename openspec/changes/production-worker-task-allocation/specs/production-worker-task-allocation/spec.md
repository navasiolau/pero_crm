# Spec Delta

## Purpose

Работники самостоятельно распределяют доступное количество обычной производственной работы между активными работниками с сохранением денежных и исполнительских ограничений.

## ADDED Requirements

### Requirement: Узкое распределение работы

CRM SHALL разрешать активному WORKER создать задачу на свободное количество обычной работы живого изделия PRODUCTION, назначив её себе или другому активному пользователю с WORKER. Система MUST заново проверять полномочия, статус, связь проекта/изделия/работы и получателя на сервере.

#### Scenario: Назначение другому работнику

- **WHEN** работник назначает часть обычной производственной работы активному WORKER
- **THEN** создаётся новая задача выбранного работника, а автор видит краткое подтверждение без чужого зарплатного расчётника, времени и права исполнения.

#### Scenario: Старое окно или чужой контекст

- **WHEN** изделие ушло из PRODUCTION, автор потерял WORKER, получатель неактивен или работа принадлежит другому изделию
- **THEN** операция отклоняется без создания задачи, начисления, события и audit.

### Requirement: Физический бюджет и история защищены

Система MUST не позволять превысить количество работы, MUST учитывать старую allocation group один раз и MUST не изменять цену, объём работы, старые задачи и snapshots. Новая задача SHALL использовать обычное количество без новых executorShare или долевых групп.

#### Scenario: Два назначения исчерпывают работу

- **WHEN** несколько назначений расходуют доступное количество
- **THEN** оставшийся объём пересчитывается на сервере атомарно; превышающее назначение отклоняется.

### Requirement: Повтор и исполнение

Одинаковая операция с тем же UUID SHALL создавать задачу, audit и event один раз. Иной payload с тем же UUID MUST отклоняться. Работник SHALL исполнять только свои задачи с существующими зависимостями, автоматическим таймером и обязательной оценкой времени.

#### Scenario: Ответ потерян после создания

- **WHEN** автор повторяет тот же запрос
- **THEN** получает прежний результат без второй задачи и повторного назначения.

#### Scenario: Задача назначена другому работнику

- **WHEN** автор назначения пытается исполнить чужую задачу
- **THEN** существующее правило собственного исполнения запрещает действие.

### Requirement: Конкретная задача без долевых controls
Task UI SHALL представлять одну конкретную работу изделия, её выделенное количество, одного исполнителя и server-projected вознаграждение. Создание SHALL начинаться с выбранной работы текущего изделия; generic проектная/безработная/безисполнительная задача MUST NOT создаваться через UI. Название новой задачи SHALL соответствовать работе, не служебному статусному placeholder. Доля/проценты/split controls и «Без денежного начисления» SHALL отсутствовать. Независимые quantity assignments SHALL сохраняться без child split; старые данные MUST NOT удаляться или пересчитываться.

#### Scenario: Менеджер назначает работу
- **WHEN** менеджер выбирает строку работы изделия со свободным количеством
- **THEN** продукт/работа/название фиксированы и ровно один исполнитель обязателен; из общепроектного списка generic создание недоступно

### Requirement: Server reward DTO без клиентской переоценки
Task money SHALL поступать из server rewardAmount/rewardCurrency/rewardSource согласно domain68; клиент MUST NOT вычислять оплату по цене/проценту или использовать legacy share fields как fallback. Known snapshot zero SHALL отображаться как сумма0BYN; missing projection SHALL отображаться как unavailable, не выдуманный zero. Frozen historical amounts SHALL сохраняться. Payroll rules70 не меняются.

#### Scenario: Нулевая сумма
- **WHEN** server DTO передаёт rewardAmount=0.00 и rewardCurrency=BYN для назначенной работы
- **THEN** Task отображает 0 BYN, даже если старые share fields содержат другую сумму; долевые controls отсутствуют

#### Scenario: Отсутствует monetary projection
- **WHEN** сумма скрыта или server DTO ещё не содержит подтверждённую сумму
- **THEN** UI не выводит цену из workTotal/quantity/share и не объявляет денежное начисление; отображается unavailable
