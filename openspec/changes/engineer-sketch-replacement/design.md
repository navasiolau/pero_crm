# Design

## Context

Текущий sketch-upload допускает только null baseline; пользователь сначала удаляет изображение. delete core корректно ограничивает удаление чужих файлов, поэтому инженер не может заменить эскиз менеджера. Уже существуют UUID receipts, content hash, транзакция, compensated S3 failure и проверка текущего actor. Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:** атомарная загрузка замены с прежним файлом как baseline, сохранение оригинального вложения и прежнего preview до ACK.

**Non-Goals:** расширение общей file-delete ACL, физическое удаление предыдущего эскиза, изменение цен, статусов, покрытий или общего макета изделия.

## Decisions

- Upload target принимает явный nullable исходный sketchFileId. Прежний null означает добавление в пустую область; существующий ID означает замену только этого pointer.
- Preflight проверяет текущий технический доступ, совпадение pointer и точную принадлежность прежнего изображения. Persist повторяет проверку внутри product row lock и обновляет pointer через CAS. Смена автора старого файла не является препятствием, поскольку старая запись не удаляется.
- Fingerprint включает baseline и байты; прежний receipt возвращается до проверки уже изменённого pointer. Повтор с иным payload не принимается.
- В заполненной области появляется «Заменить изображение»; загрузка использует прежнюю форму с захваченным baseline. Новое изображение отображается только после согласованного ACK. Существующий delete action остаётся отдельным действием с прежними правами.
- Не вводим отдельный upload endpoint: текущая ветка эскиза уже сохраняет оригинал, генерирует preview и управляет результатом записи и компенсацией.

## Risks / Trade-offs

- Устаревшая открытая форма → preflight и транзакционный CAS, код конфликта, сохранение текущего изображения.
- Потерянный ответ → immutable attempt с теми же bytes, baseline и UUID, проверка receipt и ACK.
- Старый файл остаётся виден среди вложений → намеренно сохраняем историю и возможность просмотра; общий delete grant не меняем.

## Migration Plan

Миграции не нужны. Проверки RED→GREEN контрактов, прав, повторов и сохранения старого файла; typecheck/lint. Координатор проверяет реальный S3 и replacement на окончательной staging ревизии после обычного merge.
