# Proposal

## Why

№157 утверждён в плане улучшений приложения и зависит от завершённой карты контрактов №159. Пакет `file-stages` уже отсутствует в runtime registry, но функциональная QA изделия читает его исходник как доказательство отсутствия hook. Это мешает удалить отключённый пакет и не проверяет действующий реестр.

## What Changes

- QA проверяет настоящий `getManifest` текущего приложения и revision: только известная историческая запись `file-stages` 0.1.0 / API 1 допустима при отсутствии активного manifest.
- Неизвестные enabled-плагины и любые зарегистрированные enabled-плагины останавливают подготовку до эффектов. Demo manifest и его hooks остаются настоящими.
- Source guards QA привязываются к действующим registry, demo manifest и SDK; подписанный PRE, защита от corruption и guards физической цели сохраняются.
- Удаляются три неиспользуемых TS-файла пакета и его package/importer metadata. Исторические строки Plugin, настройки, файлы и данные остаются прежними.

## Capabilities

### New Capabilities

Нет: вывод отключённого пакета и замена внутреннего QA-доказательства не вводят поведение приложения.

### Modified Capabilities

Нет: runtime hooks, права, файловый контракт и модель данных не меняются. Для этого изменения tooling указан `skip_specs: true`.

## Impact

`packages/plugins/file-stages`, importer в `pnpm-lock.yaml`, существующие `product-draft-stage-{runner,fixtures}` и их проверки. Registry/demo/SDK читаются и компилируются как доказательство, их production-код не редактируется. Не требуются DB, HTTP, миграции или новый QA framework. Удалённые физические строки учитываются отдельно от неизмеренной экономии JS.
