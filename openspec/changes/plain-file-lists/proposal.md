# Proposal

## Why

В списках файлов слишком много служебной информации и миниатюр. Владелец согласовал единый простой список: полное исходное имя с расширением, клик для просмотра изображения либо скачивания документа и небольшая урна с подтверждением.

## What Changes

- Все списки вложений проектов, изделий, разделов замера/производства/монтажа, задач, финансов, отчётных документов, каталога и выбранных загрузок используют один файловый ряд.
- Ряд отображает только имя и урну; миниатюры, иконки типа, метаданные, категории, комментарии и отдельная кнопка скачивания убираются.
- Изображения открываются в нынешнем полноэкранном просмотре оригинала; остальные файлы, включая PDF и видео, скачиваются через действующий защищённый маршрут.
- Небольшое подтверждение привязано к урне; отмена сохраняет файл, ошибка оставляет строку, ожидающий запрос защищён от дублирования и закрытия.
- Существующие серверные права удаления и ограничения связанных финансовых документов отражаются неактивной урной. Печать добавляется отдельной задачей 116.

## Capabilities

### New Capabilities

- `plain-file-lists`: единый файловый ряд, исходное имя, просмотр/скачивание, компактное подтверждение и сохранение прав.

### Modified Capabilities

Нет. Политики доступа и мобильные требования сохраняются.

## Impact

Новые общие FileList/FileListRow и FileDeletePopover, затем адаптеры существующих файловых экранов и их безопасных серверных проекций. Задача 115, feature/115; зависит от принятой задачи 113 с File.section. Новых библиотек просмотра, API произвольных URL и миграций нет. Phase A зафиксирована отдельно; по уточнению владельца Phase B реализуется после ordinary merge reviewed feature/113, а deploy/приёмка 115 разрешаются только после actual staging acceptance 113. Отдельный catalogue UI отсутствует и не создаётся.
