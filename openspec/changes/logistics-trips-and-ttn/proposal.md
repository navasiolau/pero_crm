# Proposal

**Execution agreement:** Номер задачи 123, ветка feature/123 согласованы владельцем 10.10.2026; OpenSpec и реализация одобрены. Одна целевая локальная проверка, затем существующий полный CI без изменений и развёртывание на staging только через него; одна целевая staging-приёмка. Повторные полные ручные проверки не выполнять без конкретного сбоя. Production/main этим запуском не разрешены.

## Why

Одна отгрузка может включать изделия или материалы нескольких проектов. Нужен единый рейс с общими ТТН, чтобы документы и состав перевозки не дублировались в проектах и бухгалтер мог получать накладные самостоятельно.

## What Changes

- Один рейс хранит состав отгрузки, связанные проекты и процент каждой проектной доли; общая сумма долей — 100%.
- Для изделий выбираются существующее изделие проекта и количество; для материалов — номенклатура, количество и единица. Запись состава сама по себе не проводит складских движений.
- ТТН прикрепляются к рейсу отдельными файлами без фиксированного ограничения их количества. Документ с одной печатью служит основанием для списания; документ со второй печатью можно добавить после возврата.
- Полные права получает существующая роль `PROCUREMENT`, а также `ADMIN` и `DIRECTOR`. `ACCOUNTANT` читает сведения, необходимые для получения ТТН, и скачивает файлы; изменение рейса и документов ему недоступно.
- Общие файлы проектов не раскрывают ТТН ролям без логистического доступа. Комбинированные роли сохраняют объединение разрешений.

## Capabilities

### New Capabilities

- `logistics-trips-and-ttn`: единая отгрузка нескольких проектов, состав, процентные доли, общий комплект ТТН и серверные права на него.

### Modified Capabilities

Нет. Действующие требования инженерной видимости, общего файлового раздела и остальных ролей сохраняются.

## Impact

Аддитивная Prisma/SQL-миграция для рейсов, проектных долей, строк отгрузки и логистических документов; новый домен `src/server/logistics/`, защищённые загрузка/чтение файлов и аудит. Используются существующие storage-примитивы и лимиты загрузки, но ТТН не становятся общедоступными файлами проекта. Роль снабженца уже реализована в исследованном `origin/staging` `ab1c77f3b82cab788f206914d5b2a063e6aafe68`; новая роль не создаётся.

Первый из трёх небольших changes. Далее — `logistics-cash-allocation`, затем `logistics-workspaces`. Номера задач согласовываются до создания рабочих веток; это предложение не разрешает коммиты или выпуск.
