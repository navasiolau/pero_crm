## ADDED Requirements

### Requirement: Исполнение без учёта времени

Система SHALL предоставлять «Взять в работу» и «Завершить» без оценки, фактических минут и записи TimeEntry. NEW → DONE SHALL оставаться разрешённым. Сервер SHALL сохранять права, зависимости, обязательные фото/замерный лист, сроки, назначения и количества; обычная сдельная оплата SHALL начисляться на DONE ровно один раз.

#### Scenario: Завершение новой задачи
- **WHEN** разрешённый исполнитель завершает NEW без минут при выполненных зависимостях и приложенных обязательных файлах
- **THEN** задача становится DONE и обычное начисление создаётся однократно без записи времени

#### Scenario: Обязательные условия
- **WHEN** есть незавершённая зависимость или отсутствуют обязательные фото/замерный лист
- **THEN** статус и начисления остаются прежними, сервер возвращает существующий отказ

### Requirement: Создание и интерфейс без трудозатрат

Система SHALL создавать новые задачи с estimateMinutes=null без требования оценки и AVG истории. UI SHALL не показывать таймеры, ручной ввод, оценку/факт и статистику минут. Query задач SHALL не агрегировать TimeEntry. Calendar.plannedMinutes SHALL сохраняться.

#### Scenario: Новая задача без истории
- **WHEN** менеджер или разрешённый производственный сотрудник создаёт задачу без оценки
- **THEN** создание доступно без истории TimeEntry, UI не предлагает поля времени

### Requirement: Старые команды и сохранённая история

Система SHALL отклонять новый time-write из старой вкладки без записи. Прежний успешно сохранённый UUID SHALL проверяться до retired-валидации и подтверждаться по исходному fingerprint без повторных статусов/денег. Исторические TimeEntry, оценки и финансовые факты SHALL сохраняться. Чтение /my SHALL не останавливать таймер и не писать время.

#### Scenario: Старый UUID с минутами
- **WHEN** повторяется сохранённая команда создания с оценкой или изменения статуса с actualMinutes
- **THEN** сервер подтверждает исходную квитанцию без изменения истории и повторных эффектов

#### Scenario: Новая команда из старой вкладки
- **WHEN** новый UUID содержит retired-поле или вызывается прежний start/stop/manual action
- **THEN** сервер отказывает без записи TimeEntry

### Requirement: Операторское закрытие открытой истории

Cutoff SHALL быть выключен по умолчанию, идемпотентен по UUID и разрешён только при точном local5433/staging target proof, новом SHA и доказанном отсутствии старых writers. Под общей task advisory lock и одним временем сервера он SHALL закрывать только source=timer/stoppedAt=null с прежней формулой min1/max720 и аудитом точных ID. Task status и payroll SHALL не меняться.

#### Scenario: Guard не подтверждён
- **WHEN** отсутствуют apply, точная DB-идентичность, новый SHA или подтверждение отсутствия старых writers
- **THEN** cutoff завершается без изменения данных

#### Scenario: Повтор cutoff
- **WHEN** оператор повторяет тот же подтверждённый UUID после успешного cutoff
- **THEN** возвращается исходная квитанция, остальные исторические строки, статусы и деньги остаются прежними
