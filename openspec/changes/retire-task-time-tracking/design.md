# Design

## Context

Существующая task transaction сериализует изменения и финансовые начисления. completion-core одновременно меняет статус и пишет TimeEntry; отдельные time actions и чтение /my также меняют время. Создание manager/worker задач требует оценки или использует AVG истории. Идемпотентные квитанции включают прежние minutes в fingerprint.

## Goals / Non-Goals

Цель — полностью прекратить новый task time tracking, сохранив обычный жизненный цикл, права, доказательства истории и однократную оплату. Исторические поля БД не удаляются и не пересчитываются. Calendar.plannedMinutes — длительность календарного события и остаётся. Миграции, cutover БД и деплой выполняет основной оператор отдельно.

## Decisions

- Переходы статуса сохраняют прежнюю wire-сигнатуру для старых вкладок и UUID. Сначала читается сохранённая квитанция; новый запрос с retired actualMinutes отклоняется, новый запрос без минут проходит. Финансовая ветка DONE, required attachments и зависимости остаются в одной транзакции.
- Оценка исключается из новых UI/команд. Сервер сохраняет прежние optional-поля только для точного восстановления старой квитанции, после проверки replay отклоняет новую оценку. Новые задачи получают estimateMinutes=null. Редактирование не переписывает историческую оценку.
- Time actions остаются как авторизованные tombstones без обращения к TimeEntry и записей. /my не вызывает getActiveTimer. Runtime helper создания/остановки таймеров удаляется; чистая timerStopSnapshot сохраняется для cutoff.
- Query DTO больше не содержит spentMinutes/estimateMinutes; batch TimeEntry.groupBy и runtime guards активного таймера удаляются. Исторические строки и финансовые охраны удаления сохраняются.
- Cutoff — чистый core и отдельный inert CLI entry без подключения. Apply принимает точный hash плана и обязательный port verifyTargetAndNoOldWriters от существующего reviewed Root transport: live local5433/paired staging, новый SHA/образ и отсутствие старых writers. Совпадение БД дополнительно проверяется внутри транзакции по name/schema/systemIdentifier. Guard mismatch завершает исполнение. Под task advisory lock и NOWAIT table lock берётся один server timestamp, закрываются исключительно source=timer/stoppedAt=null по timerStopSnapshot (1–720 минут), фиксируются точные ID и аудит. Повтор по прежнему operation UUID читает receipt без новых изменений. Статусы и зарплата не изменяются. Root отдельно предоставляет live proof и запускает операторскую стадию.

## Risks / Trade-offs

Старая вкладка может прислать новые минуты; сервер возвращает понятный отказ без записи. Прежний UUID должен вернуть прежний результат, включая payload с минутами/оценкой. Cutoff не принимает подтверждение-флаг: port Root обязан заново проверить живой состав процессов/образов и exact SHA/target при plan/apply и перед COMMIT. История таймеров сохраняется; выполнение cutoff не является миграцией схемы.

## Migration Plan

Подготовить код и доказательства локальных проверок; root принимает новый образ и отсутствие старых writers. Затем отдельным разрешённым этапом запускает cutoff на подтверждённых local/staging. До выполнения cutoff не утверждать закрытие старых таймеров. Schema migration отсутствует.
