# Spec Delta

## Purpose

Непустые ставки, правка до DONE с корректировками, живой перерасчёт.

## ADDED Requirements

### Requirement: Ставки никогда не пустые

`ProductPercentageConfig.ratePercent` SHALL NOT быть null для новых записей; существующие null SHALL мигрировать в 0. Формы настроек и карточки SHALL NOT принимать пустое (ошибка «Укажите процент (0 — без оплаты)»). Создание изделия SHALL подставлять 0 вместо отсутствующего дефолта. Явный 0 сохраняется как «0.00».

#### Scenario: Backfill

- **WHEN** применяется миграция при наличии конфигов со ставкой null
- **THEN** они становятся 0, ревизии не меняются, начислений миграция не создаёт

#### Scenario: Пустой ввод отклоняется

- **WHEN** менеджер стирает процент и пытается сохранить
- **THEN** сохранение блокируется ошибкой, в БД ничего не пишется

### Requirement: Правка процента открыта до DONE

Патч `ratePercent`/`assigneeId` менеджерскими ролями SHALL приниматься при любом статусе изделия кроме DONE; при DONE SHALL отклоняться ошибкой «Изделие завершено: изменение процентов закрыто».

### Requirement: Корректировка зарплаты после начисления

Изменение ставки при существующем SETTLED (статус не DONE) SHALL пересчитывать снимок завершения и создавать корректирующую `PayrollEntry` дельтой в текущем месяце с аудитом и уведомлением специалиста; при нулевой дельте — только снимок. Пропущенное начисление (SKIPPED_ONCE) с заданной позже положительной ставкой SHALL начисляться при следующей смене статуса, затрагивающей этап.

#### Scenario: Понижение ставки после начисления

- **WHEN** менеджер меняет 6% → 5% после SETTLED (не DONE)
- **THEN** снимок и доля обновлены, создана отрицательная дельта текущим месяцем, специалист уведомлён, ChangeLog содержит старое/новое

### Requirement: Мгновенный перерасчёт превью

Превью суммы SHALL считаться от валидного вводимого черновика (fallback — сохранённое при невалидном), без ожидания сохранения и перезагрузки.
