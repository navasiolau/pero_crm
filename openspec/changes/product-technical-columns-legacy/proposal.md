# Proposal

## Why

В едином поле #217 разделитель-двоеточие выглядит неаккуратно, а номер пустой строки воспринимается заполненным. Кроме того, изделия без JSON скрывают ранее введённое описание; владелец требует сохранить его отображение и автоматические обновления из генератора КП.

## What Changes

- Сохранить общую рамку поля, заменить двоеточие единой тонкой вертикальной линией между колонками названия и значения. Плейсхолдеры оставить, номер нетронутой строки сделать серым.
- Отображать существующий JSON без преобразований; при отсутствии JSON показывать прежние характеристики в той же форме без потери текста. Первая реальная правка сохраняет весь прежний список как JSON, исходный Product.description сохраняется дословно.
- Сохранить транзакции, права, CAS/receipt, очереди, поколения и revision. Явный JSON с пустым sections не возвращает старый текст.
- Изменение характеристик в генераторе КП по-прежнему автоматически сохраняет и обновляет JSON изделия; результат выводится в двух колонках. Проверить именно autosave редактора КП.

## Capabilities

### New Capabilities

- `product-technical-columns-legacy`: две колонки единого поля и совместимость ранее введённых характеристик. Уточняет внешний вид и переход старых данных change `inline-product-technical-field` по прямому указанию владельца.

### Modified Capabilities

Нет изменений основных specs.

## Impact

Общий UI поля/ручное создание, технический контроллер и его legacy baseline, чистый legacy resolver и серверная материализация JSON при первой правке, профильные проверки. Миграций и массового преобразования нет. Справочник КП, ограниченный перенос материалов, PDF и цены сохраняют текущие правила. Выпуск — staging, production не входит в поручение.
