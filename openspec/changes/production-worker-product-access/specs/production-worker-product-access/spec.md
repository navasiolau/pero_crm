## Purpose
Предоставлять активному работнику просмотр текущего производства без назначения задачи, сохраняя точные границы записи, файлов и финансовых данных.
## ADDED Requirements
### Requirement: Производственный просмотр
Система SHALL показывать WORKER все Product в PRODUCTION, их обычные карточки и родительский Project независимо от Task. Фильтры SHALL только сужать набор, прямой URL SHALL использовать ту же политику.
#### Scenario: Нет назначения
- **WHEN** активный WORKER открывает список или прямую карточку чужого PRODUCTION
- **THEN** изделие доступно для просмотра без создания Task
#### Scenario: Другие этапы
- **WHEN** WORKER открывает чужое DESIGN или DELIVERY без независимого grant
- **THEN** изделие недоступно
### Requirement: Независимые права
Система SHALL сохранять union ролей. Pure MOUNTER SHALL не получать общий производственный grant. Общий просмотр SHALL не давать technical/status edit, task execution, файловый доступ, upload или финансы сверх прежних разрешений.
#### Scenario: Совмещённый инженер
- **WHEN** ENGINEER+WORKER видит чужое PRODUCTION
- **THEN** техническое редактирование и изменение статуса запрещены
#### Scenario: Технический файл
- **WHEN** WORKER без прежнего назначения запрашивает технический файл нового видимого изделия
- **THEN** прямой файл и его metadata не выдаются, upload запрещён
#### Scenario: Монтажник
- **WHEN** pure MOUNTER без назначения открывает чужое PRODUCTION
- **THEN** общий просмотр не предоставляется; собственное назначение сохраняет прежние права
### Requirement: Отзыв доступа
Система SHALL использовать актуальный статус и действующий actor. Общий grant SHALL не обходить soft-delete parent/product фильтры после интеграции54.
#### Scenario: Изделие вышло из производства
- **WHEN** изделие без независимого назначения перешло из PRODUCTION в DELIVERY
- **THEN** повторный запрос WORKER больше не возвращает его
