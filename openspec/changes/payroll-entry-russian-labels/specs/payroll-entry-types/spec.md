# Spec Delta

## Purpose

Сотрудник понимает вид каждого начисления в своём расчётнике по русской подписи, без необходимости читать технические коды приложения.

## ADDED Requirements

### Requirement: Русские названия типов начислений

Таблица начислений «Моя зарплата» SHALL называть колонку «Тип» и отображать русские подписи типов начислений.

| Код | Подпись |
|---|---|
| `PRODUCT_PERCENT_ENGINEERING` | Процентные отчисления инженера |
| `PRODUCT_PERCENT_ASSEMBLY` | Процентные отчисления сборщика |
| `PRODUCT_PERCENT_INSTALLATION` | Процентные отчисления монтажника |
| `PIECE` | Сдельно |
| `PERCENT_PROJECT` | % от стоимости |
| `PERCENT_TURNOVER` | % от оборота |

#### Scenario: Прямые проценты изделия

- **WHEN** сотрудник открывает расчётник с начислениями процентов за инженерный, сборочный или монтажный этап изделия
- **THEN** колонка называется «Тип», а строки показывают соответствующие русские подписи из таблицы

#### Scenario: Другие известные начисления

- **WHEN** расчётник содержит сдельные, оборотные или исторические проектные начисления
- **THEN** отображаются соответствующие существующие русские подписи из таблицы

### Requirement: Отсутствие резервных и устаревших типов

Расчётник MUST NOT вводить резервный тип для неизвестного кода или отображать устаревший `PRODUCT_ENGINEERING` как отдельный вид оплаты. Подпись типа у этих строк SHALL оставаться пустой. Расчётник MUST сохранять сами исторические строки, их дату, основание, сумму и участие в итогах; удаление подписи не является изменением финансового факта.

#### Scenario: Неизвестный сохранённый тип

- **WHEN** в данных начисления встречается код, отсутствующий в словаре подписей
- **THEN** колонка «Тип» у строки пустая, технический код и резервная категория не показываются, остальные поля строки сохраняются

#### Scenario: Устаревшее инженерное начисление

- **WHEN** расчётник содержит историческую строку `PRODUCT_ENGINEERING`
- **THEN** строка сохраняет дату, основание и сумму, а её тип не отображается и не подменяется прямыми процентными отчислениями

### Requirement: Операции таблицы используют отображаемый тип

Сортировка и поиск по типу SHALL использовать отображаемую русскую подпись. Отображение SHALL сохранять действующую таблицу и её пагинацию на настольном и мобильном экране.

#### Scenario: Сортировка и поиск

- **WHEN** сотрудник сортирует колонку «Тип» или ищет начисления по русскому названию типа
- **THEN** таблица сортирует либо находит строки по русской подписи, с прежними суммами и основаниями
