# Spec Delta

## Purpose

Обеспечить устойчивое центрирование карточки по точному отображаемому номеру после применения поисковых результатов, ролевых ограничений и появления измеримого интерфейса.

## ADDED Requirements

### Requirement: Поиск списков только по собственному номеру

Страницы проектов и изделий MUST применять одинаковый поиск только по собственному номеру сущности в канбане и таблице. Поля SHALL показывать «Введите номер». Частичный запрос SHALL сохранять поиск подстроки собственного номера, а точное строковое совпадение SHALL сохранять существующее центрирование канбана. Поиск MUST пересекаться с остальными фильтрами и серверной видимостью.

#### Scenario: Совпадения в других полях
- **WHEN** запрос совпадает с названием сущности, именем клиента или номером/названием родительского проекта, но не с собственным номером
- **THEN** сущность не попадает в результат поиска ни в одном виде списка

#### Scenario: Текстовый непустой запрос
- **WHEN** введённый непустой запрос проекта содержит что-либо кроме ASCII-цифр либо запрос изделия не соответствует `^[0-9][0-9A-Za-z.-]*$`
- **THEN** список и его счётчик возвращают пустой результат, сохраняя остальные фильтры и ограничения доступа

#### Scenario: Строковый legacy-номер изделия
- **WHEN** введён полный или частичный номер изделия с цифровым началом, включая `3.01`, `108.13.2` или ASCII-суффикс с дефисом
- **THEN** поиск сравнивает исходную строку номера без числового преобразования

#### Scenario: Очистка поиска
- **WHEN** запрос пуст или состоит из пробелов
- **THEN** ограничение по номеру снимается, а остальные фильтры и ограничения доступа продолжают действовать

### Requirement: Дождаться измеримой карточки точного результата

Канбан MUST сохранять ожидающее центрирование точного совпадения, пока его карточка временно отсутствует в DOM либо не имеет размера. После готовности он SHALL один раз приблизить её к центру по горизонтали и вертикали в доступных пределах, сохранив размеры колонок, фильтры, вид и фокус ввода.

#### Scenario: Карточка временно скрыта
- **WHEN** подтверждённый поиск содержит точный результат, но его карточка ещё имеет нулевой размер
- **THEN** поиск остаётся ожидающим и выполняет одно центрирование после появления ненулевого размера

#### Scenario: DOM-карточка появляется позднее
- **WHEN** точный результат подтверждён до вставки его DOM-карточки
- **THEN** вставка карточки завершает ожидающее центрирование без повторного ввода номера

#### Scenario: Частичный запрос или скрытый результат
- **WHEN** подтверждённый набор не содержит точного доступного номера
- **THEN** фильтрация сохраняется без принудительной прокрутки, включая последующий SSE

#### Scenario: Новый запрос отменяет прежний
- **WHEN** ожидающая карточка появляется после смены или очистки поискового текста
- **THEN** прежнее центрирование не выполняется
