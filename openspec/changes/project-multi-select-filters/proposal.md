# Proposal

## Why

Владелец05.10.2026 требует одинаковое поведение фильтров Проектов и Изделий и реальное переиспользование компонентов. Прежний scope только Проекты отменён; исправление продолжается в согласованной задаче3.

## What Changes

- Общий компонент панели: поиск, конфигурируемые многозначные поля, «Незавершённые» и «Сброс». Обе страницы используют его; отдельные filter bars становятся тонкими конфигурациями.
- Общий codec и правила сохранения для обеих страниц; project-only helper переименован, не оставляется дублирующая реализация.
- Изделия получают multi status/project/client/engineer, пустой/полный выбор без ограничения, partial OR и AND между осями.
- Новые/сброшенные настройки обоих разделов показывают всё; старые scalar/V1 и эффективный выбор сохраняются, raw CAS/no TTL/user isolation не меняются.
- Серверные ограничения видимости и финансовые данные сохраняются.

## Capabilities

### New Capabilities

- `project-multi-select-filters`: существующий change id сохраняет историю; текущая capability охватывает общие UI правила Проектов и Изделий.

### Modified Capabilities

- `persistent-list-state`: множественные наборы и version2 для обоих разделов с независимыми ключами.

## Impact

Shared filter bar/codec, тонкие Project/Product wrappers, list-state/preferences и product parser/query/tests. Продолжение feature/3 от свежего origin/stagingab1604a. SQL-миграций, переписывания данных, новых финансовых/ролевых правил и production-выпуска нет.
