# Spec Delta

## Purpose

Контекстный журнал даёт Администратору историю открытого проекта или изделия в самой карточке, сохраняя точную принадлежность событий и не раскрывая журнал остальным ролям.

## ADDED Requirements

### Requirement: Журнал проекта последней вкладкой

Страница проекта SHALL показывать вкладку «Журнал» исключительно роли ADMIN, последней после обычных и плагинных вкладок. Открытие вкладки SHALL загружать общий интерфейс журнала с постоянным ID проекта; до открытия данные журнала MUST не запрашиваться. Параметр `tab=journal` SHALL открывать журнал только Администратору.

#### Scenario: Прямой вход и неадминистративная роль
- **WHEN** Администратор открывает проект с `tab=journal`, а Директор открывает ту же ссылку
- **THEN** Администратор видит журнал нужного проекта; Директор получает обычную доступную вкладку без компонента журнала и его данных

### Requirement: Журнал изделия нижней секцией

Страница изделия SHALL показывать последнюю секцию «Журнал» исключительно ADMIN, без добавления вкладок и без переноса существующих разделов. Запрос событий SHALL начинаться при появлении нижнего раздела в области просмотра и использовать постоянный ID изделия, а не номер из URL.

#### Scenario: Прокрутка и перенумерованное изделие
- **WHEN** Администратор открывает изделие по номеру и прокручивает до журнала
- **THEN** только после достижения секции загружается журнал постоянного ID этого изделия; остальные разделы остаются на прежних местах

### Requirement: Единый интерфейс и изоляция контекста

Контекстные журналы SHALL использовать тот же список, фильтры, сравнение и карточку события, что общий журнал. Сброс фильтров MUST сохранять контекст. Страница проекта SHALL передавать проектный контекст без добавления событий изделий; страница изделия SHALL передавать контекст конкретного изделия. Серверное чтение MUST повторно проверять ADMIN.

#### Scenario: Сброс и чужая сущность
- **WHEN** Администратор сбрасывает фильтры контекстного журнала
- **THEN** следующий запрос остаётся в исходном проекте или изделии; журнал соседней сущности не подмешивается

### Requirement: Отсутствие доступа у остальных ролей

Страницы MUST не создавать компонент журнала для DIRECTOR, MANAGER, ENGINEER, ACCOUNTANT, PROCUREMENT, WORKER, MOUNTER, WORK_COORDINATOR и их допустимых сочетаний. Клиентское скрытие уже загруженных данных SHALL не заменять серверное исключение компонента.

#### Scenario: Отсутствующая вкладка и секция
- **WHEN** любую карточку открывает разрешённый для неё пользователь без ADMIN
- **THEN** в серверном представлении нет вкладки/секции журнала, его компонента и исходных записей
