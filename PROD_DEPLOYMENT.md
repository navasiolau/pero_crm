ПРИНЯТЫЕ АРХИТЕКТУРНЫЕ РЕШЕНИЯ (не переосмысливать, исполнять). Весь стек CRM живёт в ОДНОМ контейнере crm через docker-compose: сервис web (Next.js-приложение пользователя, пока заглушка на node:20-alpine, слушает 3000), сервис db (PostgreSQL 17, подключён только к docker-сети backend с internal:true, то есть без интернета), сервис proxy (Caddy, пробрасывает порт 80 контейнера на web:3000). DATABASE_URL формат: postgresql://crm:ПАРОЛЬ@db:5432/crm, пароль генерируется в /opt/crm/.env и ОБЯЗАТЕЛЬНО сохраняется в надёжное место. Authentik ставится позже в ОТДЕЛЬНЫЙ LXC с адресом 192.168.0.21 со своим compose и публикуется наружу как auth.peromebel.by. Туннель: офис инициирует WireGuard к VPS на 51820/udp; туннельные адреса VPS 10.200.200.1/24 и офисный хост 10.200.200.2/32; у VPS в AllowedIPs пира офиса указать 10.200.200.2/32 и 192.168.0.0/24, чтобы VPS доставал контейнеры напрямую; на офисном хосте включить net.ipv4.ip_forward и сделать MASQUERADE и FORWARD для трафика wg0 -> vmbr0, тогда контейнер отвечает VPS через хост. Caddy на VPS: crm.peromebel.by reverse_proxy 192.168.0.20:80, позже auth.peromebel.by reverse_proxy 192.168.0.21:9000. Публичные сертификаты Let's Encrypt выпускает Caddy на VPS автоматически по HTTP-01, поэтому на VPS должен быть открыт порт 80. Файрвол VPS (ufw): 22/tcp временно на настройку, 80/tcp, 443/tcp, 51820/udp. Прокси для сотрудников (обход блокировок из РФ): Xray VLESS+Reality на порту 8443/tcp на VPS, клиент Hiddify, подписочная модель, максимум 5 сотрудников, отзыв доступа на уровне сотрудника (один UUID на все его устройства), полная автоматизация через webhook Authentik; это решение принято, но реализуется ПОСЛЕ ядра. Бэкапы: restic в PULL-режиме (домашний сервер админа сам подключается к офису по NetBird и забирает данные, офис наружу не стучится), облачные бэкапы ЗАПРЕЩЕНЫ (закон РБ о персональных данных и недоверие к облакам). Мониторинг: Uptime Kuma на VPS плюс GitHub Actions как внешний резервный чек, алерты в Telegram. Split-DNS для локального доступа к CRM в офисе без интернета — отложено до переезда.

Шаг 4: на офисном хосте systemctl enable --now wg-quick@wg0, проверка ping 10.200.200.1.
