# PERO CRM v2 — план реализации плагина «Импорт из Базис-Мебельщик»

> Отдельный план плагина `bazis-import` для PERO CRM v2. Редакция 3.
> Зависит от: «План реализации базовой CRM» (плагинное ядро — фаза 1.5; задачи/прайсы — фаза 3).
> Цель: при загрузке данных проекта из Базис-Мебельщик CRM автоматически заполняет техническую информацию проекта и создаёт работы и задачи — без ручного труда руководителя, менеджера и инженера. Проект сразу готов к запуску в работу после назначения исполнителей.

---

## 1. Каналы извлечения данных (финальные)

Парсинг **.b3d отменён окончательно** (закрытый бинарный формат, нет спецификации). **.xmlfr исключён за ненадобностью** (есть Базис.Скрипт). Остаются два штатных канала:

### 1.1. Базис.Скрипт-экспортёр `pero_export.js` — основной канал

Скрипт на встроенном JavaScript API Базис-Мебельщик (обход сборок/панелей/фурнитуры/материалов, чтение свойств проекта, запись файлов, HTTP-запросы). Разработка: ИИ-агент при непосредственном участии владельца (профессионального веб-разработчика). Два обязательных режима:

| Режим | Сценарий | Результат |
|---|---|---|
| **«Отправить в CRM»** | Инженер открывает проект в Базисе → запускает скрипт → скрипт формирует данные и шлёт `POST /api/v1/plugins/bazis-import/import` с токеном | Проект создаётся/обновляется и заполняется **по одной кнопке прямо из Базиса** |
| **«Скачать файл»** | Скрипт сохраняет `.pero.json` рядом с проектом | Инженер прикрепляет файл к проекту в CRM с ПК или телефона — гибкость, когда CRM/сеть недоступна с рабочего места |

### 1.2. «Спецификация в XML» — второй парсер

Штатная кнопка Базиса (формат делался под интеграции с 1С, содержит полный состав заказа). Инженер экспортирует XML и прикрепляет к проекту — плагин парсит. Не требует установки скрипта: запасной и стартовый вариант.

### 1.3. Файл .b3d

Прикрепляется к проекту как обычное вложение-оригинал (категория «чертёж/проект»). CRM его не читает — нужен для воспроизводства деталей на ЧПУ «один в один» через годы (требование из встречи). Хранится в S3/NAS (см. базовый план §12).

## 2. Что плагин извлекает и куда кладёт

| Из данных Базиса | Куда в CRM |
|---|---|
| Состав изделий (шкаф, тумба, кухонный модуль…) + габариты | Проект: изделие, тип изделия, размеры, тех. блок |
| Панели: размеры, материал, толщина, кромки (длины по видам) | Тех. информация проекта; расход материалов → связь с номенклатурой |
| Материалы (ЛДСП, МДФ, кромка, пластик) с расходом | Позиции материалов проекта (→ складские резервы в фазе 6) |
| Фурнитура и крепёж (артикулы, кол-во) | Позиции номенклатуры проекта |
| Встраиваемая техника (проёмы, тип крепления фасада, тип открывания) | Тех. требования проекта (чек-лист инженера из встречи) |
| Квадратура покраски, погонаж | База для расчёта работ по прайсам |

Все поля, заполненные плагином, остаются **редактируемыми вручную** администратором и менеджером — плагин снимает рутину, контроль у людей.

## 3. Распознавание типа изделия

Прозрачный классификатор на правилах (без ML): справочник правил «тип изделия» по имени сборки и набору признаков (примеры: «дверцы распашные + штанга → шкаф»; «мойка/варочная панель → кухонный нижний модуль»; «витрины + подсветка → шкаф-витрина»). Правила редактирует админ в настройках плагина. Если тип не распознан — применяется универсальный шаблон + инженеру показывается подсказка выбрать тип вручную на экране подтверждения.

---

## 4. Движок шаблонов (TaskTemplate / WorkTemplate)

На каждый тип изделия — шаблон производственного цикла:

- **Работы**: ссылка на расценку из `PriceItem` + правило количества («м² панелей», «м.пог кромки», «шт ящиков» — вычисляется из извлечённых данных).
- **Задачи**: список операций техпроцесса **с порядком и зависимостями** (пример цепочки: подготовить деталировку → раскрой → кромка → присадка → сборка → покраска → контроль). Задача Б **блокируется**, пока не выполнена задача А. Валидация графа на циклы (DAG) при сохранении шаблона и при импорте. У задачи шаблона — дефолтная **временная оценка**; при создании реальной задачи оценка автоматически заменяется средним фактическим временем идентичных задач из истории организации (см. базовый план §9).

Шаблоны наполняются один раз совместно с технологом/Колей — это оцифровка их прайсов и техпроцессов (legacy-таблицы 1121 «Расценки», 661 «Этапы», 671 «Техпроцессы»).

## 5. Поток целиком (UX)

1. Инженер отправляет данные из Базиса (кнопка в скрипте) **или** прикрепляет `.pero.json` / XML к проекту. Обработчик файлов ядра передаёт файл плагину.
2. Плагин парсит → открывается **экран подтверждения** (постоянный режим, всегда):
   «Распознано: Шкаф 3-дверный, 2400×1800×600. ЛДСП 16 — 18,4 м², кромка 2 мм — 96 м.пог, ящиков — 6…» + состав работ и задач с суммами по прайсам.
   На этом же экране инженер **может отредактировать** любую работу/задачу, тип изделия, количества. Максимум контроля ценой одной лишней кнопки — осознанное решение владельца.
3. Инженер жмёт **«Применить»**:
   - поля проекта заполняются (тех. данные, материалы, изделия);
   - создаются работы и задачи **в правильном порядке с зависимостями**;
   - **у задач нет исполнителя — это черновики.** Их видят администратор, менеджер **и инженер** (он инициатор — не видеть созданное было бы странным UI). Работники черновики не видят никогда;
   - **администратор и менеджер получают уведомление**: «По проекту №… импортированы данные из Базиса, создано N задач — назначьте исполнителей» (в CRM; после фазы Telegram — и в бота, с inline-назначением).
4. Менеджер/админ назначает исполнителей → черновики становятся обычными задачами, видимыми работникам.
5. Проект готов к исполнению: этап переводится в **«в работе»** — никаких дополнительных согласований не требуется.

Импорт фиксируется в `ImportBatch`: проект, исходный файл, распознанные данные (JSON), созданные сущности, кто подтвердил — с возможностью **отката** одной кнопкой.

## 6. Манифест и настройки плагина

```ts
definePlugin({
  id: "bazis-import",
  name: "Импорт из Базис-Мебельщик",
  version: "1.0.0",
  apiVersion: 1,
  permissions: ["projects:read","projects:write","tasks:create","works:create",
                "prices:read","files:read","nomenclature:read","notifications:send"],
  hooks: ["file.uploaded"],
  slots: {
    "project.tab":    () => import("./ui/ProjectTab"),   // вкладка «Данные Базиса»
    "project.action": () => import("./ui/ImportButton"), // кнопка «Импорт из Базиса»
    "settings.page":  () => import("./ui/SettingsPage"),
  },
  commands: { importFile: "./commands/importFile" },
})
```

Настройки (админка → Модули → Базис): токен API для скрипта, правила классификатора, шаблоны типов изделий, поведение по умолчанию (предлагать исполнителей по участкам — да/нет).

UI нативный: вкладка проекта, кнопка-действие и страница настроек — обычные компоненты Next.js + shadcn/ui в общей теме, подключаются через `next/dynamic`.

## 7. Тестирование и приёмка

- **Эталонные проекты**: минимум 3 реальных проекта из Базиса (шкаф, кухня, МДФ-панели) — выгрузка скриптом сравнивается с ручным подсчётом инженера (квадратуры, погонаж, фурнитура — до единицы).
- **Критерий готовности фазы 4.5**: тест «шкаф» — кнопка в Базисе → проект заполнен → инженер подтвердил на экране (с правкой) → созданы черновики задач с зависимостями → менеджер получил уведомление и назначил исполнителей → проект переведён «в работе». Суммы по прайсам сошлись с ручным расчётом.

## 8. Риски

| Риск | Снижение |
|---|---|
| Обновление Базиса ломает скрипт | Скрипт маленький, версионируется; запасной парсер XML; эталонные тесты после каждого обновления Базиса |
| Шаблоны разъедутся с реальными техпроцессами | Наполнение с технологом/Колей; подтверждение с редактированием — постоянно |
| Циклы в зависимостях задач | Валидация DAG при сохранении шаблона и при импорте |
| Ошибочный импорт | ImportBatch + откат одной кнопкой; AuditLog `actor=plugin:bazis-import` |

## 9. Этапы реализации плагина

1. Парсер «Спецификации в XML» + экран подтверждения (минимальный сквозной сценарий).
2. Классификатор типов + движок шаблонов + зависимости задач.
3. Скрипт-экспортёр: режим «Скачать файл».
4. Скрипт-экспортёр: режим «Отправить в CRM» (токен, API).
5. Уведомления «назначьте исполнителей» + откат импорта + полировка.
