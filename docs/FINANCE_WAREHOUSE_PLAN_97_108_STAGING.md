# Ручная проверка задач 97–108 на staging

Окружение: https://staging-crm.peromebel.by. Main и production ожидают отдельного разрешения владельца после этой проверки.

## Документы и общие расходы

Откройте **Финансы → Расходы организации**. Создайте общий расход без проекта из кассы с достаточным остатком: без «Отчётного документа» подтверждение должно быть невозможно. Прикрепите фото или файл, дождитесь загрузки, сохраните и откройте документ из строки расхода. Аналогично проверьте расход по выбранному проекту. Старые расходы без документа остаются доступны.

В **Приходах организации** проект необязателен; для денежного прихода файл не требуется. Общие расходы не распределяются по проектам автоматически.

## Склад и проект

Для понятного результата используйте отдельную тестовую номенклатуру без других движений и изделие в тестовом проекте.

1. В **Склад → Остатки** внесите инвентарный приход5 единиц по20BYN: остаток5, кассы не изменились.
2. В изделии, в разделе **Взято со склада**, выдайте3 единицы без добавления потребности. Остаток2; в изделии появляется выдача, в финансах проекта — строка **Материалы (склад)** на60BYN. Касса не изменяется.
3. Добавьте обычный оплаченный приход2 единиц по40BYN, выбрав кассу. Остаток4, касса уменьшается на80BYN. Прежняя выдача в проекте остаётся60BYN. Связанный денежный расход нельзя удалить отдельно.
4. Верните1 единицу по исходной выдаче: проектный расход уменьшается на20BYN. Верните оставшиеся2: по этой выдаче итоговый расход становится0. Выше оставшегося количества вернуть нельзя.
5. При наличии потребности2 единицы выдача3 разрешена, если есть складской остаток. План при этом остаётся2. Недостаток склада или денег должен приводить к отказу без частичных операций.

Склад staging обнулён по отдельному разрешению владельца: прежние движения и деньги сохранены, новый учёт начат с нуля. Штатное ночное восстановление staging из production не менялось и может заменить тестовые данные.

## Отчёт по кассам

В **Финансы → Отчёт по кассам** выберите две даты. Проверьте начальный остаток, приходы, расходы со знаком минус и конечный остаток; откройте кассу для детализации. Зарплаты и авансы входят в расходы. Переключите BYN на валюты касс: разные валюты имеют отдельные итоги. История без подтверждённой суммы/кассы обозначена явно.

## Личный план

Создайте в одном дне записи на1,5 и1 час; одну выполните, ещё одну запись на2 часа отмените. В итог дня должны входить2ч30мин, в выполненные часы — длительность выполненной записи. Пустая длительность отличается от0.

Откройте **Аналитика**, выберите диапазон с этим днём. Проверьте количество выполненных записей, часы и дневную разбивку. В списке доступны поиск, статус и переход в день календаря. Фильтр списка не меняет общий итог периода. Часы относятся к дате записи в плане и являются плановыми; отменённые часы исключены. Другой пользователь, включая администратора, видит только свой план.

## Telegram

Используйте тестового бота, связанного через профиль staging. В личном чате доступны:

- `/расход` и `/приход`: выбор проекта либо **Без проекта**; новый обычный расход требует фото/документ.
- `/инвприход`: инвентарный приход без кассы.
- `/закупка`: оплаченный приход с выбором кассы, количества и цены.
- `/выдача` и `/возврат`: изделие/материал и возврат по исходной выдаче.

Финансовые действия доступны администратору, директору, бухгалтеру и снабженцу. Менеджер без финансовой роли не получает финансовые суммы; совмещённые роли сохраняют объединение прав.

## Техническая приёмка

Результаты каждой задачи находятся в её OpenSpec evidence.md. Автоматические прогоны используют собственные тестовые записи с точной очисткой либо rollback; сообщения сотрудникам не отправляются. Telegram-диалоги проверяются с подменённым транспортом, а серверные API — на реальном staging. Дампы local/staging не создаются, Restic не затрагивается.
