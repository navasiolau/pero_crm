# Переключение staging на ограниченного пользователя PostgreSQL

Сначала примите ветки с мягкими удалениями и согласуйте применимость последующих миграций. До отдельной приёмки оставьте прежний запуск web. Production не включает описанный режим автоматически.

1. Подтвердите принятую staging-ревизию, успешный CI, опубликованный digest web и при необходимости связанный renderer. Под штатным W07 подтвердите идентичность контейнера PostgreSQL, тома, первичной БД `crm` и единственной внутренней сети backend с алиасом `db`. Определите фактического мигратора из метаданных существующего PostgreSQL. Для обычной развёртки это `crm`.
2. Под существующим владельцем выполните предусмотренный разделением прав этап создания группы и выдачи отдельного LOGIN с `INHERIT TRUE, SET FALSE, ADMIN FALSE`. Имя группы определяется как `pero_crm_runtime_` и первые 16 знаков MD5 имени текущей БД. Пароль задаётся защищённым административным процессом. Ни имя базы, ни пользователь, ни пароль текущего работающего приложения на этом шаге не меняются.
3. Установите принятый watcher штатной процедурой обновления без изменения внешнего W07 wrapper, защит и расписания. В существующий постоянный `docker-compose.override.yml` внесите только относящиеся к web настройки из [overlay](../deploy/docker-compose.runtime-privileges.yml). Сохраните другие действующие override и renderer настройки. Убедитесь, что обычная конфигурация W07 видит тот же набор файлов.
4. В защищённой настройке Compose задайте `CRM_RUNTIME_DATABASE_URL` для ограниченного LOGIN. Поместите URL мигратора только в `/opt/crm-staging/.pero-migrator.env` в формате одной строки `DATABASE_URL=…` без кавычек и дополнительных переменных. Файл должен быть обычным `root:root 0400` с одной ссылкой, в каталоге владельца root. Приложение получает его как read-only файл внутри root-only каталога. Не передавайте пароль мигратора в Compose env, shell команду или журнал.
5. Вызовите штатный staging watcher **через существующий** W07 wrapper. До замены web тот же неизменяемый образ выполнит `prisma migrate deploy` и reconciliate grants в собственном временном контейнере. Отказ preflight сохраняет работающий web. При успешном старте watcher записывает `migration=applied`, новый digest и health, а образ повторяет тот же idempotent init в контейнере web. Идентичность web после обновления, PostgreSQL ID, data mount, исходные W07 файлы и отсутствие временного migrator проверьте отдельно. С одним Compose web возможен краткий перерыв на замену контейнера.
6. Проверьте `/api/health`, фактические UID/GID 1000:1000 и нулевые `CapInh/CapPrm/CapEff/CapBnd/CapAmb` процесса PID 1, `NoNewPrivs=1` и невозможность чтения файла под UID 1000. Под runtime LOGIN `SELECT public.pero_runtime_role_violations()` должен вернуть пустой массив. Проверьте запись в `.next/cache`, доступ к S3 и согласованные операции из защищённого staging. Для КП при включённом renderer дополнительно проверьте запись и чтение общего spool. При необходимости изменяйте доступ только в подтверждённом spool, без рекурсивного `chown` бизнес-данных.
7. Отдельно через штатный guard подтвердите обычный запуск без data refresh. W07 выполняет `up --no-deps --force-recreate --wait` из постоянных Compose-файлов. Его init выполняет тот же `prisma migrate deploy` и выдачу грантов даже после восстановления без ACL. Принятый watcher использует временные переменные для digest pin, чтобы Compose labels не ссылались на удалённый файл. Обычный W07 staging tag в этот момент должен разрешаться в фактический digest. Запуск refresh и правку расписания для проверки не выполнять.

При обычном переключении назад используйте исходную конфигурацию предыдущего образа. Старый root-web нельзя запускать с credential mount. Watcher выполняет rollback пары без миграций только на образе, который подтверждённо умеет сбрасывать привилегии и работал с тем же режимом ограниченного LOGIN. Миграции назад не выполняются.

В native CI тот же образ на синтетическом PostgreSQL/MinIO подтверждает миграционный init, SQL guard, фактическое отсутствие capabilities, недоступность файла непривилегированному процессу, запись в cache и HTTP/S3 readiness. Реальный nightly W07 и возможный renderer spool остаются операторской приёмкой.

Плагины остаются доверенными пакетами монорепозитория. SDK выдаёт узкую проекцию чтения и namespaced события. Бизнес-команды подключаются через доменный вход хоста и действующие права актёра.
