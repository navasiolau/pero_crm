# PERO S3-хранилище (MinIO) — руководство по использованию

Корпоративное S3-совместимое хранилище на базе MinIO. Используется CRM для
файлов проектов и доступно для любых новых продуктов компании.

## Параметры

| Параметр | Значение |
|---|---|
| Сервер | CT 104 `s3` — 192.168.0.33 (LXC на pve, 1 ядро / 2 ГБ) |
| S3 API (из офисной сети / серверов) | `http://192.168.0.33:9000` |
| S3 API (публичный, с TLS) | `https://s3.peromebel.by` — для внешних клиентов и будущего сайта |
| Веб-консоль | `http://192.168.0.33:9001` (root-креды у владельца, LAN/NetBird) |
| Хранилище | ZFS `zdata/s3`, **квота 300 ГБ** (расширение: `zfs set quota=…` на pve), шифрование aes-256-gcm (keyfile `/root/.zdata.key` на pve — копия у владельца) |
| Резервная копия | ежедневно в restic (`s3.tar.gz`) |
| Доступ | только офисная сеть / NetBird (наружу не публикуется); удалённо — jump через `ssh root@vps-nb` |

Бакеты (приватные, anonymous access запрещён):
- `pero-crm` — файлы продакшена CRM
- `pero-crm-staging` — зеркало для стейджинга (обновляется ночным refresh)
- **Новый продукт → отдельный бакет**: `mc mb peros3/<название>`

Ключи объектов CRM: `<projectId>/<storedName>`, превью: `<projectId>/thumbs/<storedName>.jpg`.

## Консольный клиент mc (на серверах уже установлен: crm, s3, nas, staging)

```bash
mc alias set peros3 http://192.168.0.33:9000 <ACCESS_KEY> <SECRET_KEY>
mc ls peros3                                    # бакеты
mc ls --recursive peros3/pero-crm | head        # объекты
mc cp ./file.bin peros3/<бакет>/путь/           # загрузка
mc cp peros3/<бакет>/путь/file.bin ./           # скачивание
mc mirror --overwrite ./dir peros3/<бакет>/dir  # синхронизация каталога
mc rm peros3/<бакет>/путь/file.bin              # удаление
mc du peros3/<бакет>                            # размер
mc anonymous set none peros3/<бакет>            # закрыть публичный доступ
```

Веб-консоль :9001 — то же самое с браузера: бакеты, загрузка/скачивание,
пользователи и политики доступа.

## Из кода (Node.js / TypeScript)

Зависимость: `@aws-sdk/client-s3`. Пример по образцу `apps/web/src/lib/s3.ts`:

```ts
import { S3Client, PutObjectCommand, GetObjectCommand } from "@aws-sdk/client-s3";

const s3 = new S3Client({
  endpoint: process.env.S3_ENDPOINT,      // http://192.168.0.33:9000
  region: "us-east-1",
  forcePathStyle: true,                   // ОБЯЗАТЕЛЬНО для MinIO
  credentials: {
    accessKeyId: process.env.S3_ACCESS_KEY!,
    secretAccessKey: process.env.S3_SECRET_KEY!,
  },
});

// загрузка
await s3.send(new PutObjectCommand({
  Bucket: "my-product", Key: "path/to/file.bin",
  Body: buffer, ContentType: "application/octet-stream",
}));

// чтение (стрим)
const res = await s3.send(new GetObjectCommand({ Bucket: "my-product", Key: "path/to/file.bin" }));
const stream = res.Body as ReadableStream;
```

Переменные окружения — в `.env` приложения (см. `docs/DEPLOY.md`). В CI/сборке
S3 недоступен — создавайте клиент лениво, внутри функций (как в CRM).

## Производительность и доступ снаружи

- **Из офисной сети**: локальный гигабит, ~90–110 МБ/с — быстрее файлового
  сервера; задержки ~1 мс.
- **Из интернета (сайт/публичные ссылки)**: путь через VPS — упирается в
  upload-канал офиса; для статики включайте `Cache-Control` в ответах.
  При росте публичного трафика — перенос на Cloudflare R2: меняется только
  `S3_ENDPOINT` и креды (R2 S3-совместим), данные переносятся `mc mirror`.

## Правила

- Приватность: бакеты private по умолчанию; публичный доступ (`mc anonymous`)
  — только осознанно и на публичные readonly-бакеты.
- Бэкап: содержимое s3 ежедневно уходит в restic; удалённые объекты
  восстановимы в пределах 7 дней (`restic restore latest` → `s3.tar.gz`).
- Не храните в S3 секреты/ключи.
- Расширение места: `zfs set quota=500G zdata/s3` на pve (пул 8 ТБ зеркальный).
