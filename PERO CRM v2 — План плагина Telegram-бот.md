# PERO CRM v2 — план реализации плагина «Telegram-бот»

> Отдельный план плагина `telegram-bot` для PERO CRM v2. Редакция 3.
> Зависит от: «План реализации базовой CRM» (плагинное ядро — фаза 1.5; уведомления, задачи, финансы).
> Цель: каждый пользователь привязывает свой Telegram-аккаунт и управляет через бота всем, что доступно ему по роли в интерфейсе CRM. Плюс текстовый режим: команды свободным языком распознаются ИИ-моделью и выполняются с подтверждением.

---

## 1. Привязка аккаунта

- В профиле пользователя CRM — кнопка «Привязать Telegram»: генерируется одноразовая ссылка `t.me/<bot>?start=<код>` (или код для ввода боту). Пользователь жмёт → бот связывает chat_id с учёткой (`TelegramLink`), подтверждает приветствием с именем и ролью.
- Отвязка — из профиля CRM или командой `/stop` в боте. Блокировка/увольнение пользователя в CRM мгновенно отключает его в боте.
- Бот обслуживает **только привязанных** пользователей; чужие сообщения игнорируются.

## 2. Кнопочный режим (для всех ролей, строго по RBAC)

Бот — тот же интерфейс, другой канал. Возможности зеркалят права роли:

| Роль | Что доступно в боте |
|---|---|
| **Работник** | «Мои задачи» (сегодня/предстоящие/просроченные), карточка задачи, смена статуса, фото с объекта, «Моя зарплата» (расчётник) |
| **Монтажник** | То же + создание задачи в своём проекте (описание + фото) |
| **Инженер** | Свои проекты, черновики задач, запуск импорта (инструкция/статус ImportBatch) |
| **Менеджер** | Проекты и их этапы, назначение исполнителей (inline-выбор сотрудника прямо из уведомления), подтверждение выполненных задач, клиенты |
| **Администратор** | Всё выше + финансы: внести платёж/расход, остатки касс, маржа проекта |

**Уведомления (исходящие):** «вам назначена задача»; админу и менеджеру — любое изменение состояния проекта (смена этапа, импорт из Базиса с кнопкой «назначить исполнителей», завершение); дедлайны и просрочки. Каждое уведомление — с кнопками действий, чтобы не открывать CRM.

## 3. Текстовый режим с ИИ (только администратор и менеджер)

Свободный текст разбирается ИИ-моделью через **OpenAI-совместимый API**. Пример из ТЗ: руководитель пишет «проект1 расход 4000 рублей» → модель распознаёт интент: проект «Проект 1» → создать расход 4 000 BYN → бот отвечает **карточкой-подтверждением** («Проект 1 · Расход · 4 000 BYN · статья: …», кнопки «Подтвердить / Изменить / Отмена») → запись создаётся **только после подтверждения**. Без подтверждения в данные ничего не пишется никогда.

- **Модель оперирует сущностями проекта** через function calling поверх Plugin SDK: проекты (найти, сменить этап), задачи (создать, назначить, закрыть), платежи/расходы, клиенты, номенклатура. Каждое мутирующее действие — с подтверждением от запрашивающего; чтение (спросить остаток кассы, статус проекта, маржу) — без подтверждения.
- **Режим доступен только администраторам и менеджерам.** Работнику текстовый режим не нужен — у него кнопки.
- **Настраиваемые подсказки.** В настройках плагина редактируются без правок кода: системный промпт; словарь синонимов и правил («расход = списание на проект», «рублей = BYN», как именуются проекты); список разрешённых интентов и соответствие «интент → действие CRM». Пользователь сам определяет, как бот его понимает.
- **Лог распознаваний** (текст → интент → параметры → результат) в настройках плагина — для отладки промптов.

## 4. Два способа подключения ИИ-модели

Вариант ещё не выбран — поддерживаются **оба**, переключение в настройках плагина без смены кода (оба говорят по OpenAI-совместимому протоколу `/v1/chat/completions`):

| Провайдер | Настройка | Когда использовать |
|---|---|---|
| **Облачный OpenAI-совместимый endpoint** | base URL + API key + модель (настройки плагина) | Быстрый старт, качество распознавания из коробки |
| **Локальная модель в llama.cpp** | base URL локального `llama-server` (OpenAI-совместимый режим), модель из локального файла | Данные не уходят наружу, нет расходов на токены; работает на нашем же железе |

Настройки: активный провайдер (переключатель), параметры каждого, таймаут, температура, max tokens. Тестовая кнопка «Проверить соединение» в админке. Архитектура от провайдера не зависит — разница только в конфигурации.

## 5. Техническая реализация

- Бот — webhook на `/api/v1/plugins/telegram-bot/webhook` (long polling как fallback, если сервер без белого IP/домена на старте).
- Очередь исходящих сообщений с повторами (через outbox-механизм ядра).
- Все действия бота — через Plugin SDK с RBAC привязанного пользователя; мутации — в журнал изменений с автором = пользователь (это действия человека через другой канал) и пометкой источника `telegram`.
- Медиа: фото из Telegram скачиваются и сохраняются как файлы проекта/задачи (StorageDriver из базового плана — local или S3/NAS).

## 6. Манифест

```ts
definePlugin({
  id: "telegram-bot",
  name: "Telegram-бот",
  version: "1.0.0",
  apiVersion: 1,
  permissions: ["*"], // действует в рамках RBAC привязанного пользователя
  hooks: ["project.stage_changed","task.assigned","task.completed",
          "import.completed","notification.created"],
  slots: { "settings.page": () => import("./ui/SettingsPage") },
  commands: { webhook: "./commands/webhook", notify: "./commands/notify" },
})
```

Настройки (админка → Модули → Telegram): токен бота, webhook/long polling, провайдер ИИ и его параметры, системный промпт, словарь синонимов, разрешённые интенты, лог распознаваний.

## 7. Приёмка (критерии готовности фазы 5.5)

1. Пользователь привязал Telegram из профиля за 30 секунд.
2. Работник закрыл назначенную задачу из бота, фото прикрепилось к задаче.
3. Админ написал «проект1 расход 4000 рублей» → получил карточку-подтверждение → расход создан в проекте «Проект 1» (4 000 BYN).
4. Уведомление о смене этапа проекта дошло админу и менеджеру; исполнитель назначен inline-кнопкой.
5. Оба ИИ-провайдера (облако и llama.cpp) проходят один и тот же набор тестовых команд; переключение — из настроек, без пересборки.

## 8. Риски

| Риск | Снижение |
|---|---|
| ИИ неверно распознал команду | Запись только после подтверждения; узкий список интентов; лог распознаваний; настраиваемые промпты |
| Локальная модель слабо понимает русские команды | Два провайдера на выбор; словарь синонимов; few-shot примеры в системном промпте; тестовый набор команд |
| Токен бота/API утёк | Токены в `.env`/настройках, отзыв и перевыпуск; отвязка аккаунта из профиля |
| Спам/чужие сообщения | Обслуживаются только привязанные chat_id |

## 9. Этапы реализации плагина

1. Привязка аккаунтов + эхо-каркас бота (webhook, RBAC-гварды).
2. Кнопочный режим для работника/монтажника (задачи, статусы, фото).
3. Уведомления по событиям ядра (включая «назначьте исполнителей»).
4. Кнопочный режим менеджера/админа (назначения, подтверждения, финансы).
5. Текстовый ИИ-режим: function calling, карточки подтверждения, настройки промптов, оба провайдера.
