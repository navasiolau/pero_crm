# Отчёт миграции legacy → PERO CRM v2 (Ф7, редакция 2)

Дата: 2026-08-30. Миграция: `prisma/migrations/20260830120000_legacy_import`.
Источник: `pero_legacy_clean` (docker `pero_legacy_pg`, порт 5432) — **только чтение** (dblink SELECT).
Файлы: скопированы скриптом `scripts/import-legacy-files.ts`, сироты вычищены `scripts/cleanup-uploads.ts`.

## Правила владельца (воплощены в миграции)

1. **Дедуп клиентов по нормализованному имени** («ОЗОН» ×99, «ЯндексМаркет» ×20 и пр. → один клиент; нормализация: нижний регистр, без пунктуации, пробелы схлопнуты). Проекты/заявки/коммуникации переподчиняются каноническому клиенту (приоритет канона: запись с телефоном, затем меньший id). Неконвертированные заявки и заказы без карты тоже резолвятся по имени в t320, авто-клиент создаётся только если имени в t320 нет.
2. **Заглушки не импортируются**: заказы с номером без цифр («нет», «Гена Дрогичин», «3,412 = …»). Архив/удалённые в clean-базе уже отсечены при её сборке (все записи «активные»).
3. **Правило давности**: проект, созданный до 2025-08-30 (>1 года) или без изменений с 2026-02-28 (>полугода, поле «Дата-текущая» f26121), импортируется ЗАВЕРШЁННЫМ — все его изделия DONE, все задачи DONE (doneAt = дата выполнения legacy или завершение проекта), неконвертированные старые заявки → REFUSED («Не конвертирована в заказ (импорт из v1)»).
4. Ориентация на состояние v1: стадии/статусы — из дат статусов 1–9; минимальная стадия заказа — CONTRACT (заказ существует).

## Примечания

- Идентификаторы детерминированные: `legacy_<сущность>_<legacy_id>`, `legacy_project_<номер группы>`, `legacy_lead_<t241.id>`, `legacy_client_auto_<md5(норм.имя)>`.
- Каждый Project/Product/Client/User/Work/File/PriceItem/Material несёт `legacyId` + `legacyTable`.
- Пароли: argon2id (OWASP: 19 MiB, t=2, p=1), bcryptjs удалён из проекта.
- Legacy база не изменялась: только SELECT через dblink.
- Повторное применение: TRUNCATE доменных таблиц + импорт заново (идемпотентно); checksum миграции в `_prisma_migrations` синхронизирован с файлом.
