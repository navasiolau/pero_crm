# Поля, перенос и деньги

Одна строка `items` представляет целое изделие или согласованную сборку. `qty` — количество изделий, `price` — цена единицы. Разделы `specifications` принадлежат этой позиции.

| Поле | Использование |
|---|---|
| `id` | Неизменяемый ID позиции; сохранять при перестановке и правке |
| `name` | Название цельного изделия, при необходимости помещение |
| `description` | Сохранять имеющееся; не добавлять описание без задачи |
| `size` | Подтверждённые общие L × H × D в мм; не размер комнаты/матраса/одного модуля |
| `qty`, `price` | Количество и цена единицы в исходной валюте КП |
| `note` | Согласованные уточнения состава/стоимости |
| `image`, `image2` | Приватные токены `kp-media:<id>` этого КП |
| `dbl` | Полный лист с двумя настоящими видами/деталями либо поллиста |
| `specifications` | Массив разделов с `id`, `type`, `group`, `label`, `value` |
| `products` | Исходные блоки прежнего формата для совместимости и истории |

## Разделы спецификации

Заполнять по порядку каталога. У каждого стандартного раздела `type`, `group` и `label` берутся из таблицы. Каждый стандартный тип встречается в позиции один раз. «Каркас» в старом заголовке может соответствовать разделу «Корпус».

| `type` | `group` | `label` |
|---|---|---|
| `body` | `construction` | Корпус |
| `facade` | `construction` | Фасад |
| `worktop` | `construction` | Столешница |
| `upholstery` | `construction` | Обивка |
| `insertsAndHandles` | `construction` | Вставки и ручки |
| `hardware` | `hardware` | Фурнитура |
| `lighting` | `lighting` | Подсветка |
| `interiorFilling` | `filling` | Внутреннее наполнение |
| `softFilling` | `filling` | Мягкое наполнение |

Если подходящего раздела нет, использовать `type: "custom"`, короткий предметный `label` и подходящую группу. Дополнения идут после стандартных разделов своей группы. Каждой новой строке присваивать UUID. При правке сохранять ID из GET, включая старые значения вроде `body`. После удаления и повторного добавления использовать новый UUID.

В `value` кратко записывать подтверждённые материал, отделку, декор, модель или состав. Считать ящики, штанги и полки на изделие и на всё количество, если оно больше единицы. Лоток внутри ящика входит в его состав. Фальш-фасад или шов сами по себе не подтверждают ящик. Характеристику указывать один раз. Подсветка имеет отдельный раздел, температуру указывать только по подтверждённому заданию. Неизвестные характеристики пропускать. По визуальному сходству нельзя устанавливать марку материала или скрытую конструкцию. Неоднозначные «наружный» и «внутренний» материалы старого блока нельзя автоматически назначать корпусу и фасаду.

Пример для двух тумб с подтверждёнными материалами и одним ящиком в каждой. Поля `qty`, `description`, `size` и `note` остаются на уровне позиции. Использовать значения проекта, а пример применять как образец структуры.

```json
[
  {"id":"28d99f86-2470-4d80-b88e-74c56e5123ef","type":"body","group":"construction","label":"Корпус","value":"ЛДСП EGGER W980"},
  {"id":"3e131bd2-8878-4c43-9efa-61e2bbaf095b","type":"facade","group":"construction","label":"Фасад","value":"МДФ, натуральный шпон дуба"},
  {"id":"03a9aa83-32c0-4886-9dbe-e654bc01560a","type":"lighting","group":"lighting","label":"Подсветка","value":"LED 3000 К"},
  {"id":"2e57d81d-31a7-4d79-9788-5530253115ae","type":"interiorFilling","group":"filling","label":"Внутреннее наполнение","value":"1 ящик на изделие, 2 на комплект"}
]
```

Существующие `products` сохранять без правок. При сохранении старой позиции без `specifications` CRM переводит исходные блоки в новую структуру. При правке старых характеристик сверить все исходные разделы перед отправкой полного массива. Явное `[]` очищает характеристики, поэтому его передают при согласованном удалении всех разделов или при создании новой позиции без подтверждённых характеристик.

### Формат для старой CRM

Если проверка текущего сервера вернула `specifications: false`, передавать характеристики в `items[].products`. Брать порядок и названия новых блоков из каталога, записывать имя раздела в `title`. При правке начинать с существующих блоков и сохранять все подтверждённые сведения вне запрошенных изменений.

| Раздел | Поле блока |
|---|---|
| Конструкция и дополнительные материалы | `outer` для подтверждённой наружной отделки, `inner` для подтверждённого внутреннего материала или основы |
| Фурнитура | `hinges` |
| Подсветка | `lighting` |
| Внутреннее наполнение | `drawers` для подтверждённых сведений о ящиках |
| Мягкое наполнение, другие сведения и материал с неуточнённой ролью | Отдельный блок с `title` вида «Название раздела — краткое значение» |

Указать подтверждённые сведения один раз. Если проект называет материал без указания внутренней или наружной роли, сохранить формулировку проекта в заголовке блока. При последующем переходе такой блок останется дополнительным разделом до уточнения. На старом сервере в новой позиции или существующей legacy-позиции использовать только `products`. Если свежий GET уже содержит `specifications`, сохранение этой позиции требует обновления CRM. После записи сверить GET и PDF, если он входит в поручение. В результате можно кратко указать, что использован формат текущего сервера.

```json
[
  {"title":"Корпус","inner":"ЛДСП EGGER W980"},
  {"title":"Подсветка","lighting":"LED 3000 К"},
  {"title":"Внутреннее наполнение","drawers":"1 ящик на изделие, 2 на комплект"}
]
```

«Оформи как КП X» переносит подачу, не спецификацию. «Материалы как X» разрешает только названные категории. Точный перенос всей позиции требует свежего GET исходника и всех её полей/изображений; удалить исходный item.id, получить новый серверный ID, изображения загрузить новому владельцу. Источник не менять. Клиента, доставку и общие условия переносить только в согласованном объёме.

Изменять реальные `price`, `discount`, `delivery`, а не примечание с обещанной новой суммой. Неизвестная цена — 0 с отметкой незавершённого расчёта, а не бесплатная мебель. Цена комплекта и цена единицы различаются. Существующие валюта, скидка, оплата и сроки сохраняются, пока их не просили менять.

Печатные суммы рассчитывает исходный шаблон, перенесённый в `@pero/kp-template`; не заменять его округление своей формулой. CRM пересчитывает зафиксированный курс в BYN через Decimal: initialPrice единицы до скидки, expectedPrice после скидки. Услуги участвуют в пропорциональной скидке; отдельная поправка проекта сохраняет общий итог до копейки. Исторические начисления не пересчитываются.

Для `delivery.mode=total` указать общую сумму, не выдумывать разделение. Для `mode=items` каждая строка хранит `crmKind=DELIVERY|UNLOADING|INSTALLATION`; произвольная подпись не определяет категорию. Сохранять исходные печатные подписи, price и согласованный итог строк. При выключенных услугах суммы не участвуют в итоге.
