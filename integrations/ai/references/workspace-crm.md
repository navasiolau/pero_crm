# Переключение рабочего каталога КП на CRM

Этот раздел предназначен для связанных инструкций E:\KP после сквозной приёмки. Существующие AGENTS.md/INSTRUKCIYA.md сохраняют правила работы с проектами; их старый адрес/авторизацию/загрузки требуется заменить следующими положениями, сохраняя остальные owner-правила.

- Система: раздел «КП и договоры» PERO CRM. Origin берётся из PERO_CRM_API_URL; API `/api/v1/kp`.
- Секрет: отдельный отзываемый ключ активного пользователя в PERO_CRM_API_KEY. Старый API_KEYS, публичные uploadUrl/publicUrl и облачный генератор больше не используются.
- Номер нового КП назначает CRM одновременно с проектом «Лид». Не искать максимальный номер и не занимать его локальной папкой.
- State сервера первичен. Сначала GET с revision и локальный снимок, затем полное сохранение со стабильными items[].id, expectedRevision и UUID operationId. Повтор после тайм-аута — чтение прежней операции.
- Полное сохранение перезаписывает связанные коммерческие поля CRM и скрывает отсутствующие позиции. CRM не обновляет КП. Редактирование/восстановление только в «Лиде».
- Клиент выбирается из CRM; «Временный» не заполняется данными заказчика. Курс зафиксирован; обычное сохранение его не меняет.
- Картинки приватные, ссылки state `kp-media:<id>`. Передача в другое КП требует собственной загрузки. Файлы PDF/DOCX читаются с Bearer через API.
- Выпуск PDF/договора создаёт версию только после SUCCEEDED. Нельзя экспортировать произвольный state в обход сохранённой ревизии.
- Договор открывает реквизиты выбранного клиента; сохранить sourceRefs/clientBaseline. Его успешный выпуск автоматически переводит все включённые «Лид»/«Просчёт» в «Договор», черновики — в «Подготовку».
- Версии можно читать/скачивать; восстановление явно меняет текущий КП и синхронизирует CRM. После годовой очистки изображения могут быть недоступны, PDF и история договоров сохраняются.

Проверенный помощник и MCP устанавливаются из той же принятой ревизии CRM. API-ключи в команды, инструкции, квитанции, коммиты и исходники не помещать.
